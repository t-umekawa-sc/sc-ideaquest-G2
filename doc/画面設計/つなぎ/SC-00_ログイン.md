# つなぎ SC-00 ログイン（画面↔API オーケストレーション）

> **本書は orchestration/state のみ**を定める。リクエスト/レスポンスの**スキーマ・エラーcode の網羅は OpenAPI／[`../../API設計/A_認証・セッション.md`](../../API設計/A_認証・セッション.md) が SoT**（ここには再掲しない＝DRY・規約 §2.3）。
> 実装＝`impl/frontend/src/features/auth/`（`app/` はルーティングのみ・§4.1）。対象＝**状態A（PWログイン）**のみ（MFA/初回・再設定PW は後続）。

## 1. 呼び出しシーケンス

| # | 契機 | 呼び出し | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- |
| 1 | ログイン押下 | `POST /api/v1/auth/login`（同一オリジン→backend へ rewrite プロキシ） | `authenticated` → `/`（SC-01）へ遷移＋`router.refresh()` | code に応じて §3 の文言表示・パスワード欄クリア |
| 2 | 認証後ページ描画 | Server Component が `GET /api/v1/auth/session`（Cookie 転送） | セッション表示（display_name 等） | `null` → `/login` へ redirect |
| 3 | ログアウト押下 | `POST /api/v1/auth/logout`（`X-CSRF-Token`＝`iq_csrf`） | `/login` へ遷移 | いずれにせよ `/login` へ |

## 2. 状態（loading / error / empty）

- **loading**＝送信中はボタンを `disabled`＋「送信中…」。二重送信を防ぐ。
- **error**＝`role="alert"` で1行表示（§3）。フィールド単位のエラー（422 `errors[]`）は将来フィールド直下に出す（現状は全体表示）。
- **empty/未認証**＝保護ページはセッション無しで即 `/login` redirect（画面ちらつきを避けるためサーバー側で判定）。

## 3. エラー code → UI 文言（列挙耐性を守る）

| code / 状況 | 文言（SC-00 §7） |
| --- | --- |
| `unauthenticated`（会社コード/ID/PW 不一致・PW未設定を一律） | ログインIDまたはパスワードが正しくありません。 |
| `company_suspended` | このアカウントは現在ご利用いただけません。管理者にお問い合わせください。 |
| `rate_limited` | 試行回数が多すぎます。しばらくして再度お試しください。 |
| `validation_error` | 入力内容をご確認ください。 |
| その他/通信失敗 | エラーが発生しました。時間をおいて再度お試しください。 |

- **どちらが誤りかは示さない**（列挙攻撃対策・A.1）。`password_setup_required` 等は返らない前提。

## 4. 認証・セキュリティ配線（§4.1・A.0）

- **同一オリジン方針**＝ブラウザは常に `:3000` と通信し、`/api/v1/*` は `next.config` の rewrite で backend へプロキシ。**CORS 不要**。
- **Cookie**＝`iq_session`（httpOnly・ブラウザが自動送出）／`iq_csrf`（非httpOnly・JS が読んで `X-CSRF-Token` に載せる＝ダブルサブミット）。fetch は `credentials: "include"`。
- **CSRF**＝状態変更系（logout）のみ付与。login は CSRF 免除（Origin/Sec-Fetch のみ・A.1）。
- **401 リダイレクト**＝保護ページの Server Component が `getServerSession()` で判定し `/login` へ。
