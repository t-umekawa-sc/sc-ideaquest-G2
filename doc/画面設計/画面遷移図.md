### 2.1 認証・パスワード設定 / 再設定フロー（詳細）

> ログインは会社コード＋ログインID＋パスワード（要MFA時はメールOTP）。**初回パスワードも再設定も、メールで届く設定リンク（`otp_challenges` purpose=`password_setup`・72h・単回）から行う**（仮パスワードは使わない）。API の正＝`doc/API設計/A_認証・セッション.md`（§A.1 ログイン/MFA・§A.7 パスワード設定/再設定＝自己サービス要求 `request`・トークン確認 `verify`・設定 `complete`）。

```mermaid
flowchart TD
    LOGIN["SC-00 ログイン（会社コード＋ID＋PW）"]
    OTP["SC-00 認証コード入力（MFA・状態C）"]
    DASH["SC-01 ダッシュボード"]
    PWREQ["SC-00 パスワード再設定リクエスト（会社コード＋ログインID）"]
    ADMIN["管理者による発行 / パスワード再設定（SC-93 会社アカウント管理者 / SC-92 システム管理者）"]
    MAIL["メール: パスワード設定 / 再設定リンク（72h・単回）"]
    PWSET["SC-00 初回 / 再設定パスワード設定（状態B）"]

    LOGIN -->|"第1要素OK・要MFA"| OTP
    OTP -->|"OTP一致"| DASH
    LOGIN -->|"第1要素OK・信頼端末 or MFA=OFF"| DASH
    LOGIN -. "パスワードをお忘れですか？" .-> PWREQ
    PWREQ -. "登録メールへ送信（実在有無に依らず常に同一応答＝列挙耐性）" .-> MAIL
    ADMIN --> MAIL
    MAIL --> PWSET
    PWSET -->|"設定完了（セッションは張らない）"| LOGIN
```

> - **初回パスワード未設定のアカウントで login しても状態B へは遷移しない**（他の失敗と区別せず一律 `401`＝列挙耐性・ドメインA F3）。初回設定リンクは**管理者のアカウント発行時**に送信される。
> - **自己サービスのパスワード再設定リクエスト**は、会社コード＋ログインID を受け、該当があれば登録メールへ再設定リンクを送るが、**応答は常に同一**（アカウントの有無・PW未設定状態を漏らさない）＋レート制限。バックエンドは `POST /api/v1/auth/password-setup/request`（`A_認証・セッション.md` §A.7）。
> - パスワード設定 / 再設定の完了で**当該アカウントの全セッション破棄＋信頼端末失効**（`A_認証・セッション.md` §A.9-③）。完了後はログイン画面（SC-00）から通常ログイン。

## 3. ロール別アクセス（サマリ）

- **一般（パーティーメンバー）**: SC-00〜SC-41（管理画面を除く）。個別操作は権限（投票/アイデア作成/コメント/評価）に従う。
- **クエストグループ管理者**（＝`quest_group_members.role=admin` の有効所属を 1 つ以上持つ・per-group）: 上記＋ SC-90（**参加選択専任**＝自グループへの参加追加/除外のみ）。
- **会社アカウント管理者**（`system_role=company_account_admin`）: 上記＋ SC-93（自社アカウントの発行/編集/無効化/PW再設定＋QG管理者〔per-group admin〕の任命）。※職務分離（SoD §8-⑯）でアカウントのライフサイクル＋グループ管理者の任命を担う（system_role 付与は system_admin のみ）。
- **システム管理者（運営）**（`system_role=system_admin`）: SC-91（会社一覧）＋ SC-92（会社詳細/設定・全アカウント/所属・システムロール(3値)/admin 付与）。SC-90/SC-93 の全操作を全会社範囲で上位互換。※運用画面中心。

## 4. 補足・確認したい点

- **アカウント発行（決定）**: アカウントは**管理者発行のみ**（**会社アカウント管理者〔SC-93〕／システム管理者〔SC-92〕が発行**。QG管理者は職務分離で発行不可＝参加追加のみ SC-90）。自己新規登録画面は作らない。一般ユーザーは**管理者発行時にメールで届く設定リンク（72h・単回）から初回パスワードを設定**する（仮パスワードは使わない）。
- **パスワード再設定（決定・2026-07-29）**: **自己サービス**とする。SC-00 に「パスワードをお忘れですか？」導線を置き、会社コード＋ログインID から**登録メールへ再設定リンク**を送る（**列挙耐性で常に同一応答**＋レート制限）。管理者からの再設定（SC-93 会社アカウント管理者／SC-92 システム管理者）も同じメールリンク基盤を使う。フロー詳細＝§2.1、API＝`POST /api/v1/auth/password-setup/request`（`A_認証・セッション.md` §A.7）。
- **アイデア一覧（決定）**: 独立画面にせず **SC-12 クエスト詳細内のセクション/タブに内包**（旧 SC-20 は廃止）。
- **ダッシュボードからの直行（決定）**: ダッシュボードに「参加中クエスト」カードを置き、**一覧を経由せずクエスト詳細へ直行**するショートカットを用意。
- **実績・ランキング（決定）**: **両方とも初期スコープに含める**（SC-40 実績/バッジ・SC-41 ランキング）。
- **登録・編集のモーダル化（決定）**: SC-11・SC-21 は**独立画面ではなくモーダルダイアログ**。**Next.js Parallel Routes ＋ Intercept Routes** で実装し、URLを持つモーダル（共有・戻る/進む・リロードでフルページ）を標準とする。一覧/ダッシュボードから開く**詳細（SC-22）も同方式でモーダル差し込み**。
- **アイデアフォロー（決定）**: 参加中クエストのアイデアを**フォロー＝ウォッチ**。**ダッシュボードにフォローパネル**を置き、パネルクリックで**拡大アニメーション（framer-motion `layoutId`）→ SC-22 をモーダル表示**。
- **下書き（決定）**: クエスト・アイデアは**下書き保存**可（作成者本人のみ表示・公開/投稿までパーティー非公開・XP/コインは公開/投稿時に付与）。**ダッシュボードの最上段（参加中クエストの上）に下書きパネル**を置き、クリックで**作成/編集モーダル（SC-11/SC-21）**を開いて続きを編集。
- **未投票アイデアの投票ショートカット（決定）**: 参加クエストで**自分がまだ投票していないアイデア**をダッシュボード（下書きの下）にパネル表示。**カード内の賛成/反対でクイック投票**、パネルクリックで**拡大→投票モーダル**（アイデア要約＋賛成/反対）。投票=SC-22内のアクションと同一（1人1票・締切まで変更可・XP付与）。
- **チャットリアクション & 魔法（決定）**: チャット（SC-24）に**2層リアクション**（通常＝絵文字/無料・魔法＝SP解放/エフェクト/クールダウン）。**レベルアップで SP を獲得**し、**新画面 SC-32「魔法/スキル」で SP を消費して魔法を解放**。解放した魔法は SC-24 の**魔法リアクション**として発動し、対象メッセージに**永続エフェクト**（例: 炎＝枠が燃える）を残す。装飾/社交演出のみ（XP/評価に非影響）。

## 5. 次の進め方（提案）

1. **本遷移図で全体フローを合意**（画面の粒度・遷移・TBD の解消）。
2. 画面ごとに **ワイヤーフレーム（レイアウト）** を 1 枚ずつ作成し確認。
3. レイアウト確定後に **画面モック（HTML/CSS・決定）** を作成。ブラウザで見た目を確認でき、Next.js 実装への流用も可能。
4. 画面ごとの **画面設計（機能詳細: 表示項目・アクション・権限・入出力・API）** を詰める。

> - 画面設計（機能詳細）は画面単位で `doc/画面設計/screens/SC-xx_<名前>.md` に分割。
> - HTML/CSS モックは `doc/画面設計/mocks/SC-xx_<名前>.html` に配置（静的ファイル。ブラウザで直接開いて確認）。
> - モックは確認用の静的プロトタイプであり、実装（Next.js）とは別管理。共通の見た目は簡易な共有 CSS を用意して各モックから参照する想定。
