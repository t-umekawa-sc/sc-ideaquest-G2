    14. 完了通知スナックバー（提案・ゲーム要素入り）

    更新完了などの処理の終了を画面下中央にトーストで知らせる。自動で消える（下端のタイマーバー・ホバーで一時停止）／ ✕・アクション（元に戻す 等）付き・複数は縦に積む。業務は意味色（成功/エラー/情報）、 ゲーム文脈は「報酬スナックバー」（CRTガラス＋XP/コインチップ＋きらめき）で獲得を演出する。

    呼び出しは1関数（デモの iqSnack({type,title,msg,rewards,action,duration})）を想定。 type＝success/error/info（意味色）と reward/levelup（報酬・CRTガラス）。aria-live で読み上げ、エラーは role="alert"。prefers-reduced-motion で動きを抑制。 duration:0 で自動消滅させない（✕クローズのみ＝§4.7 の持続エラー等）。

    重なり増加時の UI（決定 2026-08-22）＝同時表示は最新 3 件まで。4 件目以降は上部に「▽ その他 N 件」を表示（標準スナックバーと同じ緑のゲージ付き＝折りたたみ中で「最後に消える」隠れ通知の残り時間を表す）。クリックで全件を縦スクロール表示（スナックバー領域だけに縦スクロール・各バーは潰れず自然高さ・残り時間インジケータは動き続ける）・「▲ 折りたたむ」で戻す。「重なり（5件・上限確認）」で挙動を確認できる。

    14b. セッション終了時の通知（§14・決定 2026-08-23）

    セッション切れでログイン画面へ戻された時、なぜ戻されたかを info トーストで伝える（無言リダイレクトの UX 改善・自動消滅＝一過性の案内で sticky は使わない）。 受け渡しは URL query の enum reason（session_expired／logged_out）で、ログイン画面が固定文言にマップして表示（表示後 query を除去＝ワンショット）。未ログインの直アクセス（Cookie が最初から無い）は通知なし。

    実体（impl）＝401 を lib/api/client の apiFetch が /login?reason=session_expired へ一元リダイレクト（/auth/* 除外・/login 上は無処理）／(auth) レイアウトの SessionNotice が reason を固定文言にマップ→トースト→query 除去。セキュリティ＝reason は非機密 enum のみ・リダイレクト先は固定 /login（可変 next 無し）。

    15. 確認ダイアログ（提案・ゲーム要素入り）

    ブラウザ標準の window.confirm を、デザインに合ったダイアログに置き換える提案。 共通モーダルの見た目（.modal__panel.sectioned）を流用し、Promise を返す1関数で使う。 業務は危険操作（削除）＝赤の確定ボタン、ゲーム文脈は購入確認＝ピクセル見出し＋コスト/残高プレビュー＋ ▶ ボタン。 Enter で確定 / Esc・バックドロップ・✕ でキャンセル。prefers-reduced-motion で動きを抑制。

    呼び出しは await iqConfirm({title, msg, variant:'danger'|'game', confirmLabel, cancelLabel, cost:{icon,name,price,balance}}) を想定（true/false を返す）。 確定後は「14.」の iqSnack と連動（削除＝成功／購入＝報酬）。

    16. ツールチップ（ホバーで補足・pixel 風）

    17. 魔法発動エフェクト＝受信/表示側の4パターン（発動者→作成者）

    実チャットで「発射後にスクロールすると弾が発射前の位置に着弾する」問題への対策検証。 A＝弾をスクロール内容の座標に置く（アンカー）と、スクロールしても対象に追従してズレない。 B＝スクロールが止まってから発火すると、速い流し見中の無駄な連続発火を間引ける。

    A. 着弾ずれ対策：スクロール座標系アンカー

    発動ボタンを押した直後に枠内をスクロールしてみてください。アンカー（橙）は対象メッセージに追従してズレず、 固定＝従来（青）はスクロールでズレます（弾はデモ用に約2秒）。
