情報インプット 動的タブ — UI 3案 比較（検討）

会社が動的に足す「内容タブ」（全般／カメリオ連携／情報共有…）を、既存 SC-50 の「🧭 情報インプット／🔍 全文検索」タブと二重にならない形でどう見せるか。 「タブ内タブ」回避の3案を同じ代表データで並べて比較する。正＝doc/設計ドラフト/情報インプット動的タブ_設計.md §4。 ※静的モック（クリックでの切替・DataTable は未結線）。採用案を決めたら SC-50 本モックへ移植する。

案A

内容タブ＋横断検索バー

— タブ行は1段だけ／全文検索はバーに格上げ

情報インプット

タイトル / 要約状態優先度影響分類ソース
改正個人情報保護法ガイドライン公表判定済普通機会公的機関
業界展示会レポート（要約）未判定低機会展示会
主要取引先の組織改編メモ判定済高—取引先

「🔗 カメリオ連携」タブを開くと、API 取得記事（未判定・自動リンクOFF）が並ぶ。

考え方＝タブ列を1段（内容タブ）だけに。既存の「🔍 全文検索」はタブをやめて右上の横断検索バーへ格上げ（全タブ横断で探せる）。

✅ タブが1段でシンプル・「タブ内タブ」が消える
✅ 検索が常時アクセス可（タブ切替不要）
✅ ユーザーの「タブで束ねる」イメージに最も素直
⚠️ 既存の全文検索タブ挙動をバーへ変更する必要
案B

左フォルダ型サイドナビ

— 束=左ナビ／機能タブ=右に維持

情報インプット

タイトル / 要約状態優先度影響分類
改正個人情報保護法ガイドライン公表判定済普通機会
業界展示会レポート（要約）未判定低機会
主要取引先の組織改編メモ判定済高—

考え方＝束を左サイドのフォルダ（メール／チャンネルの比喩＝「まとまり」に最適）に。右は既存の「一覧／全文検索」をそのまま維持＝軸が縦横で分かれ混同しない。

✅ 「まとまり」メタファに最適・束が多くても縦スクロールで収まる
✅ 既存の一覧/全文検索を変えずに済む
⚠️ 横幅を使う（モバイルは折り畳み必要）
⚠️ 左ナビは新パターン（他画面に無い＝新規UI）
案C

束セレクタをツールバーに

— タブUIを足さず最小追加

情報インプット

タイトル / 要約状態優先度影響分類
改正個人情報保護法ガイドライン公表判定済普通機会
業界展示会レポート（要約）未判定低機会
主要取引先の組織改編メモ判定済高—

考え方＝タブUIを足さず、束をツールバーのセレクタ（ドロップダウン）に。既存の一覧/全文検索タブは不変＝追加UI最小。

✅ 追加UI最小・混同ゼロ・実装が軽い
✅ 既存SC-50をほぼ変えない
⚠️ 「タブで束ねる」体験は弱い（束が埋もれる）
⚠️ 束の一覧性が低い（開かないと中身が見えない）

推奨＝案A（ユーザーの「タブで束ねる」イメージに最も近く、タブ内タブも解消）。束が将来とても多くなるなら案Bが効く。最小変更を最優先なら案C。
