## 1. 概要・目的

- **システム管理者（運営）**が、**選択した 1 社（テナント）**の**設定**（投票匿名化／管理者開示／MFA）と**アカウント・クエストグループ所属のフル操作**を行う画面。
- SC-91（会社一覧）で会社を選ぶと本画面へ。**画面上部に「メンテナンス中の会社」を示す文脈バナーを常時（sticky）表示**し、どの会社を操作しているかを明確にする（誤操作防止）。
- 会社一覧（SC-91）と分離することで、テナント単位の管理が完結し、視点が明確になる。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| アクセス可能者 | **システム管理者（運営）のみ** |
| 対象 | URL の `?company=<id>` で特定した**1社**。以降の設定/アカウント操作はすべてこの会社に適用 |
| データ | 設定＝`Company`（会社コード/フラグ）・`Account`（管理DB）／**所属＝会社DB `quest_group_members`**（QG所属は会社DBが正・§8-①） |

## 3. レイアウト構成（決定・業務層）

- **共通ヘッダー**（運営バッジ＋ベル＋アバターメニュー）。
- **パンくず**: システム管理 › 会社一覧 › ◯◯株式会社。
- **文脈バナー（`.ctx`・sticky）**: **会社アイコン〔`.quest-icon`＝画像 or 頭文字タイル・会社カラー〕＋「メンテナンス中の会社」ラベル＋会社名（大）＋会社コード（等幅）＋状態バッジ＋DB識別子＋件数＋「会社一覧へ戻る」**。会社カラーで左帯を色付けし識別性を上げる。**共通ヘッダーの直下（`top: --header-h`）で固定**し、スクロールしても表示。**z-index はヘッダーより低く**（ヘッダーと重ならず、アバターメニュー等のヘッダー内UIが常に手前）。
- **会社プロフィールカード**: **会社アバター/アイコン（アップロード・未設定は頭文字フォールバック）＋会社カラー（`.swatches`）**。変更は**バナーのアイコン・カラー（左帯）に即反映**。
- **会社設定カード**: **`.switch` トグル3種**＋DB識別子＋プロビジョニング注記。
- **クエストグループカード**: この会社のクエストグループ一覧（名称・コード・メンバー数）＋「＋グループ作成」＋行操作（リネーム／削除）。
- **アカウント & 所属（この会社）**: 一覧標準（検索＋状態フィルタ）＋テーブル＋「＋アカウント発行」（会社は固定表示）。
- **モーダル**: アカウント発行/編集（対象会社を固定表示・所属グループはこの会社の候補）／クエストグループ作成・リネーム（対象会社を固定表示）。

## 4. 表示・入力項目

### 4.1 文脈バナー（メンテ中の会社）
- **会社アイコン**（画像 or 頭文字タイル・会社カラー）／会社名（大・ピクセル見出し）／**会社コード（等幅・読み取り専用）**／状態／DB識別子／アカウント数・グループ数／会社一覧へ戻る。会社アイコン＋カラーで識別。会社コードは作成時確定・ここでは変更不可。

### 4.1b 会社プロフィール（アバター・カラー）
- **会社アバター/アイコン**（アップロード／未設定は頭文字＋会社カラー・`Company.icon_image_path`）＋**会社カラー**（プリセット `.swatches`・`Company.color`）。クエスト（SC-11）と同方式。変更はバナー・一覧に反映。

### 4.2 会社設定（`.switch`・Company フラグ）

| 設定 | フラグ | 既定 | 補足 |
| --- | --- | --- | --- |
| 投票の匿名化 | `vote_anonymized` | ON | ON=集計数のみ（匿名）／OFF=賛成/反対のアバターを表示（記名） |
| 匿名時に所有者/管理者へ投票者を隠す | `hide_voters_from_managers` | ON | ON=管理者にも非開示／OFF=所有者・クエスト管理者のみ確認可。**匿名化 OFF（記名）時は無効** |
| MFA を必須にする | `mfa_required` | ON | ON=メールOTP（信頼済み端末はスキップ）／OFF=ID＋パスワードのみ |

- **DB接続識別子**（`.env` 参照キー）＋**プロビジョニング注記**（compose 手編集・物理分離）。

> **位置づけ（2026-08-01 更新・SoD §8-⑯）**: SC-92（システム管理者）は **全社範囲の最上位画面**で、**SC-93（会社アカウント管理者）と SC-90（QG管理者）の全操作を全会社で実施できる**。
> - **SC-93（会社アカウント管理者）の操作**＝アカウントの発行/編集/無効化⇄再有効化/PW再設定は、SC-92 でも可能（SC-93 は自社のみ・SC-92 は全会社を `?company` で選択）。
> - **SC-90（QG管理者）の操作**＝グループへの参加追加/除外は、SC-92 の所属グループ割当（行形式エディタ）に含まれる。
> - 加えて **SC-92 のみ**＝**会社設定・会社プロフィール・所属グループの割当・システムロール付与（`company_account_admin`/`system_admin`）・グループ内ロール `admin`（QG管理者）の付与/剥奪**（§8-①＝ロール付与は system_admin のみ）。

### 4.2c クエストグループ（この会社・CRUD＝system_admin・B.3）
- **一覧**＝グループ名 / **コード**（`quest_group_code`・等幅・作成時のみ確定＝以後不変）/ **メンバー数**（有効所属 `quest_group_members.removed_at IS NULL`）/ 操作（リネーム・削除）。会社DB `quest_groups`（`deleted_at IS NULL`）。
- **作成**（`＋グループ作成`）＝モーダルで `quest_group_code`（英大文字始まり・`A-Z`/`0-9`/`-`・2〜20字・会社内一意・大文字正規化・§5.4）＋`name`。作成したグループがアカウント編集「所属グループ」の候補になる。
- **リネーム**＝`name` のみ変更（**コードは不変**）。一覧・所属バッジの表示名に反映。
- **削除**＝**空のグループのみ**（有効所属・クエストがある間は不可＝先に所属を外す）。トゥームストーン（`quest_groups.deleted_at`）で過去の所属履歴は保持（B.3）。
- **権限**＝作成・リネーム・削除は**システム管理者のみ**（会社構造の変更＝会社設定と同格・SoD §8-⑯＝会社アカ管理者/QG管理者は不可）。

### 4.3 アカウント & 所属（この会社）
- **氏名 / ログインID / メールアドレス / システムロール（一般 / 会社アカウント管理者 / システム管理者＝3値）/ 所属クエストグループ（複数可・各グループのロール〔QG管理者=admin / メンバー=member〕）/ 状態 / 操作**。※ログインIDとメールは別項目。※**「クエストグループ管理者」は system_role ではなく所属グループの `admin` ロールで表す**（B案 2026-07-27）。
- **システムロール＝3値（データモデル §3 `system_role`・SoD §8-⑯）**: `general`（一般）／`company_account_admin`（**会社アカウント管理者**＝自社の全アカウントのライフサイクル管理・SC-93）／`system_admin`（**システム管理者**＝運営）。**いずれの `system_role` の付与/変更も system_admin のみ**（会社アカウント管理者・QG管理者は付与不可・§8-①）。
- **操作＝編集 / パスワード再設定 / 無効化（⇄再有効化）**（SC-90 の旧機能を含む全操作を全社範囲で）。
- 発行/編集モーダル＝**対象会社（固定表示）**・氏名・**ログインID（識別子）**・**メールアドレス（OTP/初回設定リンク送付先）**・**システムロール（一般/会社アカウント管理者/システム管理者＝3値）**・**所属グループ（行形式エディタ）**。所属グループは**選択済みグループを1行ずつ表示**し、各行に**グループ内ロールのセグメント切替〔メンバー=member / 管理者=admin〕＋削除〔✕〕**、末尾の**「＋グループを追加」プルダウン**（この会社の未選択グループのみ・自由入力なし）から行を追加。役割の既定は member。保存で `memberships:[{group_id, role}]` 相当を更新し、一覧の「·管理者」バッジに反映。**`admin`（＝クエストグループ管理者の任命）指定も system_admin のみ可**（指定されたユーザーは当該グループを SC-90 で管理可能に）。編集時は**既存の所属・グループ内ロールをモーダルへ反映**。
- **自己ロックアウト防止**: 自分自身の `system_admin→` 降格は不可。降格/無効化で有効な system_admin が 0 名になる操作は拒否（`last_system_admin`・B.2）。

## 5. アクション・遷移

| トリガー | 条件 | 遷移/結果 |
| --- | --- | --- |
| 会社アバター/カラー変更 | — | `Company.icon_image_path`/`color` を更新。**バナー・一覧の表示に即反映**（画像は MinIO 保管） |
| 設定トグル（3種） | — | 当該会社の `Company` フラグを更新（サーバー保存）。匿名化OFFで「管理者へ隠す」は自動無効 |
| ＋グループ作成 | — | モーダル→この会社の会社DB `quest_groups` に INSERT（`quest_group_code` 大文字正規化＋会社内一意）。所属エディタの候補に追加 |
| グループ リネーム | — | 会社DB `quest_groups.name` を更新（`quest_group_code` は不変）。一覧・所属バッジに反映 |
| グループ 削除 | 空グループのみ | 有効所属/クエストがあれば拒否（`in_use`）。空ならトゥームストーン（`deleted_at`・履歴保持）。破壊的＝確認 |
| ＋アカウント発行 | — | モーダル→**この会社に** Account 作成（管理DB）→会社DBに User ミラー生成＋所属（会社DB `quest_group_members`・グループ内ロール member/admin）割当。初回ログインでパスワード設定 |
| 編集 | — | 氏名/ログインID/メール/**システムロール（一般/会社アカウント管理者/システム管理者）**変更・**所属グループの割当変更＋グループ内ロール（member/admin）変更**（フル操作。ロール付与は system_admin のみ） |
| パスワード再設定 | — | 初回パスワード設定フローに戻す（`otp_challenges` password_setup リンク再送・72h）。全社範囲 |
| 無効化（論理削除）/ 再有効化 | — | `accounts.status` を disabled⇄active。入力（アイデア/投票/評価/コメント）は保持。全社範囲 |
| 会社一覧へ戻る / パンくず | — | **SC-91** |
| 検索 / 状態フィルタ | — | この会社のアカウント一覧を更新 |

## 6. データ・API（想定）

- **GET `/api/sysadmin/companies/{id}`**: 会社の詳細＋フラグ＋所属グループ候補。
- **PATCH `/api/sysadmin/companies/{id}`**: `color` / `icon_image_path`（会社アバター・カラー）を更新。アイコン画像は MinIO に保管（ハッシュ名）。
- **PATCH `/api/sysadmin/companies/{id}/settings`**: `vote_anonymized` / `hide_voters_from_managers` / `mfa_required` を更新。
- **GET/POST/PATCH `/api/sysadmin/companies/{id}/accounts`**: この会社のアカウント発行・編集（ロール・所属）。所属割当は**会社DB `quest_group_members`**（QG所属は会社DBが正）。
- **GET/POST/PATCH/DELETE `/admin/companies/{id}/quest-groups`〔/{group_id}〕**: クエストグループの一覧/作成/リネーム/削除（API設計 B.3・実 API は `/api/v1/admin/...`）。作成=`quest_group_code`＋`name`／リネーム=`name` のみ／削除=空グループのみ（トゥームストーン）。
- 権限は**システム管理者のみ**。操作は監査ログ（`SystemAdmin 操作ログ`）に記録。

## 7. アクセシビリティ / 表示配慮

- **文脈バナーで対象会社を常時明示**（sticky・会社カラー）。誤って別会社を操作しないための最重要要素。
- トグルは `.switch`（focus-visible・ON/OFF 状態語）。依存関係（匿名化OFF→管理者開示は無効）を UI と文言で明示。
- 状態・ロールは色＋テキスト。DB識別子は等幅。破壊的操作は確認。

## 8. 状態・バリエーション

| 状態 | 表示 |
| --- | --- |
| 会社=準備中/停止 | バナーに状態バッジ。設定は可（停止中の扱いは TBD） |
