# SC-70 プロジェクト一覧（画面設計 / 機能詳細）

> 画面遷移図: [画面遷移図](../画面遷移図.md) ／ 要件: [要件定義 README](../../要件定義/README.md)（FR-43 ソリューション開発）／ API: [API設計 Q_ソリューション開発](../../API設計/Q_ソリューション開発.md)（Q.1 一覧）／ データモデル: [データモデル](../../データモデル.md) §5.49（`projects`）

## 1. 概要・目的

- **ソリューション開発プロジェクトの一覧**。go 判定コンセプト（FR-42）から起票されたプロジェクト（＝タスクツリー）を俯瞰し、詳細（SC-71）へ入る。
- **配置＝グローバル「プロジェクト」領域**（クエストタブには混ぜない＝コンセプト段までの「探索・合議」とは別パラダイムの「実行・デリバリ管理」・[設計ドラフト](../../設計ドラフト/ソリューション開発機能_設計.md) §1.2/§6）。
- **レイアウトはクエスト一覧（SC-10）を踏襲**（[フロントエンド実装フロー規約](../../規約/フロントエンド実装フロー規約.md) §2.1c）＝「← ダッシュボードへ戻る」＋大見出し「プロジェクト一覧」＋右上「＋ プロジェクトを作成」＋説明＋共有 `DataTable`（カード/リスト切替）。**リストは溢れを「…」省略／カードは全文折り返し**（進捗・タスク・更新は1行）。件名はリンクにせず行クリックで詳細へ（他一覧と統一）。
- **起票（作成）の2経路**：① **SC-61 コンセプト詳細の「開発を始める」**（コンセプト由来・1コンセプト=1プロジェクト）／② **本画面の「＋ プロジェクトを作成」**＝**コンセプトに紐づかない単純タスク管理プロジェクト**（`concept_id`/`quest_id` NULL・2026-09-27 追加）。いずれも下記の**プロジェクト作成ダイアログ**（§4b）で作成。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| 閲覧 | **各プロジェクトの由来クエストのパーティー所属（イノベーション担当）OR そのプロジェクトの開発メンバー（`project_members`）**（門番＝`can_access_project`・[API Q](../../API設計/Q_ソリューション開発.md) Q.0）。一覧はサーバーが閲覧可能なもののみ返す |
| 作成 | 本画面では不可（SC-61「開発を始める」から・`decision='go'` 時のみ） |
| 行操作 | 詳細（SC-71）へ遷移。削除/複製等の行アクションは第一版では持たない（プロジェクトのライフサイクルは SC-71 の `status` で管理） |

## 3. レイアウト構成（決定）

- **一覧セクションは白パネルで囲う**（`.card admin-create admin-create--table`・デザイン標準 §4.5「一覧セクションは白パネル」）。見出し「プロジェクト」はカード上部 `.admin-toolbar`。
- **共有 `DataTable`（server モード）**＝サーバー委譲（§4.5・§4.1）。ツールバー（検索/並び替え/絞り込み/列設定/エクスポート/表示密度）は共有部品のまま。
- 業務層クリーン基調。ゲーム層要素は持たない。

## 4. 表示項目（列）

> 列 `sortable`/`filter` フラグは backend ホワイトリスト（Q.1）に一致させる（[フロントエンド実装フロー規約](../../規約/フロントエンド実装フロー規約.md) §4.1）。

| 列 | 内容 | ソート/絞込 |
| --- | --- | --- |
| プロジェクト名 | `title`（主要名称列・先頭固定・詳細へのリンク） | ソート可 |
| 由来コンセプト | `concept.title`（SC-61 コンセプト詳細へのサブリンク） | 絞込（`concept_id`） |
| 由来クエスト | `quest.title` | 絞込（`quest_id`） |
| 状態 | `status`（planning/in_progress/on_hold/done・バッジ） | 絞込（enum 多値） |
| 進捗 | `progress`＝配下タスクの done/total（バー＋`n/m`・サーバー算出） | ソート可 |
| タスク数 | `task_count` | ソート可 |
| 所有者 | `owner`（アバター＋氏名） | — |
| 更新 | `updated_at`（相対/絶対） | ソート可（既定降順） |

- **空状態**＝「まだプロジェクトがありません。『＋ プロジェクトを作成』か、コンセプト詳細の『開発を始める』で起票します。」
- **リスト**＝各列は溢れを「…」省略（§4.5④・進捗は数値 `done/total`）。**カード**＝見出し・由来は全文折り返し、`進捗/タスク/更新` は1行。**コンセプト非依存プロジェクト**は 由来列＝「—」／カードは「コンセプト無し」。

## 4b. プロジェクト作成ダイアログ（共有・SC-70/SC-61 で使用）

> **新規 UI は作らず、クエスト作成ダイアログの構成を踏襲**（[フロントエンド実装フロー規約](../../規約/フロントエンド実装フロー規約.md) §2.1c）。入力モーダル標準＋[§4.7](../デザイン標準.md) 検証。作成後は**遷移せずダイアログを閉じる**（ユーザー要望）。

| 項目 | 種別 | 必須 | 補足 |
| --- | --- | --- | --- |
| プロジェクト名 | テキスト | **必須** | コンセプト由来時は「〈コンセプト名〉 開発」で初期化 |
| 概要 | テキストエリア | 任意 | コンセプト由来時は課題＋価値提案で初期化 |
| ローンチ状態／導入計画／KPI 実測 | テキスト/エリア | 任意 | `deployment`（jsonb）＝⑤導入メタ |
| **参加グループ（アクセス条件・任意）** | Multiselect | 任意 | **クエスト作成の同 Field を踏襲**＝開発メンバー候補の範囲を絞る（未選択＝全社） |
| **参加メンバー（開発メンバー）・役割** | 参加メンバー編集エディタ | 任意 | **クエスト作成「参加メンバー（パーティー）・権限」を踏襲**（候補追加＋選択中一覧）＝唯一の適応＝クエスト5権限チェック→**開発役割（lead/member）** |

- **経路**＝SC-70「＋ プロジェクトを作成」（コンセプト非依存＝`POST /projects`）／SC-61「開発を始める」（コンセプト由来＝`POST /concepts/{id}/project`・コンセプト内容で初期値）。
- 起票後＝一覧は更新イベントで反映（試作はデモ）。作成成功トーストに設定した開発メンバー数を含める。

## 5. アクション・遷移

| トリガー | 条件 | 遷移/結果 |
| --- | --- | --- |
| ＋ プロジェクトを作成 | 認証済み | プロジェクト作成ダイアログ（§4b・コンセプト非依存＝単純タスク管理）→ 作成→閉じる |
| 行クリック | 閲覧可 | **SC-71 プロジェクト詳細**へ（件名はリンクにしない・行クリックで遷移） |
| 検索/ソート/絞込/ページ | 閲覧可 | サーバー委譲で再取得（URL 同期・状態復元＝§4.5⑨/§4.12） |
| エクスポート（CSV） | 閲覧可 | 現在の絞込・列で CSV（`format=csv`・§4.5⑦） |

## 6. 状態・バリエーション

| 状態 | 表示 |
| --- | --- |
| 0 件 | 空状態メッセージ（§4） |
| 読み込み中 | DataTable 既定のローディング（§13） |
| 閲覧不可（範囲外） | サーバーが返さない＝一覧に出ない（存在秘匿・Q.0） |

## 7. データ・API（想定）

- **GET `/projects`**（Q.1）＝`items[]`＝`{id, title, status, concept:{id,title}, quest:{id,title}, progress〔done/total〕, task_count, owner, updated_at}`＋カーソル。DataTable クエリ契約（§1.8.1・複数ソート・enum フィルタ・`page`/`per_page`＋`page_info.total`・`format=csv`）。
- 閲覧範囲（パーティー OR 開発メンバー）・進捗算出はサーバー（Q.0/Q.1）。

## 8. アクセシビリティ / 表示配慮

- DataTable の a11y（列見出し `aria-sort`・行リンク・ページャ `aria-current`）は共有部品に準拠。
- 進捗は色のみに依存しない（`n/m` テキスト併記）。
