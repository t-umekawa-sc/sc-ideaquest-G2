## 1. 概要・目的

- **1 プロジェクト（＝1 go コンセプト由来）の実行管理画面**（フルページ）。**WBS ツリー（要件→タスク）**でブレイクダウンし、担当・状態・進捗・期日を管理する（ISO 56001 ④開発）。
- **二層メンバーシップの同席**＝**開発担当**（`project_members`）が実行し、**イノベーション担当**（由来クエストのパーティー）が参照＋チャットで口を出す。両者がタスクチャットで見え方の差＝**仕様ブレを突き合わせ**る（[設計ドラフト](../../設計ドラフト/ソリューション開発機能_設計.md) §7）。
- **導入・価値実現メタ**（⑤導入）＝コンセプト段の viability を導入後の実測で検証し KPI ループを閉じる（§4.5）。

## 2. アクセス条件・権限

| 操作 | 権限（[API Q](../../API設計/Q_ソリューション開発.md) Q.0） |
| --- | --- |
| 参照・チャット発言 | イノベーション担当（由来クエストのパーティー）**OR** 開発担当（`project_members`）。発言者は**開発/イノベーションのバッジで区別**（見え方の差の可視化） |
| プロジェクト編集（title/description/status/deployment/external_link） | 起票者本人 ＋ owner/quest_admin |
| 開発メンバー管理（追加/役割変更/除外） | project owner ＋ quest owner/quest_admin |
| タスク作成/編集/削除/割当/並替/親変更 | project owner ＋ 開発 `lead` ＋ owner/quest_admin |
| タスクの状態更新（status/done） | **担当者(assignee)** ＋ 開発 `lead` ＋ project owner |

- **担当割当先は開発メンバー（`project_members`）に限る**（範囲外は 422・Q.0）。
- クエスト完了後も**書き込みは凍結しない**（実行段は完了後に走る・Q.0・2026-09-27 確定）。
- `my_permissions`＋自分の領域（dev/innovation/both）はサーバー算出（フロントは再実装しない）。

## 3. レイアウト構成（決定）

- フルページ（SC-61 コンセプト詳細と同型の土台＝共有クラス再利用・DRY）。
- **上から**＝①ヘッダー（戻る＋タイトル/状態＋由来コンセプト/クエストのリンク＋編集）→ ②開発メンバー（party 一覧踏襲）→ ③WBS ツリー（核心）→ ④導入・価値実現メタ。タスク選択で⑤タスクチャット（ドロワ or タスク詳細）。
- 業務層クリーン基調。ゲーム要素は完了報酬トースト（§14・+開発XP/コイン）に限定。

## 4. 表示項目

### 4.1 ヘッダー
- 戻る（← プロジェクト一覧）／**タイトル**（`title`）＋**状態バッジ**（planning/in_progress/on_hold/done）。
- **由来コンセプト**（SC-61 へ）＋**由来クエスト**（SC-12 へ）のリンク（出自を明示）。
- **編集**（起票者/owner）＝プロジェクト編集モーダル（title/description/status）。

### 4.2 開発メンバー（`project_members`・**SC-12 パーティー一覧を踏襲**）
- **「誰がどの役割か」を一覧表示**＝`.pmember` 相当の行（アバター＋氏名＋**役割バッジ `lead`/`member`**）。SC-12 の `PERM_BADGE` 表示を踏襲（バッジの意味を役割に差し替え）。
- **イノベーション担当（クエストパーティー）も参考表示**＝「参照＋口出し可」の一覧（read 合成・`innovation_members[]`）。開発担当と視覚的に区別。
- **「開発メンバーを管理」**（project owner/quest_admin）＝**SC-12「パーティー・権限を編集」エディタを踏襲**したモーダル（候補追加＋選択中一覧・唯一の適応＝権限チェック→役割 lead/member）。候補＝会社ディレクトリ（B 流用）。

### 4.3 WBS ツリー（核心・`tasks` 自己参照ツリー）
- **要件（L1）→ タスク（L2）→…** を任意深さのツリーで表示（`kind` で粒度ラベル・[設計ドラフト](../../設計ドラフト/ソリューション開発機能_設計.md) §3.1）。
- 各ノード＝**タイトル／`kind`／担当（アバター）／状態（todo/doing/done/blocked）／期日／進捗ロールアップ**（親は子孫の done 比率）。
- 行操作＝**＋子タスク追加**／**編集**（SC-72）／**状態変更**（担当者/lead/owner）／**削除**（子ありは 409＝先に子処理を促す・Q.2）／並べ替え（`sort_order`）。
- **状態→done で完了報酬**＝開発XP＋コインのトースト（§14・Q.3・冪等）。
- **CSV 取込・コンセプト種継ぎ**＝種継ぎ（「解の形態＋必要な能力」→要件候補）は候補提示（Q.2 seed）。**CSV 取込は Phase2**（本画面には出さない）。

### 4.4 タスクチャット（**SC-24 共有 `IdeaChatView` を踏襲**・`taskSource`）
- タスク選択で軽量チャット（ドロワ or タスク詳細内）。**チャット中核（`chat_thread owner_type='task'`）を再利用**＝メッセージ/リアクション/ピン/メンション/引用/添付は SC-24 と同一機能。
- **両担当が同席**＝発言者に**開発/イノベーションのバッジ**を付け、領域の見え方の差＝**仕様ブレを突き合わせ**る場にする。
- 「束ねて仕様に」（プロジェクト配下の全 thread 横断集約）は Phase2。

### 4.5 導入・価値実現メタ（`projects.deployment`・jsonb・⑤導入）
- 導入計画メモ／ローンチ状態／**KPI 実測**（自由記述＋状態）を表示・編集（起票者/owner）。
- 狙い＝コンセプト段の viability（コスト/収益/ROI）を**導入後の実測で検証**し、[FR-39](../../設計ドラフト/FR-39_クエスト最終結果_ISO56001.md) §9/§10 とループを閉じる（[設計ドラフト](../../設計ドラフト/ソリューション開発機能_設計.md) §3.5）。
- 第一版は最小（記述＋状態）。固定 KPI・実測連携は Phase2。

## 5. アクション・遷移

| トリガー | 条件 | 遷移/結果 |
| --- | --- | --- |
| ← プロジェクト一覧 | — | SC-70 へ |
| 由来コンセプト/クエスト リンク | 閲覧可 | SC-61 / SC-12 へ |
| プロジェクト編集 | 起票者/owner | 編集モーダル（`PATCH /projects/{id}`・無変更は info・§14） |
| 開発メンバーを管理 | owner/quest_admin | party 編集踏襲モーダル（`POST/PATCH/DELETE /projects/{id}/members`・Q.1b） |
| ＋タスク追加 / 編集 | 管理権限 | **SC-72 タスク登録/編集モーダル** |
| タスク状態→done | 担当者/lead/owner | `PATCH /tasks/{id}`（status=done）→ **完了報酬トースト**（開発XP＋コイン・Q.3） |
| タスク削除 | 管理権限 | 確認ダイアログ（§15）→ `DELETE`（子ありは 409・先に子処理） |
| タスク選択 | 閲覧可 | タスクチャット（ドロワ/タスク詳細・SC-24 踏襲） |
| 導入メタ編集 | 起票者/owner | `PATCH /projects/{id}`（deployment） |

## 6. 状態・バリエーション

| 状態 | 表示 |
| --- | --- |
| タスク0件 | 「まだタスクがありません。『＋タスク追加』か、コンセプトの『解の形態＋必要な能力』から種継ぎできます。」 |
| 開発メンバー0名 | 「開発メンバー未設定」＋（owner）「開発メンバーを管理」。担当割当は不可（先にメンバー追加） |
| done タスク | 打ち消し/淡色＋完了バッジ（完了済みの凍結表示・デザイン標準の完了UI標準に準拠） |
| blocked タスク | 注意バッジ（任意状態・第一版は表示のみ） |
| 閲覧のみ（イノベーション担当・非 lead） | 管理系ボタンは事前無効化＋tooltip（デザイン標準の完了/権限凍結UI標準） |
| reduce-motion | 進捗/トーストの動きは静止（§4.9） |

## 7. データ・API（想定）

- **GET `/projects/{id}`**（Q.1）＝`project`（title/description/status/deployment/external_link/concept/quest/owner/progress/my_permissions/viewer_domain）。
- **GET `/projects/{id}/tasks`**（Q.2）＝ネストした tree。**GET `/projects/{id}/members`**（Q.1b）＝`members[]`（役割）＋`innovation_members[]`。
- **PATCH `/projects/{id}`**（Q.1・status/deployment 等）／**タスク CRUD**（Q.2）／**メンバー管理**（Q.1b）／**タスクチャット**＝既存チャット EP（thread 単位・Q.4・E 再利用）。
- 完了報酬＝タスク done で G 委譲（`delivery_xp_gain`・冪等・Q.3）。

## 8. アクセシビリティ / 表示配慮

- ツリーは `role="tree"`/`treeitem`（展開/折りたたみ・キーボード操作）。状態/進捗は色のみに依存しない（バッジ文言＋`n/m`）。
- 権限で不可の操作は事前無効化＋tooltip（押下後の失敗より親切・完了/権限凍結UI標準）。
- チャット/確認ダイアログ/トーストは共有部品の a11y に準拠。
