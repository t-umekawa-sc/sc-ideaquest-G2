> 運営（管理者）が投稿した**全社お知らせ**を、全ユーザーが**ダッシュボード（Zone D）＋専用一覧/詳細**で読む。本文はリッチテキスト（`RichTextView`・サニタイズ済）。
> 仕様の正＝[ダッシュボード再設計・お知らせ 設計](../../設計ドラフト/ダッシュボード再設計・お知らせ_設計.md) §4・[API設計 U](../../API設計/U_お知らせ.md)（U.0/U.1/U.3）・[データモデル §5.65/5.66](../../データモデル.md)。要件＝[FR-49](../../要件定義/README.md#6-機能要件)。
> 対象デザイン標準＝[デザイン標準](../デザイン標準.md)（DataTable §4.5・バックリンク・バッジ）。一覧は [フロントエンド実装フロー規約 §4.1](../../規約/フロントエンド実装フロー規約.md)（DataTable）に準拠。
> リッチテキスト部品は **SC-50（[情報インプット](SC-50_情報インプット.md)）の資産を中立化して共用**（`RichTextView`/`RichTextEditor`＝`app/core/richtext` の backend サニタイズと対）。

## 1. 概要・目的

- 全ユーザーが**運営からの全社お知らせ**を読む（告知・募集・運用連絡）。投稿/編集/ピン留めは管理者（[SC-96](SC-96_お知らせ管理.md)）側で、**本画面は閲覧専用**。
- 到達動線＝**ダッシュボード Zone D「📢 お知らせ」パネルの「すべて見る」**（主）＋グローバルナビ「お知らせ」（`AppNav`・全員）。
- **なぜ専用一覧を別に持つか**＝ダッシュボードのパネルは選別3件（§4.3a＝ピン→未読で埋める→既読非ピンは出さない）に絞るため、既読も含む全件を落ち着いて読む場が要る（ダッシュボードは「気づき」・一覧は「読み返し」の分担）。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| アクセス可能者 | **会社内の active な全ユーザー**（`require_me`・`role=general` 可）。他テナントは不可。 |
| 表示対象 | `status=published` かつ 掲載期間内（`starts_at<=now`〔or NULL〕AND `now<ends_at`〔or NULL〕）AND `deleted_at IS NULL`（[API U.0](../../API設計/U_お知らせ.md)）。draft/期間外/削除は一覧に出ず、詳細直リンクは **404**。 |
| 操作 | 閲覧のみ（ピン留め・編集・削除は無い＝[SC-96](SC-96_お知らせ管理.md) 管理者限定）。既読化は閲覧の副作用（§5）。 |

- **公開会社（`access_mode=public`）での閲覧＝可（実装済・2026-10-07）**（設計 §4.6／[API U.0](../../API設計/U_お知らせ.md)）＝FR-48 の外周ガード許可リスト（`access_gate._CONTEST_ALLOW`）に `/announcements`（read／既読）を含め、公開会社でも全ロールが閲覧できる（お知らせは**会社DBスコープ**＝他社漏れなし）。管理（作成/編集＝[SC-96](SC-96_お知らせ管理.md)）は `/admin/announcements`＝管理者のみ（外周ガードの管理許可リスト）。公開ナビ（BIZ_PUBLIC）にも「📢 お知らせ」を出す。

## 3. レイアウト構成（一覧・`/announcements`）

- 冒頭＝**フローティング バックリンク**「← ダッシュボードへ戻る」（`.backlink--float`）＋見出し「📢 運営からのお知らせ」＋リード文（**未読 N 件**・行クリックで全文）。
- **既読状態スイッチ**（`.segmented`・`role=radiogroup`）＝**すべて／未読／既読**（各**件数バッジ**付き・既定＝すべて）。クライアント側の絞り込み（`statusLabel` で判定）。**なぜ**＝「未読だけ追う」「読んだものを探す」の両方の読み方を低摩擦で切替（ユーザー要望）。
- **本体＝標準 DataTable**（`storageKey="sc95-announcements"`）＝カード/リスト切替（既定＝**リスト**）・横断検索（タイトル＋本文抜粋）・列フィルタ/ソート・ページャ（12/24/48・既定12）・CSV。

### 3.1 一覧の列（DataTable）

| 列 | 内容 | ソート/フィルタ |
| --- | --- | --- |
| タイトル | `idea-title` リンク（→詳細）。**先頭の 📌 は付けない**（ピンは「ピン」列で表現） | ソート可・テキストフィルタ（検索対象＝タイトル＋本文抜粋） |
| 公開日 | `published_at`（日付） | ソート可 |
| ピン | `📌`／`—` | ソート可・enum フィルタ（📌 ピン/—） |
| 状態 | **未読**（`badge-danger`）/**既読**（`badge-muted`） | ソート可・enum フィルタ（未読/既読） |
| 既読日時 | `read_at`（分まで・未読は「—」） | ソート可 |

- **本文抜粋（`excerpt`＝`body_text` 先頭）は列に出さず、カード表示のビューにのみ使う**。**なぜ**＝リスト行は一覧性優先（タイトル/状態/日付）、カードは本文の手がかりが欲しい、の役割分担。
- カード＝タイトル＋状態バッジ＋本文抜粋＋「公開 … ・ 既読 …」。

### 3.2 タイトル先頭📌の方針（横断決定）

- **タイトル先頭に 📌 を付けるのはダッシュボード Zone D パネルのみ**。一覧（本画面）・詳細はピンを**列/メタ**で表現し、タイトル文字列には混ぜない。**なぜ**＝ダッシュボードは一目の優先度表示が要る一方、一覧/詳細では列・バッジで十分で、タイトルの可読性を保つため（ユーザー要望）。

## 4. レイアウト構成（詳細・`/announcements/[announcementId]`）

- **フルページ遷移**（intercept モーダルではない）。**なぜ**＝お知らせは「開いて読む」単独コンテンツで、一覧の文脈を保持したまま重ねる必要が薄く、直リンク/ブックマーク共有に素直なため（SC-50 情報詳細の URL付きモーダルとは異なる判断）。
- 構成＝**文脈バックリンク**（§5）＋`article.card`（タイトル `h1` ＋メタ「🗓 公開日 ・ 投稿者（`created_by.display_name`／無ければ「運営」）」＋**本文 `RichTextView`**〔`body_html` をサニタイズ済み前提で表示〕）。
- **表示対象外（draft/期間外/削除）＝404 の体裁**＝「このお知らせは見つかりませんでした（公開終了・削除の可能性があります）」＋バックリンクのみ。

## 5. アクション・遷移

| 操作 | 条件 | 遷移/結果 |
| --- | --- | --- |
| 行/カード/タイトルをクリック | 全ユーザー | **詳細（`/announcements/[id]`）へ遷移**。一覧からの遷移は来歴を記録（`markAnnouncementFromList`・§5.1） |
| 詳細を開く | 全ユーザー | 初回表示時に **未読なら既読化**（`POST /announcements/{id}/read`・冪等）→ `ANNOUNCEMENTS_CHANGED_EVENT` を発火（ヘッダー/ダッシュボードの未読数を更新） |
| すべて/未読/既読 スイッチ | 全ユーザー | クライアント側で表示行を絞り込み（件数バッジ連動） |
| 検索/絞込/ソート/表示切替 | 全ユーザー | DataTable の標準（URL/`localStorage` で状態復元） |
| ← 戻る | 全ユーザー | §5.1（文脈で戻り先/ラベルを出し分け） |

### 5.1 戻る動線の出し分け（文脈依存）

- **戻る動作は常に `router.back()`**（`backToListOr`＝実際の遷移元へ復帰）。**ラベルと fallback だけ**を来歴で出し分ける（`lib/nav`）:
  - **一覧から来た**（行クリックで `markAnnouncementFromList` を set）＝「← お知らせ一覧へ戻る」／fallback `/announcements`。
  - **ダッシュボード経由・直リンク**（来歴なし）＝「← ダッシュボードへ戻る」／fallback `/`。
- 来歴はマウント時に**1回だけ消費**（`consumeAnnouncementFromList`）。**なぜ**＝同じ詳細画面でも「どこから来たか」で自然な戻り先が変わるため（ダッシュボードの📢→詳細→ダッシュボード、一覧→詳細→一覧）。

## 6. データ・API（正＝[API設計 U](../../API設計/U_お知らせ.md)）

- 一覧＝`GET /announcements`（`cursor`/`limit`/`unread`・応答に `unread_count` 同梱）。**実装の現況**＝フロントは `limit=100` で取得し DataTable 側でページング/絞り込み（サーバーカーソルは未使用＝お知らせ件数が小さい前提）。件数が増えたらサーバー委譲へ移行（§8）。
- 詳細＝`GET /announcements/{id}`（`body_html`・`created_by`・`is_read`・掲載期間）。
- 既読＝`POST /announcements/{id}/read`（冪等・`verify_origin`/`verify_csrf`）。
- ダッシュボード パネル＝`GET /dashboard` の `announcements`（最大3件・§4.3a 選別）＋`announcements_unread_count`（[API U.3](../../API設計/U_お知らせ.md)）。

## 7. セキュリティ・表示配慮

- **本文 XSS＝保存時に backend `app/core/richtext.sanitize_html`（nh3・許可リスト）で無害化済み**＝表示は `RichTextView`（`dangerouslySetInnerHTML`・サニタイズ済のみ）。`body_text` はサーバー派生（検索/抜粋用・クライアントから受け取らない）。
- 状態（未読/既読）・ピンは**色のみに依存せずテキスト併記**（バッジ文言）。既読スイッチは `role=radiogroup`。
- テナント分離＝会社DB（他社のお知らせは 404）。表示対象外（draft/期間外/削除）の直リンクは 404（存在秘匿）。
