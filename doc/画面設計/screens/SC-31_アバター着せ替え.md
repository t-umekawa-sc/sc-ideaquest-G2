# SC-31 アバター / 着せ替え（画面設計 / 機能詳細）

> 画面遷移図: `doc/画面設計/画面遷移図.md` ／ モック: `doc/画面設計/mocks/SC-31_アバター着せ替え.html` ／ 要件: `doc/要件定義/README.md`（FR-08・第6節「装備 / アイテム」）
> 対象デザイン標準: `doc/画面設計/デザイン標準.md`（**ゲーム層**＝レトロ/ドット・CRTガラス）

- 最終更新: 2026-07-19
- ステータス: ドラフト（機能詳細）

## 1. 概要・目的

- **3Dアバターを表示し、所有済み装備を着せ替える**画面（ゲーム層）。ゲーミフィケーションの「見た目のカスタマイズ」による楽しさ・継続動機の中心。
- アバターは **5スロット（頭 / 顔 / 体 / 手持ち / 背景）**・各スロット1点まで装備。**装備の入手はコイン購入のみ**（ショップ SC-30）で、本画面は**所有済み装備の付け替え**を担う。
- 導線: **共通ヘッダーのアバターメニュー「アバター / 着せ替え」**／ダッシュボード（SC-01）ヒーローの「▶ きせかえ」・ショートカットタイル「アバター」。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| アクセス可能者 | 認証済みユーザー全員（自分のアバターのみ編集） |
| 装備 | **所有済み（購入済み）装備**のみ着せ替え可。各スロット1点・「外す」で未装備に |
| 購入 | 本画面では行わない。未所有装備は**ショップ（SC-30）へ誘導**。購入・所有はサーバーで検証 |

## 3. レイアウト構成（決定・ゲーム層）

- **共通ヘッダー**（Lv/コイン/SP＋ベル＋アバターメニュー）。本画面ではアバターメニューの「アバター / 着せ替え」が現在地（`aria-current`）。
- **2カラム**（狭い画面〔≤900px〕は1カラム縦積み）:
  - **左＝アバタービューア（`.pixel-panel`＝CRTガラス・sticky）**: 3Dアバターを表示（本番は VRM/R3F で回転可）。氏名・Lv・（モックは装備を絵文字で重ねた見立て）。
  - **右＝ワードローブ**: コイン残高＋**ショップ導線**、スロットごと（頭/顔/体/手持ち/背景）に**所有装備＋「外す」＋未所有（ショップ）**を並べたグリッド。
- **レイヤー方針（1レイヤー1マテリアル）**: アバタービューアは CRTガラス（ゲーム層の顔）。ワードローブのカードは**可読性優先のクリーンカード＋ゲーム要素**（レアリティ色・ピクセル見出し・`.btn-pixel`）。SC-32 と同方針。

## 4. 表示・入力項目

### 4.1 アバタービューア（左・CRTガラス）
- **3Dアバター**（本番＝three-vrm・パーツ差し替え方式でスロット装備メッシュを反映。回転）。モックは `mascot-hero.png` ＋装備絵文字の重ねで見立て。
- **ベース切替（男 / 女）**＝ベースアバターは男女 2 体（§9.2）。切替は即時プレビュー反映・選択は保存（`users.avatar_base`）。動物キャラ等は将来（§9.6）。
- **氏名・レベル**。装備変更が**即座に反映**される（プレビュー同期）。

### 4.2 ワードローブ（右・スロット別）
- スロットは **5種（頭 / 顔 / 体 / 手持ち / 背景）**、各スロットに「装備中: ◯◯」を表示。
- 各スロットのグリッド先頭に **「✕ 外す」カード**（未装備にする）。続けて装備カード。
- **装備カード**＝サムネイル（本番は装備画像）＋名称＋**レアリティ**（コモン/標準/レア＝`--rarity-*`）。
  - **所有・装備中**: 枠を強調＋「装備中」バッジ。
  - **所有・未装備**: クリックで装備。
  - **未所有**: グレーアウト＋価格（◆N）＋「🔒 ショップで購入」。クリックで**ショップ（SC-30）へ誘導**。
- コイン残高（`◆ N`）と **「🛒 ショップへ」ボタン**を上部に表示。

### 4.3 装備ラインナップ（初期値・調整可）
- **入手はコイン購入のみ**。レアリティ3段階＝コモン10〜30 / 標準50〜150 / レア300〜800コイン（第6節）。
- モック初期セット（例）: 頭＝王冠/シルクハット/キャップ/麦わら帽、顔＝サングラス/メガネ/マスク、体＝アーマー/スーツ/道着/コート、手持ち＝剣/杖/本/大槌、背景＝夕焼け/星空/森/古城。※最終ラインナップは TBD。

## 5. アクション・遷移

| トリガー | 条件 | 遷移/結果 |
| --- | --- | --- |
| 装備カードをクリック | 所有済み | 同スロットの装備を差し替え（1点）。ビューアに即反映。**サーバーは所有を検証** |
| 「✕ 外す」 | — | 当該スロットを未装備に |
| 未所有カード / 「🛒 ショップへ」 | — | **SC-30 ショップ**へ（購入は SC-30 で実施） |
| ダッシュボードへ戻る | — | **SC-01** |

## 6. データ・API（想定）

- **GET `/api/items`**: 装備マスタ（名称/スロット/レアリティ/価格/パーツ参照）＋自分の所有・装備状況（`UserItem`）。
- **PUT `/api/me/avatar`**（or `/api/me/equipment`）: スロットごとの装備を更新。**サーバーで所有（購入済み）を検証**し、各スロット1点に正規化。
- 購入は **SC-30**（`POST /api/items/{id}/purchase`・コイン残高/価格をサーバー検証）。
- **3D**: 装備の VRM パーツをスロットに取り付け・差し替え（three-vrm / R3F）。

## 7. アクセシビリティ / 表示配慮

- 装備カードは `role="button"`・キーボード操作（Enter/Space）対応。装備状態は色だけでなく「装備中」バッジ＋文言で示す。
- レアリティは色＋テキスト併記（`--rarity-*`）。CRTガラス上の明るい文字は on-dark トークン（Lv=`--pixel-level-on-dark` 等）。
- **3D（WebGL）非対応環境**の代替表示は本設計 §9.3（2D フォールバック＝現行のマスコット画像＋装備アイコン重ねへ自動デグレード）。`prefers-reduced-motion` 尊重（回転/演出）。

## 8. 状態・バリエーション

| 状態 | 表示 |
| --- | --- |
| 所有0のスロット | 「外す」＋未所有（ショップ）カードのみ。装備は「なし」 |

## 9. 技術・設計決定（3D ビューア / VRM / フォールバック）

> 旧「残 TBD」を確定した設計決定（2026-08-27）。数値・ラインナップ・操作可否は本プロジェクト慣習に従い**初期値（後で調整可）**。技術スタックは要件定義（Three.js / React Three Fiber / three-vrm）に準拠＝[`doc/要件定義/README.md`](../../要件定義/README.md) 第7節。**着せ替え機能（スロット装備・所有検証・ショップ導線）は実装・接続済み**（`impl/README.md` SC-30/SC-31）＝本節は残る **3D 描画（VRM）** の設計を確定する。

### 9.1 装備ラインナップ（確定）

- **全社同一シード 19 点**を正式版として確定（§4.3 の初期セット＝`impl/backend/migrations/company/versions/0015_company_items.py`・`code` upsert・`doc/データモデル.md` §8-③準拠）。帯は §4.3（コモン10〜30 / 標準50〜150 / レア300〜800）に一致。
- スロット別: 頭＝王冠(レア600)/シルクハット(標準120)/キャップ(コモン20)/麦わら帽(コモン20)、顔＝サングラス(標準90)/メガネ(コモン15)/マスク(コモン15)、体＝アーマー(レア700)/スーツ(標準150)/ロングコート(標準120)/道着(コモン30)、手持ち＝剣(レア500)/魔法の杖(標準120)/大槌(標準90)/本(コモン25)、背景＝古城(レア500)/星空(レア400)/夕焼けの海(標準100)/森(コモン25)。
- `items.part_ref` は **VRM アセット制作時に付与**（現状 NULL 許容）。アセット未整備の間はビューアは 2D 見立て（§9.3 フォールバック）で先行する＝ラインナップ確定と 3D アセット制作を分離。

### 9.2 ベースアバター（男女2体）/ VRM / スキニング方式（決定）

- **ベースアバター＝男女 2 体を用意**（`male`／`female`）。R3F の `<Canvas>` 内で選択中のベース VRM を描画（three-vrm）。氏名・Lv は §4.1。**動物キャラ等の追加ベースは将来拡張**（§9.6）。
  - **ベース選択の UI**＝アバタービューア（§4.1・左パネル）に**ベース切替（男 / 女）**を置き、切替は即時プレビュー反映。装備は付けたまま（同一 humanoid リグ前提・下記）。
  - **選択の保存**＝会社 DB の `users` に**ベース種別を保持**（`avatar_base`＝`male`／`female`、将来 `animal_*`）。初期値は `male`（調整可）。※本項は**データモデル追記が必要**＝[`doc/データモデル.md`](../../データモデル.md) §5.3（users）へ `avatar_base` 列を追加する（実装スライス時に migration。会社 DB 単独列＝管理 DB からのミラー対象外）。
- **装備＝スロット別パーツの実行時アタッチ（差し替え方式）**。ボーン対応: `head`→頭ボーン / `face`→頭部前面 / `body`→胸〜腰（体はベースメッシュ相当を差し替え） / `hand`→右手ボーン。**`background` は 3D メッシュにせず 2D レイヤ**（canvas 背景・性能優先）。各スロット 1 点（§2）は既存 DB 制約（`user_items` 部分ユニーク・§5.26）で担保済み＝描画は装備状態を反映するのみ。
- **男女共通で装備を使い回す制作前提（重要）**＝2 体は**同一 humanoid リグ（同一ボーン構成・VRM humanoid 規格）**で作る。これにより装備パーツ（`part_ref`）は男女どちらのベースにもそのままアタッチでき、**装備アセットを性別ごとに二重制作しない**（DRY）。体格差でクリップ（貫通）する装備のみ、必要に応じ性別バリアントを追加（例外・初期は共通で対応）。
- **`items.part_ref` の規約**＝パーツアセットの参照キー（例 `parts/head/crown.glb`、または単一 VRM 内のメッシュ名）。1 レイヤ 1 マテリアル方針（§3）と整合。差し替え方式によりラインナップ追加はアセット＋シード行の追加のみで済む（DRY）。

### 9.3 フォールバック / 対応環境 / 性能（決定）

- **対応環境**＝WebGL2 対応モダンブラウザ（社内 PC・Chrome/Edge 最新）。要件定義 第7節「WebGL 前提」を踏襲。
- **Progressive enhancement**＝WebGL 利用可時のみ 3D を載せ、**非対応/初期化失敗時は現行の 2D フォールバック（マスコット画像＋装備アイコン重ね）へ自動デグレード**。フォールバックの正＝現行実装（`impl/frontend/src/features/avatar/components/AvatarView.tsx`）。
- **性能（初期値）**＝初回ロード ≤ 3s（アセット遅延ロード＋スケルトン/スピナー表示）、描画 30fps 目標。`prefers-reduced-motion` 時は自動回転オフ・手動操作のみ。

### 9.4 ビューア操作（決定・初期値）

- **回転＝ドラッグで水平回転 ON**（3D の主目的＝見た目カスタマイズの確認）。**ズーム/パン＝MVP は固定**（将来 §9.6）。**表情/ポーズ＝MVP なし**。
- 装備変更は**即時反映**（プレビュー同期・§4.1 不変）。

### 9.5 未所有プレビュー（試着）＝MVP 非対応（決定）

- 未所有装備の**試着は MVP では行わない**（未所有はショップ導線のまま・§5）。理由＝購入誤認の UX リスク＋所有はサーバ権威で検証するため試着に実利が薄い。将来 SC-30 側の試着プレビューとして温存（§9.6）。

### 9.6 将来拡張（優先度低・温存）

- **動物キャラ等の追加ベースアバター**（§9.2 の男女 2 体に続く第2弾）／試着プレビュー（SC-30/SC-31）／ズーム・パン／表情・ポーズ／複数コーデの**プリセット保存**（コーデ切替）／装備の追加ラインナップ。いずれも MVP 対象外。
