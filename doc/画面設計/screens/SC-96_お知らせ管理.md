# SC-96 お知らせ管理（作成/編集/公開・管理者）（画面設計 / 機能詳細）

> 対象デザイン標準＝[デザイン標準](../デザイン標準.md)（DataTable §4.5＋RowMenu・確認モーダル・入力検証 §4.7・モーダル §4.1）。閲覧側は [SC-95](SC-95_お知らせ.md)。リッチテキスト部品は **SC-50（[情報インプット](SC-50_情報インプット.md)）の資産を中立化して共用**。

- ステータス: **実装済み（FR-49 Phase2・2026-10-05）**＝ルート `app/(app)/admin/announcements/`／`features/announcements/AnnouncementAdminView`＋`api.ts`／backend 管理EP（`GET/POST/PATCH/DELETE /admin/announcements`）実結線。ナビ「お知らせ管理」（`AppNav`・管理者のみ）。テスト＝[U-TC-101〜109](../../テスト/U_お知らせ.md)。
- **踏襲元（新規UIを作らない）**＝管理系 DataTable＋**RowMenu（⋮）トグル**（クエスト等と同型）＋作成/編集モーダル（`.checkbox`・`.row-2`・確認ダイアログ）。

## 1. 概要・目的

- 管理者が全社お知らせを**作成 → 下書き/公開 → ピン留め → 掲載期間設定 → 編集/削除**まで一元管理する。閲覧側（[SC-95](SC-95_お知らせ.md)・ダッシュボード Zone D）は本画面の成果を読むだけ。
- **ピン留めの操作はここに集約**（一覧 RowMenu の即時トグル＋作成/編集モーダルのチェックボックス）。**なぜ**＝ダッシュボード/一覧（閲覧）に操作を置くと一般ユーザーに誤操作余地が生まれるため、権限境界を管理画面に閉じる（設計 §4.5）。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| アクセス可能者 | **`company_account_admin` / `system_admin`**（一般ユーザーは不可）。**サーバーで強制**＝管理EPは管理者ロールを 403 で弾く（UI非表示に依存しない・[API U.0](../../API設計/U_お知らせ.md)・コーディング規約 §1.6）。 |
| 表示 | 全件（`draft`/`archived` も含む・`pinned`→`published_at`/`created_at` 降順）＋既読数（`read_count`）。 |
| 変更 | 作成/編集/ピン留めトグル/削除＝管理者のみ。`body_html` は**保存時サーバーでサニタイズ**（受信値を信用しない）。 |

## 3. レイアウト構成

- 冒頭＝バックリンク「← ダッシュボードへ戻る」＋ページヘッダー（見出し「📢 お知らせ管理」＋主操作「＋ お知らせを作成」）＋リード文。
- **本体＝標準 DataTable**（`storageKey="sc96-announcements"`）＝カード/リスト切替（既定＝リスト）・検索（タイトル）・列フィルタ/ソート・ページャ（12/24/48）・CSV。
- 作成/編集＝**モーダル**（`Modal` size=lg・§6）。

### 3.1 一覧の列（DataTable）

| 列 | 内容 | ソート/フィルタ |
| --- | --- | --- |
| タイトル | `idea-title`（クリック＝編集を開く） | ソート可・テキストフィルタ |
| 状態 | **下書き**（`badge-muted`）/**公開中**（`badge-success`）/**アーカイブ**（`badge-muted`） | ソート可・enum フィルタ |
| ピン | `📌`／`—` | ソート可・enum フィルタ |
| 公開日 | `published_at`（日付・未設定は「—」） | ソート可 |
| 掲載期間 | `starts_at` 〜 `ends_at`（各日付・未設定は「—」） | ソート可（開始日） |
| 既読 | `read_count`（数値右寄せ） | ソート可 |
| （操作） | **RowMenu（⋮）**＝📌ピン留めトグル／編集／削除（danger） | — |

- 行クリック＝**編集モーダルを開く**（RowMenu の「編集」と同じ）。
- カード＝タイトル＋状態バッジ＋「📌 ピン ・ 公開日 ・ 掲載期間 ・ 既読数」メタ。

## 4. 一覧アクション（RowMenu）

| 操作 | 結果 |
| --- | --- |
| 📌 ピン留めする／解除 | **即時トグル**＝`PATCH /admin/announcements/{id}` `{pinned}` → 成功トースト → 一覧リロード。**なぜ即時**＝ピンは1クリックの軽い操作で、モーダルを挟むと重い（RowMenu トグルの既存標準・デザイン標準 §4.5）。 |
| 編集 | 作成/編集モーダル（§6）を編集モードで開く |
| 削除 | **確認ダイアログ（danger）**「『…』を削除しますか？ 一覧・ダッシュボードから見えなくなります。」→ `DELETE /admin/announcements/{id}`（**論理削除**＝`deleted_at`/`deleted_by_id`）→ 成功トースト → リロード |

## 5. アクション・遷移（画面全体）

- ＋ お知らせを作成 → 作成モーダル（§6・新規）。
- 行クリック/RowMenu 編集 → 編集モーダル（§6・本文は詳細取得でプリフィル）。
- RowMenu ピン/削除 → §4。
- ダッシュボードへ戻る（バックリンク）。

## 6. 作成/編集モーダル（§4.1 モーダル）

- **`Modal`（size=lg）**。ヘッダー＝「お知らせを作成」/「お知らせを編集」。
- **入力項目**:
  1. **タイトル**（必須・`Field` エラー＝未入力で「タイトルを入力してください。」）。
  2. **本文**（`RichTextEditor`＝見出し/強調/箇条書き/リンク。保存時サーバーでサニタイズ）。
  3. **状態**（`select`＝下書き（非公開）/公開する／**アーカイブは編集時のみ**選択可）。
  4. **ピン留め**（`.checkbox`「📌 上部に固定する」）。
  5. **掲載開始日 / 掲載終了日**（任意・`type=date`→保存時に `T00:00:00Z` で ISO 化）。
- **フッター**＝「キャンセル」（左）＋「作成する」/「保存する」（primary・`loading`）。
- **保存時の挙動**:
  - 作成＝`POST /admin/announcements`（`status=published` 指定時にサーバーで `published_at=now`。作成時に `archived` は選べないため `draft` に丸める）。
  - 編集＝`PATCH /admin/announcements/{id}`（部分更新。`draft→published` で `published_at` 設定）。
  - 失敗時はトースト（「作成/更新に失敗しました（権限が必要な場合があります）」）。
- **編集時の本文プリフィル**＝一覧 DTO に `body_html` が無いため**詳細（`GET /announcements/{id}`）を取得**してセット。**注記**＝詳細 EP は表示対象（published・期間内）のみ返すため、**draft/期間外のお知らせは本文を取得できず空で開く**（既知の制約・§8 残TBD）。

## 7. データ・API（正＝[API設計 U](../../API設計/U_お知らせ.md) U.2）

- 一覧＝`GET /admin/announcements`（全件・`read_count`・`can_manage`）。
- 作成＝`POST /admin/announcements`（`{title,body_html,status,pinned,starts_at?,ends_at?}`・body_html はサーバー sanitize・`body_text` 派生）。
- 編集＝`PATCH /admin/announcements/{id}`（部分更新・ピン留めトグル含む）。
- 削除＝`DELETE /admin/announcements/{id}`（論理・204）。
- `body_text`/`published_at`/`created_by_id`/監査列＝**サーバー生成**（クライアントから受け取らない＝マスアサインメント防止・[API U.4](../../API設計/U_お知らせ.md)）。
