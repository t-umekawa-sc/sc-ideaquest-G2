# SC-62 コンセプト評価（画面設計 / 機能詳細）

> 画面遷移図: [画面遷移図](../画面遷移図.md) ／ 要件: [要件定義 README](../../要件定義/README.md)（FR-42 コンセプト創造・検証）／ API: [API設計 P_コンセプト](../../API設計/P_コンセプト.md)（P.5 評価）／ データモデル: [データモデル](../../データモデル.md) §5.43（`concept_evaluations`）・§5.44（`concept_evaluation_scores`）
> 設計の背景: [設計ドラフト コンセプト機能_ISO56001_再設計](../../設計ドラフト/コンセプト機能_ISO56001_再設計.md)（§3.6 評価観点＝中核5＋補助3）
> 対象デザイン標準: [デザイン標準](../デザイン標準.md)（入力モーダル標準・§4.7 入力検証／**ガイダンス標準 §4.13＝`.screen-purpose` ⓘ＋短ラベル・ホバーでフローティング展開・クリックで全文**）
> 対称元: [SC-25 評価画面](SC-25_評価画面.md)（アイデア評価＝5観点＋総評＋公開範囲）／評価結果の表示は [SC-61 コンセプト詳細](SC-61_コンセプト詳細.md) §4.6

- ステータス: ドラフト（機能詳細）

## 1. 概要・目的

- **1 つのコンセプトを評価するモーダル**（評価者権限）。**中核5観点＋補助3観点**を採点し、**総評＋評価者の Go/Pivot/Kill 推奨**を付けて確定する（ISO 56001 §8.3.3 準拠・[設計ドラフト コンセプト機能_ISO56001_再設計](../../設計ドラフト/コンセプト機能_ISO56001_再設計.md) §3.6）。
- **N 個の候補コンセプトが競合**するため、評価は**候補比較・選定の道具**も兼ねる（推奨分布が owner の選定/総合判定を補助・SC-61 §4.6/§4.7）。
- **SC-61 コンセプト詳細の「評価する」から開くモーダル差し込み**。確定で SC-61 の評価結果（§4.6）に反映。
- **観点が ISO 用語で難解**なため、**各観点に ⓘ ガイダンス**（[デザイン標準](../デザイン標準.md) §4.13）＝「何を見るか」をホバー展開＋クリックで全文。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| 評価可能者 | **評価者権限**（当該クエスト・門番 P.0）。`active` のコンセプトが対象 |
| 1人1評価（upsert） | 自分の評価は1件（下書き→確定）。再評価は同レコード更新（`PUT /concepts/{id}/evaluation`・P.5） |
| 公開範囲 | 評価者が確定時に指定（party／limited・F と同 enum・[SC-25 評価画面](SC-25_評価画面.md) §4.3 と同挙動） |
| 要再評価（stale） | リンク前提が反証に転じると評価が stale（SC-61 §4.4/P.7）。評価者は再評価で織り込む |

## 3. レイアウト構成（決定）

- **入力モーダル標準**（`.modal.sectioned`・`.modal--lg`）。上部に**評価対象コンセプトの参照ブロック**（名前＋由来アイデア＋要点／囲まず薄い仕切り線・[デザイン標準](../デザイン標準.md) ダイアログ内コンテンツ標準）。参照折り畳みは `.disclosure--ref`。
- **中核5＋補助3の採点**（各観点＝スコア＋コメント・**観点ラベル横に ⓘ ガイダンス**）。**補助3は折り畳み（任意）**（`.disclosure`）。
- **総評（全体コメント・確定時必須）** ＋ **評価者の Go/Pivot/Kill 推奨（確定時必須）**。
- **集計プレビュー**（自分のスコアの平均・確定後は全体集計は SC-61 §4.6 で見る）。
- **公開範囲**（party／limited）。
- **フッター順**＝閉じる（左）→ 下書き保存 →（主）評価を確定。

## 4. 表示・入力項目

### 4.1 観点の採点（中核5＋補助3・[設計ドラフト コンセプト機能_ISO56001_再設計](../../設計ドラフト/コンセプト機能_ISO56001_再設計.md) §3.6・`concept_eval_aspect`）
| 区分 | 観点 | 必須 | 見るもの（ⓘ ガイダンス全文の骨子） |
| --- | --- | --- | --- |
| 中核 | 望ましさ `desirability` | **必須** | 狙う価値が明確・対象が本当に欲しがるか（検証の裏付け込み） |
| 中核 | 実現可能性 `feasibility` | **必須** | 形態・必要能力が現実的か |
| 中核 | 採算・事業性 `viability` | **必須** | コスト/収益モデル/ROI が筋か（価値実現モデル） |
| 中核 | 前提検証の強さ `assumption_strength` | **必須** | 主要な前提が"証拠で"検証されているか（言い張りを弾く・ISO③ 固有ゲート） |
| 中核 | 差別化 `differentiation` | **必須** | 競合に対する位置づけ |
| 補助 | 新規性 `novelty` | 任意 | 既存に対する新しさ・独自性（ISO §8.3.3） |
| 補助 | 持続可能性 `sustainability` | 任意 | 環境・社会・事業継続で無理がないか（ISO §8.3.3） |
| 補助 | 知的財産 `ip` | 任意 | 知財で保護できるか／他者の知財を侵害しないか（ISO §8.3.3・§8.3.5） |

- 各観点＝**スコア（1..5）＋任意コメント**（`concept_evaluation_scores`）。**中核5は 1..5 必須**、補助3は任意（未採点可）。スコアは色のみに依存しない（数値併記）。
- **各観点ラベル横に ⓘ ガイダンス**（[デザイン標準](../デザイン標準.md) §4.13）＝上表「見るもの」を短ラベル＋全文で提示（ISO 用語の理解補助）。

### 4.2 総評・推奨
- **総評（`overall_comment`）＝確定時必須**（[SC-25 評価画面](SC-25_評価画面.md) §4.1b と同型）。
- **評価者の Go/Pivot/Kill 推奨（`recommendation`＝`concept_decision`）＝確定時必須**。**"Go/Pivot/Kill" は当社ラベル**（[設計ドラフト コンセプト機能_ISO56001_再設計](../../設計ドラフト/コンセプト機能_ISO56001_再設計.md) §3.6）。**コンセプト自身の総合判定（owner・SC-61 §4.7）とは別**＝評価者の推奨は集計 `recommendations` で分布可視化。

### 4.3 集計プレビュー・公開範囲
- **集計プレビュー**＝自分の中核5平均（/5.0）。全体集計・推奨分布は確定後 **SC-61 §4.6** で見る。
- **公開範囲**＝party（既定・パーティー全員）／limited（投稿者＋評価者＋所有者/管理のみ・範囲外は完全非表示＝分母から除外・F と同挙動）。

## 5. アクション・遷移

| トリガー | 条件 | 遷移/結果 |
| --- | --- | --- |
| 閉じる/キャンセル | — | モーダルを閉じる（SC-61 へ戻る） |
| 観点 ⓘ をクリック | 全員 | 全文ガイダンスダイアログ（観点の意味・[デザイン標準](../デザイン標準.md) §4.13） |
| 下書き保存 | 評価者 | `PUT /concepts/{id}/evaluation`（`status=draft`）＝部分入力可 |
| 評価を確定 | 評価者 | `PUT /concepts/{id}/evaluation`（`status=submitted`）。**中核5(1..5)＋総評＋推奨 必須をサーバー検証**（P.5）→ SC-61 §4.6 に反映 |
| 公開範囲を変更 | 評価者 | party/limited を指定（確定時） |

## 6. 状態・バリエーション

| 状態 | 表示 |
| --- | --- |
| 新規 | 未採点・下書き可 |
| 下書きあり | 既存の自分の評価をプリフィル（`GET .../evaluation/me`） |
| 確定検証エラー | 中核5未採点・総評空・推奨未選択をフィールド直下に表示（§4.7） |
| 要再評価（stale） | 上部に「前提の反証により要再評価」バナー＋対象前提へのリンク（SC-61 §4.4） |
| 補助3 | 折り畳み（任意・未採点で確定可） |
| reduce-motion | ⓘ 展開の流れは静止（[デザイン標準](../デザイン標準.md) §4.9/§4.13） |

## 7. データ・API（想定）

- **GET `/concepts/{id}/evaluation/me`**（P.5）: 自分の評価/下書き（`status/scores/comments/overall_comment/recommendation/visibility`）。
- **PUT `/concepts/{id}/evaluation`**（P.5）: upsert（下書き/確定）。**`submitted` で中核5＋総評＋推奨 必須をサーバー検証**。
- 全体集計・推奨分布の表示は **GET `/concepts/{id}/evaluation`**（visibility 適用・SC-61 §4.6）。
- 認可（評価者権限・門番）・visibility はサーバー側で最終制御（P.0/P.8）。

## 8. アクセシビリティ / 表示配慮

- スコア・推奨は**色のみに依存しない**（数値＋テキスト＋アイコン）。スコアバーは数値併記。
- **ガイダンス ⓘ**（[デザイン標準](../デザイン標準.md) §4.13）＝ボタン扱い＋`aria-haspopup="dialog"`＋`aria-label`。展開の流れは reduce-motion（OS／`accounts.reduce_motion`・§4.9）で静止。フォーカスリングは `outline` でなくベース＋展開部の枠線を青で一続きに。
- モーダルはフォーカストラップ・`aria-modal`・`Esc`/バックドロップで閉じる（モーダル標準）。
