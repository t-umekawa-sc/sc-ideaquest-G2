# SC-93 会社アカウント管理（会社アカウント管理者）（画面設計 / 機能詳細）

> 画面遷移図: `doc/画面設計/画面遷移図.md` ／ モック: `doc/画面設計/mocks/SC-93_会社アカウント管理.html` ／ 要件: `doc/要件定義/README.md`（FR-17・第2/6節・データモデル）

## 1. 概要・目的

- **会社アカウント管理者（`system_role=company_account_admin`）** が、**自社（セッション会社）の全アカウント**の**ライフサイクル**（発行 / 編集 / 無効化⇄再有効化 / パスワード再設定）を管理する画面。
- **職務分離（SoD・2026-08-01・データモデル §8-⑯／B.2.1）** の一方の担い手。もう一方の **QG管理者（SC-90）＝参加選択専任**（メンバーシップのみ）と対をなす。
- パスは**セッション会社固定**（`/admin/accounts`・`company_id` を受けない＝クロステナント不可）。**会社設定・会社プロフィール・プロビジョニング・システムロール付与は持たない**（＝システム管理者 SC-92 の領分）。
- 導線: ダッシュボード（SC-01）のロール条件付き管理導線（`company_account_admin` のみ表示）。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| アクセス可能者 | **会社アカウント管理者＝`session.system_role == company_account_admin`**（`system_admin` も上位互換で可＝ただし運営は通常 SC-92 を使う） |
| 対象 | **自社（`session.company_id`）のアカウントのみ**（会社選択・`?company` は無い＝クロステナント不可） |
| できること | 自社アカウントの**発行 / 編集（氏名・ログインID・メール・所属グループ）/ 無効化⇄再有効化 / パスワード再設定**。所属は `quest_group_members` の **member / admin（QG管理者）を per-group 指定**で付与（差分適用・2026-08-02 改定） |
| できないこと | **システムロールの付与/変更**（`company_account_admin`/`system_admin` 付与・降格）・**会社設定 / 会社プロフィール / 会社作成・プロビジョニング**（＝システム管理者 SC-92）。**system_admin アカウントの無効化/編集は不可**（`last_system_admin` 迂回防止・§8-⑯） |
| 委譲運用 | system_admin が会社アカウント管理者を用意 → **会社アカウント管理者が QG管理者（per-group `admin`）を任命** → QG管理者（SC-90）がメンバー指定、という委譲を想定（B.2.1/B.7.2・2026-08-02） |
| 上位互換 | 本画面の全操作は **SC-92（システム管理者）が全会社範囲で実施可能** |

## 3. レイアウト構成（決定・業務層）

- **共通ヘッダー**（会社アカウント管理者バッジ＋ベル＋アバターメニュー）。
- **自社コンテキスト行**: 自社名（固定表示）＋「自社のアカウントを管理しています」の注記（会社選択は無い＝誤操作防止）。
- **ツールバー（一覧標準 `.list-toolbar`）**: 検索（氏名/ログインID/メール）＋状態フィルタ（有効/無効）＋**「＋アカウント発行」**。
- **アカウント一覧テーブル（`.table`）**: 氏名 / ログインID / メールアドレス / システムロール / 所属クエストグループ / 状態 / 操作。
- **発行/編集モーダル**（モーダル標準・所属は member/admin セグメント付きの行形式エディタ）。

## 4. 表示・入力項目

### 4.1 一覧テーブル
- **氏名 / ログインID / メールアドレス（**未確認/確認済みバッジ**を併記・ADR-0009）/ システムロール（読み取り専用バッジ）/ 所属クエストグループ（各グループのロールを表示）/ 状態（有効/無効）/ 操作**。※ログインIDとメールは別項目。メール確認バッジの源泉＝`email_verified`（`GET /admin/accounts` の各行）。
- 操作（⋯ RowMenu）＝**編集 / 複製 / 確認メールを送信 / パスワード再設定 / 無効化（⇄再有効化）**。ただし**対象が `system_admin` の行は操作不可**（読み取りのみ・「システム管理者は SC-92 で管理」を表示）＝会社アカウント管理者は system_admin を編集/無効化できない（§8-⑯）。
  - **複製**＝発行ダイアログを追加モードで開き表示名を引き継ぐ（デザイン標準 §4.5・ログインID/メールは一意キーで除外）。
  - **確認メールを送信**（opt-in・ADR-0009）＝現メール宛に確認リンクを送付（`POST /admin/accounts/{id}/email-verification`・202→成功トースト「確認メールを送信しました」）。本人がリンクを開くと確認済みになる。**確認済みでも再送可**（アドレス変更後の再確認）。編集でメールを変えると自動で未確認へ戻る。
- 所属グループの `admin`（QG管理者）バッジを表示。**本画面で付与/剥奪も可**（編集モーダルの per-group セグメント・2026-08-02 改定）。

### 4.2 発行/編集モーダル
- **氏名（必須）/ ログインID（必須・ログイン識別子）/ メールアドレス（必須・OTP/初回設定リンク送付先）/ 所属クエストグループ（行形式エディタ・member/admin セグメント）**。※ログインIDとメールは別項目。
- **システムロール欄は無い**＝本画面が発行/編集できるのは `system_role=general` のアカウントのみ（`system_role` の付与は system_admin=SC-92）。※per-group の `admin`（QG管理者）は `system_role` ではなく所属側なので本画面で指定可。
- **所属クエストグループ**＝選択済みグループを 1 行ずつ表示（各行に**メンバー/管理者セグメント**＋削除✕）、末尾の「＋グループを追加」プルダウン（自社の未選択グループのみ・自由入力なし）から行を追加。役割の既定は member。**「管理者」＝QG管理者（per-group `admin`）の任命**（2026-08-02 改定＝委譲運用のため会社アカウント管理者に解禁）。保存で `memberships:[{group_id, role: member|admin}]` 相当を更新。編集時は既存の所属・ロールを反映。
- 発行時の注記＝初回ログイン時にパスワード設定（`otp_challenges` purpose=password_setup・72h・メールリンク）。

## 5. アクション・遷移

| トリガー | 条件 | 遷移/結果 |
| --- | --- | --- |
| ＋アカウント発行 | — | モーダル→**自社に** Account 作成（管理DB・`system_role=general`）→ outbox で会社DB に User ミラー＋所属（member/admin）割当。初回ログインでパスワード設定 |
| 編集 | 対象が general | 氏名/ログインID/メール/所属グループ（member/admin＝QG管理者任命）を更新（identity は会社内一意） |
| パスワード再設定 | 対象が general | 初回パスワード設定フローに戻す（`otp_challenges` password_setup リンク再送・72h・旧リンク失効） |
| 無効化（論理削除）/ 再有効化 | 対象が general | `accounts.status` を disabled⇄active。無効化＝**全アクティブセッション破棄＋信頼端末失効**（A.9-③）。入力（アイデア/投票/評価/コメント）は保持 |
| **行/カードクリック** | 対象が general | **編集モーダルを開く**（[デザイン標準.md](../デザイン標準.md) §4.5 ⑪＝複数操作ありの既定＝編集）。⋯メニューの各操作は従来どおり |
| 行/カードクリック | 対象が system_admin | **無反応**（クリック不可・指カーソルも出さない。操作は SC-92） |
| system_admin 行の操作 | — | **不可**（読み取りのみ・SC-92 へ誘導） |
| 検索 / 状態フィルタ | — | 自社アカウント一覧を更新 |

## 6. データ・API（正＝`B_会社・アカウント・所属.md` B.2.1）

- **GET `/api/v1/admin/accounts`**: 自社アカウント一覧（氏名/`login_id`/`email`/`system_role`/`status`＋所属＋グループ内ロール・`page`/`per_page`）。
- **POST `/api/v1/admin/accounts`** `{display_name, login_id, email, memberships:[{group_id, role:member|admin}]}`: 発行（B.5 発行フロー・outbox 相乗）。`system_role` は指定不可＝サーバーで `general` 固定。**`role=admin`（QG管理者任命）は自社スコープで可**（2026-08-02 改定）。
- **PATCH `/api/v1/admin/accounts/{account_id}`**: 氏名/ログインID/メール/所属（member/admin）の差分更新。`system_role` 変更は不可（403）。identity は会社内一意（重複=409）。
- **POST `/api/v1/admin/accounts/{account_id}/disable`** / **`/enable`**: 無効化⇄再有効化（disable は全セッション破棄＋信頼端末失効）。**対象が system_admin なら拒否**（422/403）。
- **POST `/api/v1/admin/accounts/{account_id}/password-reset`**: 初回/再設定 PW リンク再送（A.7）。
- 権限は**サーバーで判定**＝`session.system_role == company_account_admin`（or system_admin）かつ**セッション会社のアカウントのみ**。**会社設定（`/settings`）・会社作成（B.1）・`system_role` 付与は本画面/経路からは呼べない**（per-group `admin` 任命は可）。操作は `system_audit_logs` に記録（B.6・操作者=会社アカウント管理者）。

## 7. アクセシビリティ / 表示配慮

- 会社選択が無い＝**常に自社**であることを注記で明示（誤操作防止）。
- 状態は色バッジ＋テキスト（有効/無効）。無効行は淡色＋「再有効化」明示。
- 破壊的でない**論理削除**（無効化）＋確認ダイアログで誤操作を防止。
- system_admin 行は操作不可であることをテキストで明示（グレーアウト＋理由）。

## 9. 残TBD（この画面）

- **職務分離（SoD）＝ 決定（2026-08-01）**: アカウントのライフサイクル管理（会社アカウント管理者＝本画面）と参加管理（QG管理者＝SC-90）を分離（データモデル §8-⑯・B.2.1/B.4）。**なぜ**＝会社DB内アカウント参照の緩和（B.7.2）と両立させても権限昇格が起きないよう、破壊系を会社スコープの本ロールに集約し、QG管理者からは撤廃するため。
- **画面の新設 ＝ 決定（2026-08-02・ユーザー選択）**: 会社アカウント管理者の画面は **SC-92 への委譲ではなく新規 SC-93 として作成**。理由＝スコープ（自社固定・ロール付与なし・会社設定なし）が明確で、system_admin の全社クロステナント前提（`?company`・文脈バナー）と相容れず、委譲すると出し分けが複雑化するため。
- **CSV 一括発行/無効化** は MVP 見送り（SC-90/B.7）。
- **監査ログ表示** は後回し（記録は `system_audit_logs`・B.6／表示 UI は MVP スコープ外）。
- **発行フロー詳細 ＝ 決定（2026-07-20）**: 初回パスワード設定はメールリンク方式・72h（`otp_challenges` purpose=password_setup・単回）。dev=MailHog / prod=SMTP。
