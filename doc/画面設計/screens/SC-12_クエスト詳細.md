# SC-12 クエスト詳細（画面設計 / 機能詳細）

> 画面遷移図: `doc/画面設計/画面遷移図.md` ／ モック: `doc/画面設計/mocks/SC-12_クエスト詳細.html` ／ 要件: `doc/要件定義/README.md`（FR-20〜27・権限モデル）
> 対象デザイン標準: `doc/画面設計/デザイン標準.md`（業務層＝クリーン。登録・編集はモーダル標準）

- 最終更新: 2026-07-16
- ステータス: ドラフト（機能詳細）

## 1. 概要・目的

- 1つのクエストの詳細画面。**クエスト情報＋アイデア一覧（内包）＋パーティー/権限**を集約し、アイデアの投稿・議論・評価の起点になる。
- **アイデア一覧は独立画面にせず本画面のタブに内包**（旧 SC-20 廃止）。
- **登録・編集はモーダル**（UI標準）：アイデア追加＝SC-21、クエスト編集/パーティー・権限編集＝SC-11 をモーダルで開く。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| アクセス可能者 | **C.0 門番 `can_access_quest`**＝作成者（別格・常に可）／非作成者は**有効パーティー員 かつ（参加部署 0 件なら条件なし／1 件以上ならいずれかに現所属）**（FR-38 再設計）。**アクセスの都度、現所属で再判定**（異動で全参加部署を外れたら参照不可＝失効）。非該当は 404 |
| 表示 | 上記アクセス条件を満たすメンバーが閲覧可。**参加部署外になったパーティー員（`in_scope=false`）はパーティータブのメンバー行を淡色＋「部署外・失効中」バッジで明示**（作成者は別格で常に有効・SC-11 §4.2 と共通） |
| アクション権限 | アイデア追加＝**アイデア作成権限**／クエスト編集・パーティー/権限編集＝**所有者 or クエスト管理権限**／評価＝評価者権限（SC-25）。権限の無いアクションボタンは非表示 |
| 管理者閲覧 | 管理機能の範囲での閲覧は別（本画面はパーティー向け） |

## 3. レイアウト構成（決定）

- **戻る導線**（→SC-10 クエスト一覧）
- **上部2カラム**: 左＝**クエストヘッダー（カード）**（カテゴリー・ステータス・件名・目的/テーマ・メタ＋アクション）、右＝**クエスト内 週間ランキング**（ゲーム層 `.pixel-panel .rank-panel`）。
- **上部: 関連情報ストリップ（🔗・FR-41・情報インプット連携）**: **新着の議論／活動の活発さ の下・クエストKPI／クエスト内ランキング の上**に**全幅の横スクロール棚**で本クエストに紐づいた情報を**常時表示**（§4.1d）。⚠反証を先頭固定。
- **タブ切替**（決定）: `[💡 アイデア] [👥 パーティー] [🔍 全文検索] [🏁 結果] [🧩 コンセプト] [📋 概要]`（各タブ左にアイコン）。既定＝**アイデア**タブ。**「🏁 結果」は常時表示**＝完了前は「暫定」チップを付す（FR-39・§4.5）。**「🧩 コンセプト」＝ISO ②③段の候補コンセプト一覧＋検証プールへの導線**（FR-42・§4.6／🏁結果＝アイデア選別の申し送りを受けて次段へ）。
- **アイデア一覧＝テーブル（行リスト）**（決定）。

> レイアウトは「**上部2カラム（左クエスト情報＋右クエスト内週間ランキング）＋タブ（アイデア/パーティー/全文検索/概要）／アイデア一覧はテーブル**」で確定（2026-07-16）。狭幅（〜860px）では2カラムを縦積み。

## 4. 表示項目

### 4.1 クエストヘッダー
| 項目 | 種別 | 補足 |
| --- | --- | --- |
| クエストアイコン | `.quest-icon lg` | カスタム画像 or **未設定時は件名頭文字＋所有者アバターのフォールバック**。設定はクエスト編集モーダル（SC-11） |
| カテゴリー | `.badge badge-muted` | |
| ステータス | `.badge` | 募集中/進行中/評価中/選定/完了（下書きは本画面に出ない＝作成者のみ） |
| 件名 | 見出し | |
| 目的・テーマ | テキスト | |
| メタ | テキスト | 締切（近接は警告色）/ 👥人数 / 💡アイデア数 / 所有者 / **参加部署（0..N・すべて同格・全部署を表示・0 件なら「全社」・FR-38 再設計）** |

### 4.1b クエスト内 週間ランキング（右カラム・ゲーム層）
| 項目 | 種別 | 補足 |
| --- | --- | --- |
| 見出し / 期間 | テキスト | 「★ クエスト内ランキング ★」＋「このクエストの活動で獲得（今週）」 |
| 順位（1〜3位） | メダル | 🥇🥈🥉。自分が3位内なら行ハイライト＋（あなた） |
| アバター / 氏名 | `.avatar sm` ＋テキスト | パーティーメンバー |
| スコア | 数値 | **このクエストの活動で得た XP＋コインの合算**（内訳 EXP/◆ 併記） |

> **スコア定義**: `スコア = 今週このクエストの活動で得た XP ＋ 得たコイン`。全社の週間ランキング（SC-01）と同じ合算式だが、**集計対象を当該クエストの活動に限定**（Activity の `quest_id` で絞り込み）。週次リセット。共通コンポーネント `.rank-panel`（shared.css）を使用。

### 4.1c クエスト内アクティビティ（右カラム・時系列・FR-36）
- **このクエストの参加メンバーの活動**を新しい順で表示（`Activity.quest_id = 当該クエスト`）。各行＝アクター（アバター＋氏名）＋イベント（例「〈アイデア名〉を投稿」「実績〈…〉を獲得」「Lv 上昇」）＋相対時刻。「もっと見る」でカーソル追加読込。ランキング（4.1b）が「今週の合算スコア」なのに対し、本節は「起きた出来事の時系列」で相補的。
- **源泉＝元帳 `Activity` の絞り込み**（データモデル §8-㉑・API設計 G.5.1 `GET /quests/{id}/activities`）。**成果系のみ公開**（投稿/選定/実績/レベルアップ・初期値）＝私的行動（購入/魔法解放/ログイン）と投票/評価（匿名性）は出さない。
- **門番**＝当該クエストのパーティー所属（クエスト閲覧権・C.0）。**依存**＝C（参加メンバー判定）／リンク付き表示は D/E（ref 解決）。C 実装の周回で接続（それまでは demo）。

### 4.1d 上部: 関連情報ストリップ（🔗・情報インプット連携・FR-41）
- **配置＝新着の議論／活動の活発さ の下・クエストKPI／クエスト内ランキング の上（全幅・目立たせる）**。本クエストに紐づいた情報（情報インプット＝外部情報の知識レイヤ・FR-41）を**横スクロール棚**（ユーザー操作＝自動送りしない・reduce-motion 安全・見逃し防止）で表示。データ＝**API `C.8b`＝`GET /quests/{quest_id}/related-info`**（`info_links` の `target_type='quests'`・一致度 `score` 降順・`rejected`/archived 除外）。
- **ヘッダー＝「🔗 関連情報 N件（⚠反証 K）」**（件数＋反証バッジで目立たせる）＋**「＋ 関連情報を追加」**（後述）＋**「⤢ 全画面で一覧」**（SC-13 発見カタログと同じ**最大化ダイアログ**を流用してモックのグリッド一覧）。
- **「＋ 関連情報を追加」＝成果物→情報の逆向きピッカー（双方向）**。既存情報を検索して選び（**`GET /info-items` を流用**＝タイトル/本文検索＋機会/脅威フィルタ）、**設定する種別**（関連/裏付け/反証）を選んで「選択を確定」で**このクエストに関連付け**（**`POST /info-links`**〔`target_type='quests'`・`created_by_id`＝関連付けた人〕を流用・**新規 EP 不要**）。ダイアログ体裁は情報側「対象を選ぶ」と統一（絞り込み→設定する種別→絞り込み結果の3セクション）。**追加は会社内 active 全員**（新規情報の登録は SC-50 へ）。
- **カード**＝タイトル＋**種別バッジ**（🔗関連／✅裏付け／⚠反証）＋**由来**（🤖 自動〔`origin=auto`・system〕／✋ **手動＝関連付けた人のユーザーアバター＋氏名**〔`created_by_id` 解決〕）＋**一致度**（`score`）＋出典（`source_url`）＋要約抜粋。**⚠反証は先頭固定＋赤帯**（隠れない）。**カードクリックで情報詳細（SC-52 モーダル）**（最大化一覧内は入れ子モーダルを避け SC-52 へ置換遷移）。
- **Phase 1＝表示＋追加（会社内 active 全員）**。種別変更/棄却は情報側（SC-50/52）でも可（会社内全員）。空表示（0件）あり＝「情報インプット（SC-50）から関連づけできます」。
- **Phase 2＝採否（disposition・管理権限者＝owner/quest_admin）**＝各リンクに **未処理／採用／不採用** の状態と処理メモを持つ（`info_links.disposition`・C.8b `PATCH .../related-info/{link_id}`）。
  - **ストリップ（既定）**＝未処理＋採用を表示・**不採用は非表示だが件数はヘッダーに表示**（例「不採用 M」）。
  - **「⤢ 全画面で一覧」**＝**未処理／採用／不採用**の3グループに分けて表示。**採用グループは情報＋処理メモ**を出す。
  - **採否操作**＝カードクリックで開く情報詳細（SC-52）を**成果物側コンテキスト**で開き、最下部の「この情報の扱い」で状態＋処理メモを保存（管理権限者のみ・SC-52 §参照）。
  - **ロック**＝採用/不採用済みのリンクは棄却/種別変更不可（`pending` に戻すと解除）。
  - **採用は「🏁 結果」タブ（§4.5）に集約表示**（クエスト＋配下アイデアの採用関連情報＋処理メモ）。
- アニメは **CSS のみ**（framer 不使用）・`prefers-reduced-motion` で自動スクロール挙動を無効化（メモリ／デザイン標準の reduce 方針）。見本＝`mocks/SC-12-22_関連情報パネル.html`。

### 4.2 タブ: アイデア（既定・テーブル）
- **一覧ツールバー（一覧の操作標準＝`デザイン標準.md §4.5`（DataTable）に準拠。実体＝`mocks/SC-12_クエスト詳細.html` の `DataTable.init`）**:
  - **検索**: 件名・投稿者のキーワード（横断検索）。
  - **フィルター**: 状態（すべて/未投票/投票済/自分の投稿/**下書き（自分）**）・評価（すべて/評価待ち/評価済）。将来は投稿者などを追加。
  - **並び替え**: 投票が多い順 / 新着順 / 評価が高い順 / コメントが多い順。
  - 件数表示・0件時の空表示は DataTable が下部フッター／`emptyText` で提供。
  - **実装ノート（2026-08-17・DataTable 移行）**: 上記は `§4.5` の DataTable で実現。**フィルターは項目別絞込**（評価・あなた〔状態〕を「⧩ 絞り込み」ダイアログで指定）、**並び替え**は列見出しクリック＋「↕ 並び替え」で。**「新着順」は投稿日列（既定非表示・列設定で表示可）**の降順で実現（可視列は下記6列のまま）。既定順＝投票が多い順。適用中の条件（検索・並び替え・絞込）は「適用中」チップ行に集約（`§4.5` 改定 2026-08-17）。
- テーブル列: **件名 / 投稿者（アバター＋氏名）/ 賛成・反対（▲n ▼n）/ 💬コメント数 / 評価（n/5 or 評価待ち）/ あなた（未投票・投票済・自分の投稿・**下書き**）**。
- **自分の下書きアイデアも一覧に表示**（決定・API `D.1`／`GET /quests/{id}/ideas` に本人の `draft` を含める）: 投稿者本人にのみ表示し **下書きバッジ**を付す。他パーティーメンバーには見えない。**行クリックは SC-21 編集モーダル**（公開して初めて投票/コメント対象＝下書き行は賛成/反対・コメント・評価は 0/空表示）。ダッシュボード（SC-01/ドメイン I）にも集約＝両導線。
- **公開済みの行クリックで SC-22 アイデア詳細**（本番は Intercept Route でモーダル差し込み、URL直/リロードはフルページ）。
- 投票の集計表示は会社の匿名化設定に従う（既定＝集計数）。

### 4.2b タブ: 全文検索（日本語）
- **検索対象（このクエスト内）**: アイデアの **件名 / 本文（アイデア）/ 価値 / 備考・特記事項**、**チャット本文（ChatMessage）**、および **添付ファイル名（Attachment.original_name）**。
- **検索範囲＝当該クエストのパーティー閲覧範囲**（他クエストは対象外・クロステナント不可）。
- UI: 検索ボックス＋**対象フィルタ（すべて / アイデア / チャット / 添付）**＋件数。結果は **種別バッジ（アイデア/チャット/添付）＋所属アイデア＋ハイライト付きスニペット**。クリックで **アイデア詳細（SC-22）/ チャット（SC-24）** へ（**添付ヒットは紐づく親＝アイデア or チャットメッセージへ遷移**し、該当添付を示す）。空/0件の表示あり。
- **日本語全文検索エンジン＝決定**: **PostgreSQL の PGroonga**。
  - 理由: **分かち書き不要**で日本語に強い／ランキング（`pgroonga_score`）・スニペット/ハイライト（`pgroonga_snippet_html`）を**DB内で完結**（追加コンテナ不要）。索引は会社DBの **Idea（件名/本文/価値/備考）＋ ChatMessage（本文）＋ Attachment（添付ファイル名）**。拡張は**会社DBのみ**に導入。
  - 代替: **pg_bigm**（不採用）。将来の高精度化（あいまい・シノニム・タイポ許容）は **Meilisearch / OpenSearch＋kuromoji**（別コンテナ・同期が必要）。
  - 検索結果は Idea / ChatMessage / Attachment を横断（UNION）しスコア順。更新方式（索引のリアルタイム/近リアルタイム）は実装で確定。
- モックは**クライアント側の部分一致＋ハイライト**で挙動を再現（本番はサーバー側 FTS）。

### 4.3 タブ: パーティー
- メンバー一覧（アバター＋氏名＋**権限バッジ**：所有者/クエスト管理/評価者/投票/作成/コメント）。
- **パーティー・権限を編集**ボタン（所有者/管理のみ）＝**参加メンバー項目だけの専用ダイアログ**（`/quests/{id}/party`・URL モーダル・#4/FR-38）を開く（旧＝クエスト全体編集 SC-11 モーダルを開いていた）。メンバー追加/削除・権限付与/剥奪。**候補＝関連グループ（複数部署）のいずれかの所属者**＝部署絞込＋一括選択＋検索。保存は `PATCH /quests/{id}` に `members` のみ。
- 補足: 新規参加メンバーの既定権限＝投票＋作成＋コメント。パーティーから外すと権限は失うが既存の入力は表示継続。
- **参加リクエストの承諾/却下も本タブに統合（新タブは作らない・FR-40／C.9）**＝`owner`/`quest_admin` のみ。**申請者（`pending`）をメンバー一覧の上位**、**却下者（`rejected`）を下部**に表示（`GET /quests/{id}/join-requests`）。**行クリックでユーザープロフィールをダイアログ表示**し、その中の**「承諾」/「拒否」**で処理（`POST .../join-requests/{uid}/approve|reject`）。承諾で通常メンバー化（既定権限付与・リクエスト経由マーク併記可）。**却下は非終端**＝下部に残し後日「承諾」で復活（`rejected→approved`）。結果は申請者へ通知＋メール（H `join_request_decided`）。

### 4.4 タブ: 概要
- 定義リスト: ステータス / カテゴリー / 目的・テーマ（全文）/ 期限日 / クエストグループ / 所有者 / 作成日 / アイデア数。

### 4.5 タブ: 結果（🏁 クエスト最終結果＝アイデア選別の申し送り・FR-39・ISO 56001）
- **位置づけ**: クエスト（現バージョン）を ISO 56001 の①機会の特定＋アイデアの選別を担うツールと捉え、**機会特定＋選別の締め＝将来のコンセプト検討へ渡す「アイデア選別の申し送り」**を、既存3成果物（アイデア＋議論＋評価）を凝縮して1枚に集約する（ISO 対応の正＝[コンセプト機能 ISO56001 再設計](../../設計ドラフト/コンセプト機能_ISO56001_再設計.md)／タブ構成の詳細＝[FR-39](../../設計ドラフト/FR-39_クエスト最終結果_ISO56001.md)・API設計 C.8・データモデル §5.32）。
- **表示タイミング**: **常時表示**（途中経過も見られる）。**`completed` 前は「暫定の途中経過」を明示**（タブに「暫定」チップ＋上部に進行中バナー＋見出しの語調）。ISO 56001 §9（継続的パフォーマンス評価）に整合。
- **構成（上から）**:
  1. **✅ 選定アイデア**: 選定アイデア（複数可）＝タイトル/価値/投稿者/評価平均＋**チャットへのリンク**（(a) 議論の要点）。選定 0 なら「選定なし」。
  2. **📊 評価・選別サマリ（§9）**: 参加指標（アイデア/選定/投票/評価/パーティー数）＋観点別平均（新規性/影響度/実現度/適合性/コスト）のバー。数値は**閲覧者に可視な submitted 評価のみ**（F.1 visibility 準拠）。
  3. **🧭 意思決定の記録**: 公開アイデアを評価平均順に「採用/不採用＋評価平均」。
  4. **📌 議論の要点**: **(b) ピン留め**メッセージ（owner/quest_admin がチャットで📌）＋**(c) 自動要約**（抽出型・オフライン・無料／管理者が生成・再生成）。
  5. **📝 振り返り・学び / 次アクション（§10）**: `summary`/`learnings`/KPI（自由記述）/`next_actions` を **owner・quest_admin が編集**。「このクエストを複製して次を起票」導線（後続サイクルへ）。
  6. **🔗 採用された関連情報（FR-41 Phase2）**: 採否で **採用（`adopted`）** にした関連情報を**クエスト＋配下アイデアで集約**して表示（情報タイトル＋出典＋**処理メモ＝どう反映したか**＋どの成果物に紐づくか＋採用者/日時）。C.8 `adopted_info[]`。0件なら非表示 or 空文言。**情報タイトルは参照モード（採否モード＝`?from=対象種別:対象ID`）で開く**（SC-52 §7-採否）。
- **権限**: 閲覧＝パーティー員（C.0・評価は visibility 準拠）。編集（4/5 と③の一言）＝**所有者・クエスト管理**。総括の初回記入で XP+20（G・冪等）。
- **完了時の副作用**: `completed` 遷移で**作成者以外へ通知**（`quest_result_ready`）＋**チーム成果フィード**（`quest_completed`）。後退しても取り消さず、再完了でも重複しない（API設計 C.5）。
- **④ソリューション開発**のアプリ内実装は**将来拡張（今回スコープ外）**。

### 4.6 タブ: コンセプト（🧩 ISO ②③段の候補コンセプト＋検証プール・FR-42）
- **位置づけ**: 🏁 結果（アイデア選別の申し送り・§4.5）を受けて、**選別済みアイデアを昇華した候補コンセプト（複数・競合）**を一覧し、**前提の検証（検証プール）**を回す段（ISO 56001 ②概念の創造・③検証／正本＝[コンセプト機能 ISO56001 再設計](../../設計ドラフト/コンセプト機能_ISO56001_再設計.md)・[要件定義 README](../../要件定義/README.md) FR-42・[API設計 P_コンセプト](../../API設計/P_コンセプト.md) P.1）。
- **タブ冒頭に ⓘ「コンセプトとは？」ガイダンス**（[デザイン標準](../デザイン標準.md) §4.13 `.screen-purpose`）＝ISO 56001 準拠の定義・狙い・粒度をホバー展開＋クリックで全文（SC-60/61 と共通文面）。
- **構成（上から）**:
  1. **候補コンセプト一覧**（`GET /quests/{quest_id}/concepts`・P.1）＝各行に **名前／status（draft/active/archived）／総合判定バッジ（Go/Pivot/Kill）／★選定／由来アイデア数／前提数／評価要約（提出数・推奨内訳）／更新日**。**自分の `draft` を含む**（本人のみ）。行クリックで **SC-61 コンセプト詳細**（モーダル差し込み・URL 直/リロードはフルページ）。一覧は DataTable 標準（サーバー委譲・[デザイン標準](../デザイン標準.md) §4.5）。
  2. **検証プール（前提）**（`GET /quests/{quest_id}/assumptions`・P.3）＝クエスト単位の第一級リスト＝**前提／現在判定（支持/反証/保留）／検証件数／リンク中コンセプト数／最終検証日**。**反証（refuted）は⚠強調**（リンク先コンセプトへ波及・要再評価）。前提は複数コンセプトで共有（DRY・§3.5）。
- **導線**: **「＋ コンセプトを作成」＝SC-60 コンセプト登録・編集モーダル**（由来アイデア選択＋スキーマ入力）。前提の作成/検証はプール所有（owner/quest_admin）＝SC-61 詳細から（P.3/P.4）。
- **権限**: 閲覧＝パーティー員（`active`／自分の `draft`・門番 P.0）。作成＝パーティー員（既定 `draft`）。活性化/保管・選定・総合判定＝owner/quest_admin（P.2）。
- **空表示**: コンセプト 0＝「まだコンセプトはありません」＋作成導線。前提 0＝「検証プールは空です」。

## 7. API 入出力（案・API設計フェーズで確定）

- **GET `/api/quests/{id}`**: クエスト情報（カテゴリー/テーマ/期限/ステータス/所有者/グループ/自分の権限）。
- **GET `/api/quests/{id}/ideas?q=&status=&state=&eval=&sort=&page=`**: アイデア一覧（件名/投稿者/賛成数/反対数/コメント数/評価集計/自分の投票状態/`my_state`）。**検索・フィルター（状態/評価）・並び替え・ページング**に対応（一覧標準）。**公開アイデア＋自分の下書き（`status=draft` は本人のみ）を返す**（API 正＝`D_アイデア・添付・版・投票・フォロー.md` D.1）。※匿名化設定に従い集計のみ返す場合あり。
- **GET `/quests/{id}/concepts?q=&status=&sort=&cursor=`**（§4.6・P.1）: 候補コンセプト一覧（名前/status/decision/is_selected/由来数/前提数/評価要約/更新日）。**自分の `draft` を含む**。一覧標準（サーバー委譲）。
- **GET `/quests/{id}/assumptions?verdict=&cursor=`**（§4.6 検証プール・P.3）: 前提一覧（記述/現在判定/検証件数/リンク中コンセプト数/最終検証日）。
- **GET `/api/quests/{id}/members`**: パーティー＋各メンバーの権限。
- **GET `/api/quests/{id}/ranking/weekly?limit=3`**: クエスト内週間ランキング（当該クエストの活動〔Activity.quest_id〕から今週の XP＋コインを合算）。TOP3＋自分の順位。
- **GET `/api/quests/{id}/search?q=&scope=&page=`**（全文検索）: 当該クエスト内の **Idea（件名/本文/価値/備考）＋ ChatMessage（本文）＋ Attachment（添付ファイル名）** を日本語全文検索。out: `[{ type:"idea"|"chat"|"attachment", field, idea_id, chat_id?, attachment_id?, idea_title, snippet_html, score, target }]`。ハイライトは `snippet_html`（サーバー生成）。`scope`＝idea/chat/attachment/空。エンジンは PGroonga（決定）。
- **POST `/api/quests/{id}/ideas`**（SC-21）: アイデア作成（下書き/公開）。
- **PATCH `/api/quests/{id}`**（SC-11）: クエスト編集。**メンバー/権限**は `/members`・`/permissions` 系で更新。
- すべて当該会社DB＋パーティー/権限をサーバーで検証。クロステナント禁止。

## 8. 非機能・アクセシビリティ

- タブは `role=tablist/tab/tabpanel`・`aria-selected`。キーボード操作対応（実装で ←→ 移動）。
- テーブル行リンクはキーボードでも到達可能にする（実装：各行に代表リンク or `tabindex`＋Enter）。
- 投票集計・評価は色のみに依存しない（数値＋テキスト）。
- 背景画像（`.app-bg`）は全認証画面共通のため本画面でも反映。
