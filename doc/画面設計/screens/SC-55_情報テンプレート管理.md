# SC-55 情報テンプレート管理（内部情報テンプレートのマスタ・会社管理者）（画面設計 / 機能詳細）

> 会社管理者が**内部情報テンプレート**（報告書/電話対応履歴/作業履歴 等の定型フォーマット）を**追加/編集/有効・無効/複製/削除（論理）**するマスタ画面。ここで管理したテンプレートが情報登録モーダル（[SC-51](SC-50_情報インプット.md) §6b ピッカー）に供給される。
> 仕様の正＝[情報インプットテンプレート機能 設計](../../設計ドラフト/情報インプットテンプレート機能_設計.md)（§3 構成・§5 データ・§6 画面・§7 API）・[API設計 N.5b](../../API設計/N_情報インプット.md)・[データモデル §5.37b](../../データモデル.md)。要件＝[FR-41 ⑩](../../要件定義/README.md#6-機能要件)。
> 対象デザイン標準＝[デザイン標準](../デザイン標準.md)（DataTable §4.5＋RowMenu・複製標準・確認モーダル・入力検証 §4.7・モーダル §4.1）。**登録/編集は URL付きモーダル（RouteModal＋Intercept）が標準**（[[url-modal-standard-for-dialogs]]）。リッチテキスト部品は **SC-50（情報インプット）の資産を共用**（本文ひな形エディタ）。

- 最終更新: 2026-10-09
- ステータス: **設計（実装着手）**＝ルート `app/(app)/admin/info-templates/`（想定）／`features/info-templates`／backend `tenant/info`（`info_templates`・N.5b EP）。ナビは管理者のみ（会社設定/マスタ系メニュー配下）。テスト＝[N-TC-3xx](../../テスト/N_情報インプット.md)。
- **踏襲元（新規UIを作らない）**＝管理系 DataTable＋RowMenu（⋮）＋**URL付きモーダル**の登録/編集（[[reuse-existing-ui-no-new]]）。

## 1. 概要・目的

- 会社ごとに扱う内部文書の「型」は異なり運用で増減する＝コードに焼き込まず**会社共通マスタ**で保守する（運用主体＝会社管理者）。
- テンプレートを選ぶと情報登録が**穴埋めだけ**になり、フォーマットが揃うことで後段分析（ワードクラウド/類似リンク/要約）が安定する（SC-51 §6b）。
- **テンプレートと情報は疎結合**＝ここでの編集/削除は**既存の情報（`info_items`）には影響しない**（登録後は `source_template_id` に由来だけ残り、本文/属性はスナップショット）。

## 2. アクセス条件・権限

| 項目 | 内容 |
| --- | --- |
| アクセス可能者 | **`company_account_admin` / `system_admin`**（一般ユーザーは不可）。**サーバーで強制**＝管理 EP（`POST/PATCH/DELETE /info-templates`・`GET /info-templates?admin=1`）は管理者ロールを 403 で弾く（UI 非表示に依存しない・[API N.5b](../../API設計/N_情報インプット.md)・コーディング規約 §1.6）。 |
| 表示 | 全件（`is_active=false` 含む・論理削除は既定除外＝`include_deleted` で表示）。`sort_order`→`name` 昇順が既定。 |
| 変更 | 追加/編集/有効・無効/複製/削除＝管理者のみ。`body_html` は**保存時サーバーでサニタイズ**（受信値を信用しない＝多層防御）。 |

## 3. レイアウト構成

- 冒頭＝バックリンク「← 管理メニューへ戻る」＋ページヘッダー（見出し「🗂 情報テンプレート管理」＋主操作「＋ テンプレートを追加」）＋リード文（「情報登録で選べる定型フォーマットを管理します」）。
- **本体＝標準 DataTable**（`storageKey="sc55-info-templates"`・**サーバー委譲**＝`GET /info-templates?admin=1`・列 flags は backend ホワイトリスト一致 [[list-server-delegation-standard]]）＝カード/リスト切替（既定＝リスト）・検索（名称/説明）・列フィルタ/ソート・ページャ・CSV。
- 追加/編集＝**URL付きモーダル**（`/admin/info-templates/new`・`/admin/info-templates/{id}`＝RouteModal＋Intercept＋フルページ fallback・§6）。

### 3.1 一覧の列（DataTable）

| 列 | 内容 | ソート/フィルタ |
| --- | --- | --- |
| 名称 | `name`（クリック＝編集を開く） | ソート可・テキストフィルタ |
| 説明 | `description`（抜粋・未設定は「—」） | テキストフィルタ |
| 既定属性 | `defaults_summary`＝設定済み属性のチップ（例「内部・取引先顧客・情報」）・無しは「—」 | — |
| 有効 | **有効**（`badge-success`）/**無効**（`badge-muted`） | ソート可・enum フィルタ |
| 並び順 | `sort_order`（数値右寄せ） | ソート可 |
| 更新 | `updated_by` / `updated_at` | ソート可 |
| （操作） | **RowMenu（⋮）**＝編集／有効・無効トグル／複製／削除（danger） | — |

- 行クリック＝**編集モーダルを開く**（RowMenu「編集」と同じ）。
- カード＝名称＋有効バッジ＋既定属性チップ＋「並び順 ・ 更新者 ・ 更新日時」メタ。

## 4. 一覧アクション（RowMenu）

| 操作 | 結果 |
| --- | --- |
| 編集 | 登録/編集モーダル（§6）を編集モードで開く（`/admin/info-templates/{id}`） |
| 有効にする／無効にする | **即時トグル**＝`POST /info-templates/{id}/activate`／`/deactivate` → 成功トースト → リロード（refreshToken bump・[[datatable-server-refreshtoken]]）。無効は**新規ピッカーから除外・既存情報は不変**。 |
| 複製 | [デザイン標準] 複製標準＝既存テンプレを雛形に**名称「〇〇のコピー」**で新規モーダルを開く（本文/既定/タイトル雛形をプリフィル・`is_active=false` 初期）。保存で別テンプレとして作成。 |
| 削除 | **確認ダイアログ（danger）**「『…』を削除しますか？ 今後の登録で選べなくなります（既存の情報は変わりません）。」→ `DELETE /info-templates/{id}`（**論理削除**＝`deleted_at`/`deleted_by_id`）→ 成功トースト → リロード。論理削除済みの名前は再利用可。 |

## 5. アクション・遷移（画面全体）

- ＋ テンプレートを追加 → 追加モーダル（§6・新規・`/admin/info-templates/new`）。
- 行クリック/RowMenu 編集 → 編集モーダル（§6・詳細取得でプリフィル）。
- RowMenu 有効・無効/複製/削除 → §4。
- 管理メニューへ戻る（バックリンク）。

## 6. 追加/編集モーダル（URL付き・§4.1 モーダル・§4.7 入力検証）

- **RouteModal**（`.modal.sectioned`・URL付き＝Parallel＋Intercept・フルページ fallback）。ヘッダー＝「テンプレートを追加」/「テンプレートを編集」。
- **ダイアログ内コンテンツ標準**（§4.1）＝**項目ごとに仕切り線**（`.dialog-section`）。
- **入力項目**:
  1. **名称**（必須・`Field` エラー＝未入力「名称を入力してください。」／重複は保存時 409 を Field エラー「同名の有効なテンプレートがあります。」へマップ）。
  2. **説明**（任意・ピッカー副文）。
  3. **タイトル雛形**（任意・穴埋め前提可・例「電話対応履歴（）」。`{{today}}` で当日日付の目印＝適用時クライアント展開）。
  4. **本文ひな形**（必須・**SC-50 と同じリッチテキストエディタを再利用**＝見出し/箇条書き/強調等）。記入欄は**プレースホルダ段落**（例「（記入）」）で明示。保存時サーバー nh3 サニタイズ。
  5. **属性既定値**（任意・各属性のセレクト＝先頭に「既定にしない」）＝優先度／情報ソース／情報分類／大分類／対象事業／影響分類／影響度／影響発生時期／**情報カテゴリ（複数可）**。選んだものだけ `defaults` に入る。
  6. **並び順**（`number`・既定 0）。
  7. **有効**（`.checkbox`「情報登録で選べるようにする」・既定 ON／複製時は OFF）。
- **入力検証は §4.7 の4部品**（[[form-validation-47-standard]]）＝Field error／FormSummary／`useFormErrorNotice`／FormFooterError（必須＝名称・本文ひな形／属性既定の enum 不正はサーバー 422 をフィールドへマップ）。
- **フッター**＝「キャンセル」（左）＋「追加する」/「保存する」（primary・`loading`）。
- **保存時の挙動**:
  - 追加＝`POST /info-templates`（`{name, description?, title_template?, body_html, defaults?, sort_order?, is_active?}`・`Idempotency-Key`）。
  - 編集＝`PATCH /info-templates/{id}`（部分更新）。`body_html` 変更で再サニタイズ・`name` 変更で一意再検証。
  - 失敗＝422（検証）はフィールド/サマリへ・403 はトースト（権限）・409（名称重複）は名称フィールドへ。
- **編集時プリフィル**＝`GET /info-templates/{id}`（管理者は無効/論理削除も取得可能＝`admin` 文脈）で `body_html`/`defaults`/`title_template` 等をセット。

## 7. データ・API（正＝[API設計 N.5b](../../API設計/N_情報インプット.md)）

- 管理一覧＝`GET /info-templates?admin=1`（DataTable 契約 §1.8.1・`defaults_summary`・`updated_by`）。
- ピッカー供給（SC-51）＝`GET /info-templates`（有効のみ・軽量）／適用詳細＝`GET /info-templates/{id}`。
- 追加＝`POST /info-templates`／編集＝`PATCH /info-templates/{id}`（`body_html` サーバー sanitize・`defaults` キー/値検証）。
- 有効/無効＝`POST /info-templates/{id}/activate`・`/deactivate`。
- 削除＝`DELETE /info-templates/{id}`（論理・204）。
- `deleted_*`/監査列（`created_by_id`/`created_at`/`updated_at`）＝**サーバー生成**（クライアントから受け取らない＝マスアサインメント防止）。

## 8. セキュリティ・ガバナンス

- **本文ひな形の XSS サニタイズ**＝**保存時＋表示時に許可リスト方式**（backend `nh3`・情報本文 `body_html` と同一許可リスト）。**管理者作成でも例外にしない**（多層防御・コーディング規約 §2.2）。
- **属性既定の値検証**＝`defaults` のキーは既知属性に限り、値は当該 enum（会社拡張含む）に実在すること（422 `invalid_template_defaults`）。
- **権限はサーバー強制**＝管理 EP は管理者ロールを 403・非管理者の `admin=1` も 403。他テナントは 404（存在秘匿）。
- **テナント分離**＝会社DB（他社テンプレは見えない）。

## 9. モック / 実装フロー

- **モック先行**（フロント実装フロー規約）＝`doc/画面設計/mocks/` に DataTable＋登録/編集モーダル（リッチエディタ＋属性既定セレクト）→受入→実装（`impl/frontend/src/features/info-templates`〔新 feature〕）。本文エディタは SC-50 の資産を共用。
- **一覧は最初からサーバー委譲契約**（`GET /info-templates?admin=1` の DataTable クエリ・列 flags=backend ホワイトリスト一致）。
