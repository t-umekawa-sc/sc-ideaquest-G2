## 0. コンセプト（決定事項）

- **トーン = バランス型**。基本はクリーンな業務SaaS（企業の社内利用に耐える落ち着き・信頼感）。
  そのうえで **ゲーミフィケーション部分だけ「昔のドット絵ゲーム（レトロ・ピクセルアート）」** をコンセプトにアクセント化する **二層構成**。
- **カラー基調 = ブルー系**（信頼・定番）。
- **モック実装方式 = 共通CSS＋デザイントークン（CSS変数）**。依存なしでブラウザ直開き可、Next.js へトークン単位で移植しやすい。

### 二層の使い分け（重要）
| 層 | 使う画面/領域 | 見た目 |
| --- | --- | --- |
| **業務層（クリーン）** | ログイン・クエスト・アイデア・評価・チャット・フォーム全般・管理画面 | ブルー基調、角丸、ソフトな影、Noto Sans JP |
| **ゲーム層（レトロ）** | ダッシュボードのステータス・XP/レベル・コイン・ショップ・アバター/着せ替え・実績/バッジ・ランキング・XP獲得/レベルアップ演出 | ドット絵風、角丸なし、ハードシャドウ、DotGothic16、`.pixel*` クラス、**マテリアル＝CRTガラス**（下記） |

> ゲーム層は「ご褒美・楽しさ」を担う**アクセント**。業務フローの本体（入力・議論・評価）はクリーン層で迷いなく使えることを優先する。

### 1レイヤー＝1マテリアル（決定・2026-07-18）

**各レイヤーが持つ「材質」は1つだけ**にする。材質（ガラス/不透明など）は「業務か遊びか」を瞬時に伝える記号なので、1画面に複数の材質を混在させると統一感を損ない、可読性も落ちる。

- **ゲーム層 = CRTガラス**（半透明の暗ガラス＋走査線＋上端反射で“古いゲーム機の画面ガラス”を表現）。ドット感（角丸なし・ハード枠/影・ピクセルフォント）は維持。背景（`.app-bg` の背景画像など）を透かして映える。トークン `--pixel-glass-*`、適用先は `.pixel-panel` / `.pixel-dialog`。
- **業務層 = クリーンな不透明カード**（白面・角丸・ソフト影）。**ガラス化しない**（読ませる本文パネルの可読性と、背景画像スクリムとの整合を守る）。
- **業務パネルの区別は「材質」でなく「色アクセント」で行う**（例: ダッシュボードの下書き=グレー／未投票=プライマリ青／フォロー中=インフォ水色／参加中クエスト=クエスト色。白カード＋上端の細い光沢や見出し/左端のアクセント色バー）。

## 1. カラートークン

`shared.css` の `:root` に定義。主要なもの:

- **ブランド**: `--color-primary #2563EB`（hover `#1D4ED8` / active `#1E40AF` / soft `#EFF6FF`）
- **ニュートラル**: `--color-bg #F8FAFC` / `--color-surface #FFFFFF` / `--color-border #E2E8F0` / `--color-text #0F172A` / `--color-text-muted #64748B`
- **意味色**: success `#16A34A` / warning `#D97706` / danger `#DC2626` / info `#0EA5E9`
- **投票**: 賛成 `--color-agree #16A34A`（グリーン）/ 反対 `--color-disagree #DC2626`（レッド）
- **レアリティ（装備）**: コモン `#94A3B8` / 標準 `#3B82F6` / レア `#A855F7`（明面用）・**レア on-dark `#D8B4FE`**（CRTガラス等の暗面用。レベルと同方針）
  - ※ 装備アイテムはショップ/きせかえ＝ゲーム層（CRTガラス）で使うのが基本。ガラス上でレアの紫が沈むため、`.pixel-panel` 内の `.rarity-rare` は自動で on-dark に切替（明面で使う場合は `.rarity-rare` のまま。単独で暗面に置くなら `.on-dark` を付与）。
- **ゲーム**: XP `#FBBF24` / コイン `#F59E0B` / レベル `#8B5CF6`（明面用）・**レベル on-dark `#C4B5FD`（CRTガラス等の暗面上のレベル文字用）** / **SP（スキルポイント）`#34D399`** / cyan `#22D3EE` / magenta `#EC4899` / パネル背景 `#1E293B`
  - ※ CRTガラス（ゲーム層）の上に**紫のレベル文字**を置くとコントラスト不足で読みにくいため、暗面上のレベル表示は `--pixel-level-on-dark`（明るいバイオレット）＋薄い影を使う。白ピル（`.pixel-stat.level`）など明面はそのまま `--pixel-level`。

## 2. タイポグラフィ

- **本文フォント（業務層）**: `Noto Sans JP`（フォールバック system-ui）。
- **ゲームフォント（ゲーム層のみ）**: `DotGothic16`（日本語対応のドットフォント）。`.pixel` / `.pixel-panel` / `.btn-pixel` などに適用。
- **サイズスケール**: xs12 / sm14 / base16 / lg18 / xl20 / 2xl24 / 3xl30。行間 1.6。
- モックはCDN（Google Fonts）で読み込む。**実装では `next/font` に置換**する。

## 3. スペーシング / 角丸 / 影

- **余白**: 4px基準（`--space-1`=4 … `--space-16`=64）。
- **角丸**: 標準 8px（`--radius`）/ カード 12px（`--radius-lg`）/ 丸 `--radius-full`。**ゲーム層は 0**（`--radius-pixel`）。
- **影**: 業務層はソフト（`--shadow-sm/…-lg`）。ゲーム層は**ハードシャドウ** `--shadow-pixel: 4px 4px 0`。ボタン押下（`:active`）の“押し込み”は**業務層＝内側の影 `inset`**／ゲーム層＝ハードシャドウ縮小で表現。

## 4. コンポーネント（共通CSSに用意済み）

- **ボタン**: `.btn` / `.btn-primary` / `.btn-outline` / `.btn-danger` / `.btn-sm`、ゲーム用 `.btn-pixel`。
  - **状態**: hover（塗り/枠を一段濃く。`.btn-danger` も hover あり）／ **押下 `:active`**（業務層＝**1px 沈み込み＋内側の影 `inset`＋塗りを一段濃く**のクリーンな挙動。バリアントごとに `active` 色を定義：primary=`--color-primary-active`／danger=`--color-danger-active`／outline=`--color-border`／標準=`--color-border-strong`）。`prefers-reduced-motion` 時は沈みを止め色変化のみ。
  - **ゲーム層 `.btn-pixel`** はハードシャドウで**ガコッと沈む**別トーン（業務層のクリーンな沈みとは意図的に差別化）。
- **カード**: `.card` / `.card-title`。
  - **用途別カラーアクセント `.card-accent`**: 業務カードを**材質でなく色で区別**する標準（1レイヤー1マテリアル方針）。左端に色帯を出す（擬似要素なのでホバーの影/枠線変化に不干渉）。色は `--accent` で指定。ダッシュボードでは下書き=グレー（`--color-text-subtle`）／未投票=プライマリ青／フォロー中=インフォ水色／参加中クエスト=**クエスト色**（カードに `--accent` を設定すると `.quest-icon__char` のタイル色も同じ `--accent` に連動）。
- **テーブル / 一覧（標準）**: `.table`（`.table-wrap` で囲むと横スクロール＋カード見た目）。数値列は `.num`（右寄せ・等幅数字）、行遷移は `<tr class="row-link">`。
  - **セルは折り返さない（既定・決定 2026-08-02）**: `.table` のセルは **`white-space: nowrap`（折り返し禁止）が既定**。幅に収まらない場合は **`.table-wrap` の横スクロール**で見せる（テーブル枠ごとスクロール）。**例外の上書き**＝長い自由文セルは **`.cell-wrap`（折り返し許可）** または **`.cell-clip`（1行省略・末尾「…」＋`title` でホバー全文表示・`--cell-clip-max` で幅）** を明示的に付ける。
  - **複数値セルの省略（決定 2026-08-02）**: バッジ等が複数入るセル（所属クエストグループ 等）は **`.cell-tags`** でくるみ、**幅（`--cell-tags-max`・既定 16rem）に収まらない分は末尾に「…」を表示・ホバーで全件**（`title` 属性・`shared.js` の `applyCellClips()` が overflow を検出して `.is-clipped` を付与）。動的描画のテーブルは **各画面の `render()` 末尾で `applyCellClips()` を呼ぶ**。
  - **操作列は sticky 右固定＋⋯メニュー（決定 2026-08-02・ユーザー選択）**: 操作（編集/無効化 等）を持つ列は **`.col-actions`** を付け、**横スクロール時も行右端に貼り付く sticky 列**にする（左側に境界の影で本文と分離）。操作が複数ある管理テーブルは **⋯（ケバブ）メニュー `.rowmenu`** に畳んで列幅を最小化（`shared.js` が `.rowmenu__list` を `position:fixed` で配置＝`table-wrap` の overflow に隠れない）。**絶対座標フローティング（オーバーレイ）は非採用**（可変行高でのズレ・データ被り・キーボード/読み上げ順の崩れを避ける）。単一操作の列は sticky 列にボタン/リンクを直接置く（⋯不要）。
  - **行リンクと操作列の併用（F5・決定 2026-08-02）**: **操作列（編集/無効化 等のボタンを持つ列）がある管理テーブルは `row-link` にしない**（行クリック遷移とボタン操作が競合するため）。行全体を遷移させたい一覧（SC-10/SC-12 等）は `row-link` を使い操作列を持たない。やむを得ず併用する場合はボタンの click で `stopPropagation` する。
  - **アクセシビリティ（F3・決定 2026-08-02）**: `<thead>` の見出しセルは **`<th scope="col">` 必須**（行見出しがある場合は該当セルを `<th scope="row">`）。テーブルの意味が見出しだけで伝わらない場合は **sr-only の `<caption>`**（視覚的に隠す）で表題を付ける。**`row-link` は先頭セルを `<a>` 化してキーボードでも到達・実行可能にする**（`<tr onclick>` だけにしない）。状態バッジは色のみに依存せずテキストを併記（`.badge` の文言）。
  - **ソートの表現（F4・改定 2026-08-13）**: **「4.5 一覧の操作標準（DataTable）」に統合**。列見出しクリックの単一列ソート（`aria-sort`）＋複数キーの詳細ソートを**共通部品として標準化**（旧「ツールバー `select` 一本化／列ヘッダソートは MVP 非採用」を**上書き**）。詳細は §4.5。
  - **件数の単位（F6）**: `.list-count` は**原則「N件」**。人数が主体の一覧（アカウント/メンバー一覧 等）は「N名」も可。同一画面内で単位を混在させない。
  - **レスポンシブ（F7）**: 列が多いテーブルは `.table-wrap` の**横スクロールで可**（MVP）。モバイル最適化（優先列の折り返し・カード化）は将来。まず横スクロールで破綻しないことを担保する。
- **一覧ツールバー（標準・`.list-toolbar`）**: **一覧（テーブル/カード）には検索・フィルター・並び替えを標準で付ける**。左＝`.filters`（横断検索ボックス＋「詳細絞込」「詳細ソート」＋適用中の要約チップ）、右＝`.tools`（**表示密度**＋**列設定**＋**エクスポート**）。**件数と表示件数は表下部のページングバー（`.dt-footer`）**にまとめる（§4.5 ③）。テーブル一覧は **§4.5 一覧の操作標準（DataTable）** に集約（`shared.js` の `DataTable`）。**データ量が少なければクライアント側、多ければサーバー側でフィルター/ソート/ページング**（実装で判断）。
  - **「絞り込みをクリア」（F1・必須・決定 2026-08-02）**: **検索語・状態フィルタ・並び替え等が 1 つでも既定から変化している時は「絞り込みをクリア」ボタンを表示**（`.filters` 末尾・既定は `hidden`）。押下で全フィルタを初期化。フィルタを持つ一覧は SC-10/SC-12 に加え **SC-90/91/92/93 等でも必須**（従来は一部のみ実装＝標準として全一覧に統一）。フィルタが検索のみの一覧でも、検索語が入っている間は表示する。
  - **0 件表示**: `.list-empty` で空表示（絞り込みで 0 件になった場合は「絞り込みをクリア」への導線も添える）。
- **ページネーション（標準・`.pagination`・F2・改定 2026-08-13）**: 件数が増える一覧（特に管理系 SC-91/92/93）に付ける標準部品。**オフセット方式＝番号リンク**「`« ‹ 1 … 4 [5] 6 … 20 › »`」（`«`最初/`‹`前/`›`次/`»`最終・現在ページは `aria-current="page"`・現在±2＋先頭/末尾＋`…`）。API `?page`/`per_page`＋`page_info.total`（API設計 §1.8）と対応。**カーソル方式**（チャット等・大量/追記型）＝`.pagination--more` の「もっと見る」（`page_info.next_cursor`）。`.list-count`（総件数）と併用。詳細は §4.5。実体は `mocks/shared.css` の `.pagination`。
- **バッジ**: `.badge` / `.badge-success` / `.badge-danger` / `.badge-muted`。投票表示 `.vote-agree` / `.vote-disagree`。
- **レアリティ枠**: `.rarity-common/standard/rare`。
- **ユーザアバター**: `.avatar`（`.sm`/`.lg` でサイズ可変）。`.avatar__img`（画像・なければ `.placeholder` でイニシャル）＋ `.avatar__level`（**下部中央にレベル表示**）。`data-name` 属性＋`tabindex="0"` で**ホバー/フォーカス時にユーザ名ツールチップ**。複数並べるときは `.avatar-group`（少し重ねる）。投票の記名モード・パーティー一覧・チャット等で使用。
- **カラースウォッチ**: `.swatches` / `.swatch`（`role=radiogroup`/`role=radio`・`--sw` に色）。**プリセットパレットからの単一色選択**（選択にチェック表示・focus-visible リング）。**クエストカラー**の設定に使用＝選んだ色が `.card-accent` の左帯と**未設定クエストアイコンのタイル色 `--accent`** を駆動（設定は SC-11）。パレットは 600 レベルの10色（ティール/ブルー/バイオレット/インディゴ/グリーン/アンバー/ローズ/シアン/オレンジ/スレート）。
- **クエストアイコン**: `.quest-icon`（`.sm`/`.lg` でサイズ可変）。**カスタム画像**（`.quest-icon__img`）を設定できる。**未設定時のフォールバック＝件名の頭文字タイル（`.quest-icon__char`）＋右下に所有者アバターを重ねる（`.quest-icon__owner`）**。**タイル色は `--accent`（クエスト色）に連動**（親カードで `--accent` を設定すると `.card-accent` の左帯とアイコン色が揃う。未指定はプライマリ）。クエストヘッダー（SC-12）・参加中クエストカード（SC-01）・クエスト一覧など、クエストを表す箇所で共通利用。実体は MinIO、`Quest.icon_image_path`。設定は作成/編集モーダル（SC-11）。
- **フォーム**: `.field` + `.input` / `.textarea` / `.select`、必須マーク `.req`、補足 `.hint`。
- **コンボボックス（選択）**: 既定は**ネイティブ `.select`**（a11y・モバイルに強い。本体は指ポインター）。ただし**候補(option)はOS描画のため cursor 制御不可**。候補までホバーの指ポインター/ハイライト/装飾を効かせたい場合は**カスタム `.combobox`**（`<button>＋role=listbox`）を使う。挙動は `mocks/shared.js`（`[data-combobox]` を初期化・↑↓/Enter/Escキー対応）。候補は自前要素なので `cursor:pointer` が確実に効く。
- **複数選択コンボボックス**: `.multiselect`（`[data-multiselect]`）＝**オートコンプリート絞り込み＋選択チップ**の複数選択部品。選択済みは control 内に**チップ表示（`.multiselect__chip`・×で解除）**、入力で候補を絞り込み **↑↓/Enter** で確定、空欄で **Backspace** でも直前チップを解除。**`data-free="true"` のモード**では候補に無い手入力文字列も **Enter で追加**（自由入力タグ＝`.is-custom` でグレー表示、候補由来と区別）。挙動は `mocks/shared.js`（`[data-multiselect]` を初期化）。**単一選択モード `data-single="true"`**＝チップにせず入力欄に確定値を表示するオートコンプリート付きセレクト（候補のみ・1つだけ）。**使い分け**: 自由入力あり複数＝**クエストのカテゴリー（複数可）・アイデアの利害関係者**／候補のみ複数＝**マスタから複数選択**（パーティー候補 等）／単一選択＝**クエストグループ（1クエスト＝1グループ）**。
- **チェックボックス**: `.checkbox`（`<label class="checkbox"><input type="checkbox"> 文言</label>`）。**モダン設計の原則に準拠**:
  - ネイティブ `<input>` を `appearance:none` で装飾（キーボード/スクリーンリーダー対応を維持）。
  - **ラベルごとクリック可・ラベル/ボックス両方が指ポインター**（無効時 `not-allowed`）。
  - 状態: hover（枠がブランド色）/ **focus-visible（リング）** / checked（ブランド色＋白チェック）/ **indeterminate**（横棒・JSで設定）/ disabled。
  - ボックスは**ラベル1行目に揃え**、複数行でも崩れない。モーションは ~120ms・`prefers-reduced-motion` で無効。
  - **使い分け**: フォーム内の選択・同意・複数選択はチェックボックス。**即時反映のON/OFF設定（管理画面のMFA有効・投票匿名化 等）はトグルスイッチ `.switch`** を用いる。
- **トグルスイッチ**: `.switch`（`<label class="switch"><input type="checkbox"><span class="switch__track"><span class="switch__thumb"></span></span><span class="switch__text">文言</span><span class="switch__state">ON/OFF</span></label>`）。**即時反映の ON/OFF 設定**向け（管理画面の会社設定＝MFA必須・投票匿名化・管理者への投票者開示 等）。ネイティブ checkbox を装飾（キーボード/SR対応維持）・ラベル/トラック両方 pointer・**focus-visible リング**・checked でブランド色＋ノブ移動・disabled は淡色。状態語（ON/OFF）は任意で併記。モーションは `prefers-reduced-motion` で無効。**チェックボックスとの違い**＝スイッチは「設定の即時 ON/OFF」、チェックボックスは「フォーム送信時に確定する選択/同意」。SC-91 会社設定で使用。

## 4.5 一覧の操作標準（DataTable・決定 2026-08-13）

> テーブル一覧に**ソート／絞り込み／ページング／列幅調整／列の表示・非表示・並べ替え／CSVエクスポート／表示密度／行の固定**を一括で付与する会社標準。実体＝`shared.js` の `window.DataTable`（`DataTable.init(root, config)`）＋`shared.css`（`9y` セクション）。ライブ実例＝`mocks/SC-91_システム管理.html`。
>
> **サーバー処理前提**: UI はクエリ条件（複数ソートキー・項目別フィルタ・ページ番号・ピンID）を組み立てるだけで、並びの最終決定・件数・CSV生成はサーバー（既存の `created_at,id` 決定的順序と整合）。モックは全件クライアント保持で挙動を再現する。**この標準は各一覧APIに「複数ソートキー・項目別フィルタ・CSVエクスポート・ピンID取得」というクエリ契約を要求する**（実装接続時に backend を拡張。CSV／行固定のページ跨ぎは backend 依存）。**このクエリ契約の具体（パラメータ記法・ホワイトリスト・offset/cursor の使い分け）は [`API設計/README.md §1.8.1`](../API設計/README.md)「DataTable クエリ契約」に規定**（2026-08-17）。

**共通の可視化ルール（改定 2026-08-17）**: **適用中の条件は全て「適用中」チップ行（`.dt-chips`）に集約**する＝**横断検索（`🔍 "…"`）・並び替え（単一列/複数キー・list/card 問わず）・絞り込み（項目別）**を1本の行にチップ化し、各チップ ✕ で個別解除。**クリアは「すべてクリア」1つだけ**（行末・`margin-left:auto` で右寄せ）＝段1の旧クリアボタン（`[data-dt-clear]`）は**廃止**。並び替え／絞り込みボタンには件数**バッジ（`.dt-badge`）**も付く（チップ行と併用）。

**ツールバーの安定配置**: DataTable のツールバー（`[data-dt-toolbar]`）は **2 カラムグリッド（`minmax(0,1fr) auto`）**。左＝`.filters`（🔍検索／↕並び替え／⧩絞り込み）は**左カラム内で折り返す**、右＝`.tools`（**列設定・エクスポート・表示密度・表示切替**の順）は**右カラムに固定**（**表示密度は表示切替の直左**に隣接）。絞込・ソートを指定して左側が増減しても**右側ツールの位置は動かない**（折り返しで飛ばない）。**段1の全コントロールは同一高さ（`--dt-ctl-h`）に揃える**（凸凹防止）。モバイル（≤768px）は 1 カラムで縦積み。

**操作列（アクション）**: 列定義に `actions: true`（`locked`・末尾固定・`.col-actions` sticky 右）を置き、`render` で **単一リンク**（例「管理する →」＝SC-91）または**⋯ ケバブメニュー（`.rowmenu`＝複数操作）**を描画。RowMenu の開閉は `shared.js` が委譲処理（動的行でも動作・`position:fixed` で `.table-wrap` の overflow に隠れない）。実処理は `menuitem` の `data-*` を各画面の委譲ハンドラで。サンプル＝`style-guide.html`「9.」の ⋯（編集/複製/削除）。**メニュー項目のホバー/フォーカスには標準で ▶ 選択カーソルが出る**（後述「メニューの選択カーソル」）。

**複製（標準アクション・決定 2026-08-22・ユーザー要望）**: 操作列（⋯ RowMenu）の**標準アクションとして「複製」**を用意する（編集/削除と並ぶ・任意採用）。**挙動＝登録（追加）ダイアログを「追加モード」で開き、選択行の値を初期表示に反映した状態で起動**する（＝既存レコードを下敷きに新規作成）。**編集モードではない**＝保存すると別レコードとして新規登録される（既存行は変更しない）。**一意キー/サーバー採番列は複製しない**＝`id`・各種業務コード（会社コード/クエストグループコード等）・作成日時/作成者などは初期値に載せず**空 or 自動採番**にする（**なぜ**＝複製直後の保存で `UNIQUE` 制約に衝突させない／新規レコードであることを明確にする／§2.2 Mass Assignment 方針でクライアントは内部列を送らない）。ダイアログは**単一の共通登録部品**を使う（§4.1 モーダル標準・複製専用ダイアログは作らない）＝`DataTable` は選択行データを渡すだけで、**プリフィルの仕組みは共通化**し、各画面は「どの項目を引き継ぐ／どれを一意キーとして除外するか」だけを宣言する。**行/カードの主アクションには割り当てない**（⑪＝複製は ⋯ メニューからのみ・行クリックの既定は編集）。適用可否は各画面が判断（複製に意味のある登録系一覧に付ける）。サンプル＝`style-guide.html`「9.」の ⋯（編集/複製/削除）。

### ① ソート（並び替え）
- **単一列**: 並べ替え可能な列は見出しクリック（`aria-sort`）。**昇順 → 降順 → 解除（既定順）** の3段トグル。インジケータ＝非アクティブ`⇅`／`▲`／`▼`。同時に1列。
- **複数キー（`.sort-builder`）**: ツールバーの**「↕ 並び替え」ボタン**（list/card 共通）→**左右2ペインのダイアログ**（見出し「並び替え（複数項目）」）。右＝対象外の項目、左＝並び替え条件（上ほど優先）。右をクリックで**FLIP アニメで左末尾へ追加**、左は各キーに昇順/降順（`.seg`）＋**▲▼で優先順位入れ替え**＋✕で除外（右へ戻る）。**適用中は単一列ソートを無効化**（バッジで明示・クリアで復帰）。並べ替えは▲▼標準（ドラッグは任意拡張）。`prefers-reduced-motion` でアニメ無効。

### ② 絞り込み
- **横断テキスト検索**: ツールバー左に常時表示（🔍アイコンを内包・**対象項目名はプレースホルダに内包**＝下段ヒントは廃止）。
- **項目別**: ツールバーの**「⧩ 絞り込み」ボタン**→ダイアログ（見出し「絞り込み」）。項目型に応じた入力＝テキスト（含む）／区分（チェック複数）／数値（範囲）／日付（範囲）。横断検索と **AND 結合**。

### ③ ページング（下部ページングバー `.dt-footer`）
- 表の下に**ページングバー**を置き、**件数ラベル（左）・番号ページャ（中央）・1ページの表示件数セレクタ（右）**をまとめる。件数・表示件数は上部ツールバーには置かない（操作系の近くにまとめる）。
- 番号リンク＋前後＋最初/末尾＝`« ‹ 1 … [5] … 20 › »`（現在±2＋先頭/末尾＋`…`・現在は `.is-current`＋`aria-current`）。1ページに収まる時はページャ非表示（件数・表示件数は残す）。カーソル方式は `.pagination--more`。
- **1ページの表示件数セレクタ**（`表示 N 件`）＝`perPageOptions`（既定 `[10,20,50,100]`）から選択。**ユーザー設定として保持**（`localStorage`）。現在値は選択肢に必ず含める。

### ダイアログ（並び替え/絞り込み）
- いずれも**標準モーダル**（`.modal.sectioned`＝ヘッダー/本文/フッター）に乗る＝**ドラッグ移動＋最大化（⤢）＋Esc/バックドロップ閉じ＋フォーカストラップ**を `shared.js` が共通適用。**動的生成モーダルにも自動適用**（`shared.js` が後から追加された `.modal`／`.modal--maximizable` を MutationObserver で拾って初期化）。サンプルは `style-guide.html`「10. ダイアログ」。

### ④ 列幅（比率フィット＋最小幅で横スクロール）＋手動調整
- **列幅は px 固定ではなく比率（%）**で与え、`table-layout:fixed` のテーブルに **`min-width`（＝読める最小幅の合計＝宣言幅合計の 80%）** を課す。これで：
  - **容器幅 ≥ min-width**: テーブルは**容器幅(100%)にフィット**＝比率どおり全列が伸縮（**横スクロール無し**）。標準の容器（1120）では常にフィット。
  - **容器幅 < min-width**（明らかに狭い時）: テーブルは **min-width を保持**＝各列は読める最小幅で止まり、はみ出しは **`.dt-scroll` が横スクロール**（列を潰さない）。
- 幅を測って合わせる処理は不要で、**縦スクロールバーの出現タイミング・サブピクセル・ウィンドウ幅に依存しない**（以前の JS 測り合わせ方式で残っていた横スクロールを根絶しつつ、狭い時は潰さず横スクロールで両立）。
- 見出し右端の**ドラッグハンドル（`.dt-resizer`）**でリサイズ（最小64px）。ドラッグ中は px で即時反映し、離すと全列を比率へ組み直して収まりを保つ（`st.widths` の px も比率・min-width 計算に含める）。**ダブルクリックで既定幅に**。あふれは省略（`overflow:hidden`＋`…`）。

### ⑤ 列の表示/非表示・⑥ 並べ替え（「列設定」メニュー `.col-menu` に集約）
- 「列設定」ボタン→ポップオーバーで**全列のチェック（表示/非表示）＋▲▼で並べ替え**。**主要名称列と操作列は `locked`＝非表示不可・並べ替え対象外**（名称列は先頭固定・操作列は末尾固定）。**列幅をリセット／既定に戻す**を同メニューに同居。
- 非表示列に有効なソート/絞込条件がある場合は**条件を維持し要約チップに残す**（隠しても効いていることを明示）。

### ⑦ CSV エクスポート
- 「エクスポート」ボタン→**現在の絞り込み・ソート結果の全件／表示中の列・列順**を **UTF-8（BOM付・Excel互換）** で出力。実装は**サーバー側生成**（同条件＋`format=csv` を受ける export EP＝backend 依存）。管理系のエクスポートは**監査ログ対象**。大量時の非同期化は将来。

### ⑧ 表示密度
- `標準 / コンパクト` の2段セグメント（`.table--compact`）。**全画面共通のユーザー設定**として保持。タッチ端末はタップ領域を確保。

### ⑨ 行の固定（ピン）＋縦は全行表示
- 行頭の**ピンアイコン（`.dt-pin-toggle`）**でトグル→**固定行セクション（`tr.is-pinned`・上部・強調背景＋区切り線）**にまとめて先頭に表示（絞り込み・ページングを override）。固定件数は**上限（既定5件・`maxPins`）**。ページャ／件数は非固定の母集合が対象（固定は別枠表示＋要約）。
- **縦は制限しない**＝テーブルは**全行を縦に表示しきり**、長い時は**ページ側がスクロール**する（`.table-wrap.dt-scroll` は横スクロールのみ＝`overflow-x:auto; overflow-y:visible`／内側の縦スクロール・固定ヘッダーは持たない）。※ 行数は**ページング（`perPage`）**で抑える。
- **保持（永続）**: 列順・表示/非表示・列幅・密度・ピン行ID・**表示（テーブル/カード）**は **`localStorage`（画面×列単位・`storageKey`）** に保存しログイン跨ぎで維持（将来はユーザー設定へ格上げ）。
- **検索/ソート/絞込/ページは URL クエリに同期**（2026-08-20 改定・従来はコンポーネント内 state で遷移すると失われていた）。キーは **`<storageKey>.q` / `.sort` / `.f` / `.page`**（`storageKey` 名前空間＝1 画面に複数テーブルがあっても衝突しない／既定値は URL に載せない）。ソートは `key`（昇順）/`-key`（降順）カンマ連結、絞込は `FilterCond` を JSON。書き戻しは **`router.replace`（履歴を汚さず現在エントリに畳み込む）**＝**詳細へドリルイン→ブラウザ戻る/一覧へ戻るで絞込・ページ付きの一覧に復帰**でき、**再読込・ブックマーク・共有**でも同じ表示が再現する。**なぜ**＝一覧→詳細→一覧の往復で検索条件が消えるのは実運用で不便（DataTable のセッション state はルート遷移で破棄されるため）。⑨の localStorage（表示状態）とは別レイヤ＝サーバーに渡すクエリ（README §1.8.1）を URL の SoT に載せるだけで、表示状態はサーバーに送らない原則は不変。詳細画面の「一覧へ戻る」は `router.back()`（履歴なし＝直接アクセス時は素の一覧へフォールバック）。**client/server どちらのモードでも同一挙動**＝サーバーモード一覧（会社一覧 SC-91 等）でも `.page`（＋`.q`/`.sort`/`.f`）を URL から復元し、**一覧→詳細→戻るで同じページ番号に復帰**する（サーバーモードでページが 1 に戻るのは本標準違反＝バグ）。

### ⑩ 表示切替（テーブル / カード）
- **`config.card(r)`（自由HTML）または `config.cardLayout(r)`（標準構造ヘルパ）を与えた一覧**に、上部ツールバー**最右**の**表示切替トグル（`.viewtoggle`＝「🔲 カード / ☰ リスト」）**を出す（未指定＝テーブルのみ・従来どおり）。**SC-10 クエスト一覧と同じ操作感**をどのテーブル一覧にも付与できる。切替は**最右に固定**し、モード変更で位置が動かない（テーブル専用ツールはその左に置き、カード時は隠す）。
- **カードの与え方（3通り）**: ①`cardLayout(r)`＝`{ title, badges:[{label,cls}], meta:[…], stats:[…] }` を返すだけで標準カードを組み立て（記述量削減）／②`card(r)`＝本文の生HTML（`.dt-card` ラッパ＋右上ツールは共通側が付与）／③**`cardRaw(r)`＝カード外側まで含む完全HTML**（`.dt-card` ラッパも⋯ツールも被せない＝**画面が見た目を完全制御する専用カードモード**。例＝SC-10 のアクセント帯付きクエストカード）。
  - **cardRaw でもピンは使える**: `pins` 有効時は**本体HTMLを書き換えず、外側に `.dt-cardraw` ラッパ＋フローティングのピンボタン（`.dt-pin-float`＝左上角に半分はみ出す小円）だけを重ねる**（ピンは本体 `<a>` の外＝押しても行遷移しない）。四隅とも情報が詰まる専用カード（SC-10）でも本体レイアウトに干渉しない。⋯アクション（`actions:true`）は cardRaw では被せない（本体で描く）。
- **行固定（ピン）の無効化**: `config.pins: false` でピン機能を切る（テーブルの📍列もカードのピンも出さない）。固定が不要な画面向け。
- **検索・絞り込み・並び替え・番号ページャ・行の固定（ピン）・操作列（⋯ RowMenu）・表示密度はカード表示でも共通**。操作列（`actions:true`）を定義していれば、テーブルと同じ RowMenu を**カード右上に自動表示**（`card`/`cardLayout` 側でアクションを書く必要はない）。**表示密度（`標準/コンパクト`）はカードにも効く**（`.dt-cards--compact`）。**列幅調整・列の表示/非表示・列設定はテーブル専用**（カード時は列設定ボタンを隠す）。
- **カード時の並び替え（改定 2026-08-17）**: 見出しクリックが使えないカード表示でも、**list と共通の「↕ 並び替え」ボタン**（複数キーダイアログ）で並び替える＝**カード専用の並び替えセレクト（旧 `.dt-cardsort`）は廃止**（list/card で操作を1本化し、段1の高さ違いの凸凹を解消）。単一列ソートは list の見出しクリックで設定した状態がカードにも引き継がれる。
- **アクセシビリティ**: 表示切替は `role="radiogroup"`＋`aria-checked`＋**矢印キー**、カードは `role="listitem"`＋（`onRowClick` 時）`tabindex`＋**Enter/Space** で開ける。並び替えの項目名が省略（…）される時は **`title` 属性でフルネームをツールチップ表示**。
- カードは `.dt-cards`（`auto-fill` グリッド・`role="list"`）＋`.dt-card`。**行固定ピン（`.dt-pin-float`＝📍/📌）は左上角へ半分はみ出すフローティング**（標準カード `.dt-card`・専用カード `cardRaw` とも共通・固定中は青塗り＋カードに青リング）／**⋯ アクション（`.dt-card__tools`）は右上**（本文先頭要素へ自動で余白を確保）。`config.defaultView: 'card'` で初期表示をカードにできる。

### ⑪ クリックの標準挙動（行 / カード・決定 2026-08-13）
> **一覧の行・カードは「読むだけの静的表示」にしない**＝クリックで必ず何らかの主アクションが起きる。どの行/カードに何を起こすかは各画面が決めるが、**選び方は本標準で統一**する。

- **クリック可の可視化**: 主アクションを持つ行/カードは**ホバーで指カーソル（`cursor:pointer`）**にする。テーブル行は `clickable` 時に共通で `.dt-row--link`（`cursor:pointer`＋ホバー背景）、カードは `.dt-card--link`（既存）。機構は `config.onRowClick(r)` に束ねる（未指定＝クリック不可・カーソルも既定のまま）。
- **主アクションの選び方（既定→例外の順）**:
  1. **既定＝編集ダイアログを開く**（管理系一覧など。モーダル標準〔§4.1 相当〕で発行/編集モーダルを開く）。
  2. **その行の操作が 1 つだけなら、クリック＝その操作のショートカット**（＝「編集」しか無ければ編集、「管理する →」しか無ければ詳細へ、のように単一操作に直結）。⋯メニューが複数操作を持つ場合は既定（編集）に従う。
  3. **ナビゲーション型一覧（各行に対応する画面がある）は、主アクション＝その画面への遷移**。行の状態で分岐してよい（例＝クエスト一覧 SC-10：公開クエストは詳細 SC-12 へ／**下書きは編集ダイアログ SC-11**）。
- **例外＝破壊的操作しか無い行はクリック主アクションを割り当てない**（誤操作防止）。行/カード全体のクリックで削除・除外のような不可逆操作が起きるのは危険なので、**破壊的操作は ⋯メニューからのみ**とし、その行はクリック不可（指カーソルも出さない）。例＝**SC-90 メンバー一覧**（唯一の操作が「このグループから除外」＝破壊的なので、クリック割当なし・除外は ⋯ から `confirm` 付きで実行）。編集など非破壊の操作が1つでもあればそれを主アクションにする。
- **無効化された行**（操作不可・ロック）はクリック主アクションを持たせない（指カーソルも出さない）。例＝SC-93 の `system_admin` 行（SC-92 で管理）。
- **操作列との関係**: ⋯メニュー（`actions:true`）や単一リンクは**行内の明示ボタン**として引き続き出す（クリック主アクションは"最頻の1つへのショートカット"であって操作列の置き換えではない）。`a,button,input,select,label` 上のクリックは主アクションを発火しない（`shared.js` が委譲時に除外済み＝ボタンは各自の動作）。
- **アクセシビリティ**: クリック可カードは Enter/Space でも主アクション発火（`role="listitem"`＋`tabindex`・既存）。テーブル行のキーボード発火は将来課題（当面は行内リンク/ボタンで到達可能にする）。
- **どこに定義するか（正の置き場）**: **本標準（§4.5 ⑪）＝振る舞いの規約**（クリック可・指カーソル・単一操作ショートカット・既定は編集）。**各画面の飛び先＝ `screens/SC-xx_*.md` の「5. アクション・遷移」表**（「行/カードクリック｜条件｜遷移/結果」で1行）。**画面をまたぐ遷移＝ `画面遷移図.md`**。二重定義せず、飛び先は screens §5 を正とする。

## 4.6 用語・ラベル標準（横断・決定 2026-08-13）

> 全画面（`mocks/SC-*.html`）でユーザーに見えるラベルの表記を統一するための正典。**採用語＝正**とし、揺れ表記は採用語へ寄せる。個別画面の見た目・文言はここを参照する。**用語の意味・仕様の正はあくまで各設計文書**（`doc/要件定義/README.md`・`doc/データモデル.md`）で、本節は「同じ概念をどの語で表示するか」を定める。

### あえて統一しない（別概念・使い分け・維持）
> 以下は一見「揺れ」に見えるが、いずれも設計に裏付けのある使い分け（D-2 で精査・確認済み）。片方へ寄せない。

## 4.7 入力検証エラーの表示（横断標準・改定 2026-08-22）

> 旧 §4「入力バリデーション（2026-08-02）」＝インラインのみ・**最初のエラー項目へフォーカス**を**上書き**する（ユーザー決定 2026-08-22）。フォーム全般（モーダル/全画面フォーム/インライン設定）に適用。サーバーの検証は最終権威（コーディング規約 §1・§2.2）。エラー応答形＝API設計 `README.md` §1.7（`422 validation_error`・`errors[].field`）。

- **インライン中心（主チャネル）**: エラー要素は**枠を赤**（`.input`/`.select`/`.textarea` に `aria-invalid="true"`）＋**直下に赤字メッセージ**（`.field__error`・`role="alert"`）。サーバー 422 の `errors[].field` を**全件**マッピングして該当 `.field` に出す（先頭1件のみ表示は不可）。
- **上部サマリ（副チャネル）＝`.form-summary`**: フォーム先頭に集約表示（`role="alert"`・枠/背景は危険色）。用途＝(a) フィールドに紐づかない一般エラー（`409 conflict`・通信失敗・トークン失効等）、(b)「N件の入力エラー」の要約。各項目は該当フィールドへのアンカー可（任意・フォーカス自動移動はしない）。
- **検証タイミング＝送信時＋blur**: 送信時に全項目、各項目は **blur でも**個別検証する（入力途中＝`input`/`change` では出さない＝急かさない）。**エラー項目へのフォーカス自動移動はしない**（旧標準の「最初のエラーへフォーカス」は撤回・ユーザー決定）。
- **スクロールするダイアログでの可視化（追加 2026-08-22・ユーザー決定）**: 縦スクロールするフォーム（モーダル）では上部サマリ／インライン枠が画面外に隠れ「押したのに無反応」に見える。これを防ぐため送信失敗時に **3 チャネルを併用**する。理由＝検証エラーは"直すまで残る持続的情報"かつ"送信操作の直後に必ず気づかせる"必要があるため、スクロール位置に依存しない足元ヒントと、成功トーストと対称なエラースナックバーを重ねる。
  1. **上部サマリへスクロール**（`scrollIntoView({block:"nearest"})`）＝**フォーカスは奪わない**（§4.7 の no-focus-jump を維持・スクロールのみ）。
  2. **足元ヒント**＝送信ボタン近く（常時見えるフッター）に簡潔なエラー行（`.form-footer-error`「⚠ 入力エラーがあります。内容をご確認ください。」）。スクロールしても見える点が要。
  3. **エラースナックバー**（§14・`type:"error"`）＝**自動消滅させない**（`duration:0`＝✕クローズのみ・持続的情報のため）。文言はサマリの要約（1件はその文言・複数は「N件の入力エラーがあります。」）。
  - **部品（impl）**: `components/ui/useFormErrorNotice`（`summaryRef`＋`notify(summary)`＝スクロール＋スナックバー）＋`components/ui/FormFooterError`（`show` で足元ヒント）＋`FormSummary` の `innerRef`。クライアント検証失敗・サーバー 422 の双方で `notify()` を呼ぶ。
- **クライアント検証は補助・サーバーが最終権威**: 送信前のクライアント検証（必須/形式）は UX 補助であり、`422` の結果で上書き反映する。本質的な検証（重複・権限・Mass Assignment）はサーバー（コーディング規約 §1）。
- **多言語（i18n・必須）**: メッセージは **ja/en**（コーディング規約 §2.1）。**ハードコード日本語を置かず**、`(field, code)` → ロケール済みメッセージのカタログで解決する（例＝`login_id`＋`duplicate` → ja「このIDは使用済みです」/ en「This ID is already in use.」）。サーバー返却の生文言は開発時フォールバック。※フロントの i18n 機構は未整備（現状 ja 直書き）＝本標準確定に合わせて導入する（TBD §7）。
- **部品**: モック＝`shared.js` の `clearFieldErrors(root)` / `setFieldError(input, msg)` ＋ `.form-summary`（`shared.css`）。impl＝`components/ui/Field`（`error` 指定時に入力へ `aria-invalid` を付与）＋サーバー `errors[]` → `{field: msg}` 変換ヘルパ＋フォーム上部 `.form-summary`。サンプル＝`style-guide.html`「4b.」。
- **ステータス＝確定（2026-08-22・ユーザーが `style-guide.html`「4b.」を確認・承認）**: 以後の新規フォーム（SC-11 等）は本標準で実装する。既存フォーム（先頭1件のみ表示・サマリ無し・`aria-invalid` 未付与のもの）は、各画面に触れる機会に順次是正（＝折衷・ドキュメント作成規約の適用方針と同じ向き）。impl 側の共通部品（`components/ui/Field` の `aria-invalid` 付与・サーバー `errors[]`→`{field:msg}` 変換ヘルパ・`.form-summary`・i18n カタログ）は SC-11 実装時に用意済み（`components/ui/FormSummary`＋`lib/forms/validation`）。

## 4.8 編集不可フィールドの表示（横断標準・決定 2026-08-22）

> 「作成後は変更できない」項目（会社コード/DB識別子・クエストグループコード・編集時のクエストグループ 等）や、一時的に操作不可の入力を、**編集可能フィールドと一目で区別**する。ユーザー指摘＝readonly が編集可能に見えて分かりづらい、を受けた標準化。

- **見た目（`shared.css`/`design-system.css`）**: `.input`/`.textarea`/`.select` の `:disabled` と `[readonly]` に、**muted な塗り（`--color-surface-alt`）＋muted な文字色（`--color-text-muted`）＋弱いボーダー（`--color-border`）** を与える（編集可能＝白面 `--color-surface`＋濃いボーダー `--color-border-strong` と対比）。カーソルは **`disabled`＝`not-allowed`／`readonly`＝`default`**（読取専用は値の選択/コピーを許す）。ブラウザ既定の薄い `opacity` には頼らない（`opacity:1` で塗り/文字色で示す）。
- **使い分け**: **値を見せるが変更不可**＝`readOnly`（DOM に残す・値の参照/コピー可）。**そもそも操作させない/送信対象外**＝`disabled`。「作成後不変」項目は原則 `readOnly` を推奨（値は見せる）。
- **補足表示**: 不変理由は `hint`（`.field .hint`）で明示する（例＝「コードは作成後は変更できません。」「クエストグループは作成後は変更できません。」）。
- **適用済**: SC-92 クエストグループ編集（コード）・SC-11 クエスト編集（クエストグループ）。以後の新規フォームは本標準に従う。サンプル＝`style-guide.html`「4c.」。
