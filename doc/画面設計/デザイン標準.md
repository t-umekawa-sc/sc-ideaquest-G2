## 0. コンセプト（決定事項）

- **トーン = バランス型**。基本はクリーンな業務SaaS（企業の社内利用に耐える落ち着き・信頼感）。
  そのうえで **ゲーミフィケーション部分だけ「昔のドット絵ゲーム（レトロ・ピクセルアート）」** をコンセプトにアクセント化する **二層構成**。
- **カラー基調 = ブルー系**（信頼・定番）。
- **モック実装方式 = 共通CSS＋デザイントークン（CSS変数）**。依存なしでブラウザ直開き可、Next.js へトークン単位で移植しやすい。

### 二層の使い分け（重要）
| 層 | 使う画面/領域 | 見た目 |
| --- | --- | --- |
| **業務層（クリーン）** | ログイン・クエスト・アイデア・評価・チャット・フォーム全般・管理画面 | ブルー基調、角丸、ソフトな影、Noto Sans JP |
| **ゲーム層（レトロ）** | ダッシュボードのステータス・XP/レベル・コイン・ショップ・アバター/着せ替え・実績/バッジ・ランキング・XP獲得/レベルアップ演出 | ドット絵風、角丸なし、ハードシャドウ、DotGothic16、`.pixel*` クラス、**マテリアル＝CRTガラス**（下記） |

> ゲーム層は「ご褒美・楽しさ」を担う**アクセント**。業務フローの本体（入力・議論・評価）はクリーン層で迷いなく使えることを優先する。

### 1レイヤー＝1マテリアル（決定・2026-07-18）

**各レイヤーが持つ「材質」は1つだけ**にする。材質（ガラス/不透明など）は「業務か遊びか」を瞬時に伝える記号なので、1画面に複数の材質を混在させると統一感を損ない、可読性も落ちる。

- **ゲーム層 = CRTガラス**（半透明の暗ガラス＋走査線＋上端反射で“古いゲーム機の画面ガラス”を表現）。ドット感（角丸なし・ハード枠/影・ピクセルフォント）は維持。背景（`.app-bg` の背景画像など）を透かして映える。トークン `--pixel-glass-*`、適用先は `.pixel-panel` / `.pixel-dialog`。
- **業務層 = クリーンな不透明カード**（白面・角丸・ソフト影）。**ガラス化しない**（読ませる本文パネルの可読性と、背景画像スクリムとの整合を守る）。
- **業務パネルの区別は「材質」でなく「色アクセント」で行う**（例: ダッシュボードの下書き=グレー／未投票=プライマリ青／フォロー中=インフォ水色／参加中クエスト=クエスト色。白カード＋上端の細い光沢や見出し/左端のアクセント色バー）。

## 1. カラートークン

`shared.css` の `:root` に定義。主要なもの:

- **ブランド**: `--color-primary #2563EB`（hover `#1D4ED8` / active `#1E40AF` / soft `#EFF6FF`）
- **ニュートラル**: `--color-bg #F8FAFC` / `--color-surface #FFFFFF` / `--color-border #E2E8F0` / `--color-text #0F172A` / `--color-text-muted #64748B`
- **意味色**: success `#16A34A` / warning `#D97706` / danger `#DC2626` / info `#0EA5E9`
- **投票**: 賛成 `--color-agree #16A34A`（グリーン）/ 反対 `--color-disagree #DC2626`（レッド）
- **レアリティ（装備）**: コモン `#94A3B8` / 標準 `#3B82F6` / レア `#A855F7`（明面用）・**レア on-dark `#D8B4FE`**（CRTガラス等の暗面用。レベルと同方針）
  - ※ 装備アイテムはショップ/きせかえ＝ゲーム層（CRTガラス）で使うのが基本。ガラス上でレアの紫が沈むため、`.pixel-panel` 内の `.rarity-rare` は自動で on-dark に切替（明面で使う場合は `.rarity-rare` のまま。単独で暗面に置くなら `.on-dark` を付与）。
- **ゲーム**: XP `#FBBF24` / コイン `#F59E0B` / レベル `#8B5CF6`（明面用）・**レベル on-dark `#C4B5FD`（CRTガラス等の暗面上のレベル文字用）** / **SP（スキルポイント）`#34D399`** / cyan `#22D3EE` / magenta `#EC4899` / パネル背景 `#1E293B`
  - ※ CRTガラス（ゲーム層）の上に**紫のレベル文字**を置くとコントラスト不足で読みにくいため、暗面上のレベル表示は `--pixel-level-on-dark`（明るいバイオレット）＋薄い影を使う。白ピル（`.pixel-stat.level`）など明面はそのまま `--pixel-level`。

## 2. タイポグラフィ

- **本文フォント（業務層）**: `Noto Sans JP`（フォールバック system-ui）。
- **ゲームフォント（ゲーム層のみ）**: `DotGothic16`（日本語対応のドットフォント）。`.pixel` / `.pixel-panel` / `.btn-pixel` などに適用。
- **サイズスケール**: xs12 / sm14 / base16 / lg18 / xl20 / 2xl24 / 3xl30。行間 1.6。
- モックはCDN（Google Fonts）で読み込む。**実装では `next/font` に置換**する。

## 3. スペーシング / 角丸 / 影

- **余白**: 4px基準（`--space-1`=4 … `--space-16`=64）。
- **角丸**: 標準 8px（`--radius`）/ カード 12px（`--radius-lg`）/ 丸 `--radius-full`。**ゲーム層は 0**（`--radius-pixel`）。
- **影**: 業務層はソフト（`--shadow-sm/…-lg`）。ゲーム層は**ハードシャドウ** `--shadow-pixel: 4px 4px 0`。ボタン押下（`:active`）の“押し込み”は**業務層＝内側の影 `inset`**／ゲーム層＝ハードシャドウ縮小で表現。

## 4. コンポーネント（共通CSSに用意済み）

- **ボタン**: `.btn` / `.btn-primary` / `.btn-outline` / `.btn-danger` / `.btn-sm`、ゲーム用 `.btn-pixel`。
  - **状態**: hover（塗り/枠を一段濃く。`.btn-danger` も hover あり）／ **押下 `:active`**（業務層＝**1px 沈み込み＋内側の影 `inset`＋塗りを一段濃く**のクリーンな挙動。バリアントごとに `active` 色を定義：primary=`--color-primary-active`／danger=`--color-danger-active`／outline=`--color-border`／標準=`--color-border-strong`）。`prefers-reduced-motion` 時は沈みを止め色変化のみ。
  - **ゲーム層 `.btn-pixel`** はハードシャドウで**ガコッと沈む**別トーン（業務層のクリーンな沈みとは意図的に差別化）。
- **カード**: `.card` / `.card-title`。
  - **用途別カラーアクセント `.card-accent`**: 業務カードを**材質でなく色で区別**する標準（1レイヤー1マテリアル方針）。左端に色帯を出す（擬似要素なのでホバーの影/枠線変化に不干渉）。色は `--accent` で指定。ダッシュボードでは下書き=グレー（`--color-text-subtle`）／未投票=プライマリ青／フォロー中=インフォ水色／参加中クエスト=**クエスト色**（カードに `--accent` を設定すると `.quest-icon__char` のタイル色も同じ `--accent` に連動）。
- **テーブル / 一覧（標準）**: `.table`（`.table-wrap` で囲むと横スクロール＋カード見た目）。数値列は `.num`（右寄せ・等幅数字）、行遷移は `<tr class="row-link">`。
  - **セルは折り返さない（既定・決定 2026-08-02）**: `.table` のセルは **`white-space: nowrap`（折り返し禁止）が既定**。幅に収まらない場合は **`.table-wrap` の横スクロール**で見せる（テーブル枠ごとスクロール）。**例外の上書き**＝長い自由文セルは **`.cell-wrap`（折り返し許可）** または **`.cell-clip`（1行省略・末尾「…」＋`title` でホバー全文表示・`--cell-clip-max` で幅）** を明示的に付ける。
  - **複数値セルの省略（決定 2026-08-02）**: バッジ等が複数入るセル（所属クエストグループ 等）は **`.cell-tags`** でくるみ、**幅（`--cell-tags-max`・既定 16rem）に収まらない分は末尾に「…」を表示・ホバーで全件**（`title` 属性・`shared.js` の `applyCellClips()` が overflow を検出して `.is-clipped` を付与）。動的描画のテーブルは **各画面の `render()` 末尾で `applyCellClips()` を呼ぶ**。
  - **操作列は sticky 右固定＋⋯メニュー（決定 2026-08-02・ユーザー選択）**: 操作（編集/無効化 等）を持つ列は **`.col-actions`** を付け、**横スクロール時も行右端に貼り付く sticky 列**にする（左側に境界の影で本文と分離）。操作が複数ある管理テーブルは **⋯（ケバブ）メニュー `.rowmenu`** に畳んで列幅を最小化（`shared.js` が `.rowmenu__list` を `position:fixed` で配置＝`table-wrap` の overflow に隠れない）。**絶対座標フローティング（オーバーレイ）は非採用**（可変行高でのズレ・データ被り・キーボード/読み上げ順の崩れを避ける）。単一操作の列は sticky 列にボタン/リンクを直接置く（⋯不要）。
  - **行リンクと操作列の併用（F5・決定 2026-08-02）**: **操作列（編集/無効化 等のボタンを持つ列）がある管理テーブルは `row-link` にしない**（行クリック遷移とボタン操作が競合するため）。行全体を遷移させたい一覧（SC-10/SC-12 等）は `row-link` を使い操作列を持たない。やむを得ず併用する場合はボタンの click で `stopPropagation` する。
  - **アクセシビリティ（F3・決定 2026-08-02）**: `<thead>` の見出しセルは **`<th scope="col">` 必須**（行見出しがある場合は該当セルを `<th scope="row">`）。テーブルの意味が見出しだけで伝わらない場合は **sr-only の `<caption>`**（視覚的に隠す）で表題を付ける。**`row-link` は先頭セルを `<a>` 化してキーボードでも到達・実行可能にする**（`<tr onclick>` だけにしない）。状態バッジは色のみに依存せずテキストを併記（`.badge` の文言）。
  - **ソートの表現（F4・改定 2026-08-13）**: **「4.5 一覧の操作標準（DataTable）」に統合**。列見出しクリックの単一列ソート（`aria-sort`）＋複数キーの詳細ソートを**共通部品として標準化**（旧「ツールバー `select` 一本化／列ヘッダソートは MVP 非採用」を**上書き**）。詳細は §4.5。
  - **件数の単位（F6）**: `.list-count` は**原則「N件」**。人数が主体の一覧（アカウント/メンバー一覧 等）は「N名」も可。同一画面内で単位を混在させない。
  - **レスポンシブ（F7）**: 列が多いテーブルは `.table-wrap` の**横スクロールで可**（MVP）。モバイル最適化（優先列の折り返し・カード化）は将来。まず横スクロールで破綻しないことを担保する。
- **一覧ツールバー（標準・`.list-toolbar`）**: **一覧（テーブル/カード）には検索・フィルター・並び替えを標準で付ける**。左＝`.filters`（横断検索ボックス＋「詳細絞込」「詳細ソート」＋適用中の要約チップ）、右＝`.tools`（**表示密度**＋**列設定**＋**エクスポート**）。**件数と表示件数は表下部のページングバー（`.dt-footer`）**にまとめる（§4.5 ③）。テーブル一覧は **§4.5 一覧の操作標準（DataTable）** に集約（`shared.js` の `DataTable`）。**データ量が少なければクライアント側、多ければサーバー側でフィルター/ソート/ページング**（実装で判断）。
  - **「絞り込みをクリア」（F1・必須・決定 2026-08-02）**: **検索語・状態フィルタ・並び替え等が 1 つでも既定から変化している時は「絞り込みをクリア」ボタンを表示**（`.filters` 末尾・既定は `hidden`）。押下で全フィルタを初期化。フィルタを持つ一覧は SC-10/SC-12 に加え **SC-90/91/92/93 等でも必須**（従来は一部のみ実装＝標準として全一覧に統一）。フィルタが検索のみの一覧でも、検索語が入っている間は表示する。
  - **0 件表示**: `.list-empty` で空表示（絞り込みで 0 件になった場合は「絞り込みをクリア」への導線も添える）。
- **ページネーション（標準・`.pagination`・F2・改定 2026-08-13）**: 件数が増える一覧（特に管理系 SC-91/92/93）に付ける標準部品。**オフセット方式＝番号リンク**「`« ‹ 1 … 4 [5] 6 … 20 › »`」（`«`最初/`‹`前/`›`次/`»`最終・現在ページは `aria-current="page"`・現在±2＋先頭/末尾＋`…`）。API `?page`/`per_page`＋`page_info.total`（API設計 §1.8）と対応。**カーソル方式**（チャット等・大量/追記型）＝`.pagination--more` の「もっと見る」（`page_info.next_cursor`）。`.list-count`（総件数）と併用。詳細は §4.5。実体は `mocks/shared.css` の `.pagination`。
- **バッジ**: `.badge` / `.badge-success` / `.badge-danger` / `.badge-muted`。投票表示 `.vote-agree` / `.vote-disagree`。
- **レアリティ枠**: `.rarity-common/standard/rare`。
- **ユーザアバター**: `.avatar`（`.sm`/`.lg` でサイズ可変）。`.avatar__img`（画像・なければ `.placeholder` でイニシャル）＋ `.avatar__level`（**下部中央にレベル表示**）。`data-name` 属性＋`tabindex="0"` で**ホバー/フォーカス時にユーザ名ツールチップ**。複数並べるときは `.avatar-group`（少し重ねる）。投票の記名モード・パーティー一覧・チャット等で使用。
- **カラースウォッチ**: `.swatches` / `.swatch`（`role=radiogroup`/`role=radio`・`--sw` に色）。**プリセットパレットからの単一色選択**（選択にチェック表示・focus-visible リング）。**クエストカラー**の設定に使用＝選んだ色が `.card-accent` の左帯と**未設定クエストアイコンのタイル色 `--accent`** を駆動（設定は SC-11）。パレットは 600 レベルの10色（ティール/ブルー/バイオレット/インディゴ/グリーン/アンバー/ローズ/シアン/オレンジ/スレート）。
- **クエストアイコン**: `.quest-icon`（`.sm`/`.lg` でサイズ可変）。**カスタム画像**（`.quest-icon__img`）を設定できる。**未設定時のフォールバック＝件名の頭文字タイル（`.quest-icon__char`）＋右下に所有者アバターを重ねる（`.quest-icon__owner`）**。**タイル色は `--accent`（クエスト色）に連動**（親カードで `--accent` を設定すると `.card-accent` の左帯とアイコン色が揃う。未指定はプライマリ）。クエストヘッダー（SC-12）・参加中クエストカード（SC-01）・クエスト一覧など、クエストを表す箇所で共通利用。実体は MinIO、`Quest.icon_image_path`。設定は作成/編集モーダル（SC-11）。
- **フォーム**: `.field` + `.input` / `.textarea` / `.select`、必須マーク `.req`、補足 `.hint`。
- **コンボボックス（選択）**: 既定は**ネイティブ `.select`**（a11y・モバイルに強い。本体は指ポインター）。ただし**候補(option)はOS描画のため cursor 制御不可**。候補までホバーの指ポインター/ハイライト/装飾を効かせたい場合は**カスタム `.combobox`**（`<button>＋role=listbox`）を使う。挙動は `mocks/shared.js`（`[data-combobox]` を初期化・↑↓/Enter/Escキー対応）。候補は自前要素なので `cursor:pointer` が確実に効く。
- **複数選択コンボボックス**: `.multiselect`（`[data-multiselect]`）＝**オートコンプリート絞り込み＋選択チップ**の複数選択部品。選択済みは control 内に**チップ表示（`.multiselect__chip`・×で解除）**、入力で候補を絞り込み **↑↓/Enter** で確定、空欄で **Backspace** でも直前チップを解除。**`data-free="true"` のモード**では候補に無い手入力文字列も **Enter で追加**（自由入力タグ＝`.is-custom` でグレー表示、候補由来と区別）。挙動は `mocks/shared.js`（`[data-multiselect]` を初期化）。**単一選択モード `data-single="true"`**＝チップにせず入力欄に確定値を表示するオートコンプリート付きセレクト（候補のみ・1つだけ）。**使い分け**: 自由入力あり複数＝**クエストのカテゴリー（複数可）・アイデアの利害関係者**／候補のみ複数＝**マスタから複数選択**（パーティー候補 等）／単一選択＝**クエストグループ（1クエスト＝1グループ）**。
- **チェックボックス**: `.checkbox`（`<label class="checkbox"><input type="checkbox"> 文言</label>`）。**モダン設計の原則に準拠**:
  - ネイティブ `<input>` を `appearance:none` で装飾（キーボード/スクリーンリーダー対応を維持）。
  - **ラベルごとクリック可・ラベル/ボックス両方が指ポインター**（無効時 `not-allowed`）。
  - 状態: hover（枠がブランド色）/ **focus-visible（リング）** / checked（ブランド色＋白チェック）/ **indeterminate**（横棒・JSで設定）/ disabled。
  - ボックスは**ラベル1行目に揃え**、複数行でも崩れない。モーションは ~120ms・`prefers-reduced-motion` で無効。
  - **使い分け**: フォーム内の選択・同意・複数選択はチェックボックス。**即時反映のON/OFF設定（管理画面のMFA有効・投票匿名化 等）はトグルスイッチ `.switch`** を用いる。
- **トグルスイッチ**: `.switch`（`<label class="switch"><input type="checkbox"><span class="switch__track"><span class="switch__thumb"></span></span><span class="switch__text">文言</span><span class="switch__state">ON/OFF</span></label>`）。**即時反映の ON/OFF 設定**向け（管理画面の会社設定＝MFA必須・投票匿名化・管理者への投票者開示 等）。ネイティブ checkbox を装飾（キーボード/SR対応維持）・ラベル/トラック両方 pointer・**focus-visible リング**・checked でブランド色＋ノブ移動・disabled は淡色。状態語（ON/OFF）は任意で併記。モーションは `prefers-reduced-motion` で無効。**チェックボックスとの違い**＝スイッチは「設定の即時 ON/OFF」、チェックボックスは「フォーム送信時に確定する選択/同意」。SC-91 会社設定で使用。

## 4.5 一覧の操作標準（DataTable・決定 2026-08-13）

> テーブル一覧に**ソート／絞り込み／ページング／列幅調整／列の表示・非表示・並べ替え／CSVエクスポート／表示密度／行の固定**を一括で付与する会社標準。実体＝`shared.js` の `window.DataTable`（`DataTable.init(root, config)`）＋`shared.css`（`9y` セクション）。ライブ実例＝`mocks/SC-91_システム管理.html`。
>
> **サーバー処理前提**: UI はクエリ条件（複数ソートキー・項目別フィルタ・ページ番号・ピンID）を組み立てるだけで、並びの最終決定・件数・CSV生成はサーバー（既存の `created_at,id` 決定的順序と整合）。モックは全件クライアント保持で挙動を再現する。**この標準は各一覧APIに「複数ソートキー・項目別フィルタ・CSVエクスポート・ピンID取得」というクエリ契約を要求する**（実装接続時に backend を拡張。CSV／行固定のページ跨ぎは backend 依存）。

**共通の可視化ルール**: 詳細ソート／詳細絞込が有効な時は ①ボタンに**バッジ（件数・`.dt-badge`）**、②ツールバー下に**要約チップ行（`.dt-chips`／各チップ ✕ で個別解除）**、③**「すべてクリア」**で全解除。

**操作列（アクション）**: 列定義に `actions: true`（`locked`・末尾固定・`.col-actions` sticky 右）を置き、`render` で **単一リンク**（例「管理する →」＝SC-91）または**⋯ ケバブメニュー（`.rowmenu`＝複数操作）**を描画。RowMenu の開閉は `shared.js` が委譲処理（動的行でも動作・`position:fixed` で `.table-wrap` の overflow に隠れない）。実処理は `menuitem` の `data-*` を各画面の委譲ハンドラで。サンプル＝`style-guide.html`「9.」の ⋯（編集/複製/削除）。**メニュー項目のホバー/フォーカスには標準で ▶ 選択カーソルが出る**（後述「メニューの選択カーソル」）。

### ① ソート
- **単一列**: 並べ替え可能な列は見出しクリック（`aria-sort`）。**昇順 → 降順 → 解除（既定順）** の3段トグル。インジケータ＝非アクティブ`⇅`／`▲`／`▼`。同時に1列。
- **詳細ソート（複数キー・`.sort-builder`）**: 「詳細ソート」ボタン→**左右2ペインのダイアログ**。右＝対象外の項目、左＝並び替え条件（上ほど優先）。右をクリックで**FLIP アニメで左末尾へ追加**、左は各キーに昇順/降順（`.seg`）＋**▲▼で優先順位入れ替え**＋✕で除外（右へ戻る）。**適用中は単一列ソートを無効化**（バッジで明示・クリアで復帰）。並べ替えは▲▼標準（ドラッグは任意拡張）。`prefers-reduced-motion` でアニメ無効。

### ② 絞り込み
- **横断テキスト検索**: ツールバー左に常時表示（対象項目をプレースホルダに明示）。
- **詳細絞込（項目別）**: 「詳細絞込」ボタン→ダイアログ。項目型に応じた入力＝テキスト（含む）／区分（チェック複数）／数値（範囲）／日付（範囲）。横断検索と **AND 結合**。

### ③ ページング（下部ページングバー `.dt-footer`）
- 表の下に**ページングバー**を置き、**件数ラベル（左）・番号ページャ（中央）・1ページの表示件数セレクタ（右）**をまとめる。件数・表示件数は上部ツールバーには置かない（操作系の近くにまとめる）。
- 番号リンク＋前後＋最初/末尾＝`« ‹ 1 … [5] … 20 › »`（現在±2＋先頭/末尾＋`…`・現在は `.is-current`＋`aria-current`）。1ページに収まる時はページャ非表示（件数・表示件数は残す）。カーソル方式は `.pagination--more`。
- **1ページの表示件数セレクタ**（`表示 N 件`）＝`perPageOptions`（既定 `[10,20,50,100]`）から選択。**ユーザー設定として保持**（`localStorage`）。現在値は選択肢に必ず含める。

### ダイアログ（詳細ソート/詳細絞込）
- いずれも**標準モーダル**（`.modal.sectioned`＝ヘッダー/本文/フッター）に乗る＝**ドラッグ移動＋最大化（⤢）＋Esc/バックドロップ閉じ＋フォーカストラップ**を `shared.js` が共通適用。**動的生成モーダルにも自動適用**（`shared.js` が後から追加された `.modal`／`.modal--maximizable` を MutationObserver で拾って初期化）。サンプルは `style-guide.html`「10. ダイアログ」。

### ④ 列幅の手動調整
- 見出し右端の**ドラッグハンドル（`.dt-resizer`）**でリサイズ（`table-layout:fixed`・最小64px）。ラベル領域＝ソート／右端＝リサイズでヒット領域を分離。**ダブルクリックで既定幅に**。あふれは省略。

### ⑤ 列の表示/非表示・⑥ 並べ替え（「列設定」メニュー `.col-menu` に集約）
- 「列設定」ボタン→ポップオーバーで**全列のチェック（表示/非表示）＋▲▼で並べ替え**。**主要名称列と操作列は `locked`＝非表示不可・並べ替え対象外**（名称列は先頭固定・操作列は末尾固定）。**列幅をリセット／既定に戻す**を同メニューに同居。
- 非表示列に有効なソート/絞込条件がある場合は**条件を維持し要約チップに残す**（隠しても効いていることを明示）。

### ⑦ CSV エクスポート
- 「エクスポート」ボタン→**現在の絞り込み・ソート結果の全件／表示中の列・列順**を **UTF-8（BOM付・Excel互換）** で出力。実装は**サーバー側生成**（同条件＋`format=csv` を受ける export EP＝backend 依存）。管理系のエクスポートは**監査ログ対象**。大量時の非同期化は将来。

### ⑧ 表示密度
- `標準 / コンパクト` の2段セグメント（`.table--compact`）。**全画面共通のユーザー設定**として保持。タッチ端末はタップ領域を確保。

### ⑨ 行の固定（ピン）＋固定ヘッダー
- 行頭の**ピンアイコン（`.dt-pin-toggle`）**でトグル→**固定行セクション（`tr.is-pinned`・上部・`position:sticky`）**にまとめ、**スクロール中も・全ページで常時表示**（絞り込み・ページングを override）。固定件数は**上限（既定5件・`maxPins`）**。ページャ／件数は非固定の母集合が対象（固定は別枠表示＋要約）。sticky を効かせるため `.table-wrap.dt-scroll`（スクロールコンテナ）＋**固定ヘッダー**（`thead` sticky）が前提。
- **保持（永続）**: 列順・表示/非表示・列幅・密度・ピン行IDは **`localStorage`（画面×列単位・`storageKey`）** に保存しログイン跨ぎで維持（将来はユーザー設定へ格上げ）。検索/ソート/絞込/ページはセッション内（ビュー状態）。

### 適用状況
- **SC-91 会社一覧＝適用済（ライブ実例）**。他の管理系一覧（SC-90/92/93）・一般一覧（SC-10 等）へ順次適用。**列定義（`columns`）とデータ（`data`）を宣言するだけ**で全機能が付く。

> **原則**: ①同一概念は同一語（表記揺れを作らない）。②業務層の語は明確さ優先で寓話化しない（ゲーム感は XP/コイン/魔法/ランキング等のゲーム層で担う＝§0 二層の使い分け）。③別概念は無理に統一しない。

### 状態・ステータス
- **会社（テナント）状態＝2値**（`company_status`＝`active`/`suspended`・データモデル.md）: `active`→**「有効」**、`suspended`→**「停止」**。**「準備中」（3値目）は設計外＝不採用**（モックから除去）。
- **アカウント状態＝2値**（`account_status`＝`active`/`disabled`）: `active`→**「有効」**、`disabled`→**「無効」**。「（論理削除）」は補足文のみで、バッジ表示は「無効」。

### あえて統一しない（別概念・使い分け・維持）
> 以下は一見「揺れ」に見えるが、いずれも設計に裏付けのある使い分け（D-2 で精査・確認済み）。片方へ寄せない。

- **並び替え（行のソート）** ≠ **並べ替え（列の順序変更）** … 別操作。SC-10/12/30 のソートは「並び替え」、DataTable の列操作は「並べ替え」で既に正しく使い分け済み。
- **所有（ショップ／装備＝購入して持つ）** ≠ **獲得（バッジ＝達成して得る）** … 別概念。SC-30/31＝「所有済み／未所有」、SC-40＝「獲得／未獲得」で各ドメイン内は一貫。無理に片方へ寄せない。
- **装備中／所有済み／解放済み／獲得** … アバター装備・アイテム所持・スキル解放・バッジ獲得はそれぞれ別の状態なので語を分けて維持する。
- **パーティー（クエストの参加者集団＝集合名詞）** vs **参加メンバー／メンバー（個々の参加者）** … 集団を指すなら「パーティー」、個人なら「メンバー」。SC-11「参加メンバー（パーティー）」は設計どおりの併記（要件定義 FR-20）。**クエストグループの所属者も「参加メンバー」**（SC-90＝`quest_group_members`・パーティーとは別概念）。
- **メッセージ（チャット投稿の実体・UI＝`ChatMessage`・SC-24 の入力欄/スレッド）** vs **コメント（投稿という行為・権限・通知の呼称）** … 要件定義が両語を使い分け（「コメント作成権限＝グループチャットでのコメント」README.md:226／「メッセージ投稿」README.md:288／通知「新規コメント」）。統一しない。
- **期限日（クエスト締切の正式なフィールド名＝FR-20／Quest エンティティ。フォーム・詳細の項目ラベル）** vs **締切（同じ日付の表示上の短縮語＝一覧列・カード・「締切が近い順」）** … 設計の用語集どおりの使い分け（README.md:243）。さらに **タイムリミット（アイデアの想定期限・README.md:251）** は別概念。

## 5. レイアウト規約

- 中央寄せコンテナ幅 `--container: 1120px`、ヘッダー高 `--header-h: 56px`。
- ブレークポイント: 768px 以下でモバイル（`.row` を縦積み、コンテナ余白を縮小）。
- 各画面モックの基本骨格:
  ```html
  <link rel="stylesheet" href="shared.css">
  <header class="app-header"><div class="container between">…</div></header>
  <main class="container"> … </main>
  ```

## 6. モック運用ルール

- 1画面 = 1ファイル `doc/画面設計/mocks/SC-xx_<名前>.html`。必ず `shared.css` を参照（トークンを画面内に直書きしない）。
- 画面固有の微調整のみ各HTMLの `<style>` に書く。**再利用する見た目は `shared.css` へ昇格**。
- モックは静的プロトタイプ（確認用）。ロジックは持たない。実装（Next.js）とは別管理。
- 新しい色・部品が必要になったら、まず本ドキュメント＋`shared.css` にトークン/クラスを追加してから使う。
