# ADR-0001 認証・セッション基本パラメータ

- ステータス: **確定（2026-08-08 ユーザー承認）** / 値は運用で調整可（下記 [採用] 参照）
- 対象スライス: ドメイン A「状態A＝パスワードログイン」（MFA OFF・初回/再設定PW は範囲外）
- 関連: `doc/API設計/A_認証・セッション.md`（A.0/A.1/A.6・正）・`doc/API設計/README.md` §1.4/§1.7・`doc/WEBアプリ開発時のセキュリティ対策一覧.md`

> 目的＝ログインスライスを実装するために **API設計で「実装時に確定」とされていた具体値**（TTL・ハッシュパラメータ等）を決める。
> 設計上の方針（Cookie 属性・CSRF 方式・列挙耐性・セッション固定対策）は A.0 が正で、本 ADR はそれを**変更せず具体値を埋める**。
> 各項目に **[採用]（この値で実装）** か **[暫定・要確認]（レビューで確定）** を付す。

---

## 1. コンテキスト

A.0/A.1 は「Cookie＋Redis 不透明セッション」「ダブルサブミット CSRF」「セッション固定対策＝認証成功時に新ID」等の**方針**を確定済み。一方で TTL・パスワードハッシュのコストパラメータ・レート制限閾値などは「実装時に確定（SC-00 §10）」として保留されている。ログインを動かすにはこれらの具体値が要る。

## 2. 決定

### 2.1 API ベースパス
- **[採用]** すべての API は `/api/v1/` 配下（SC-00 §8 と一致）。認証は `/api/v1/auth/*`。

### 2.2 セッション（Redis・不透明トークン）
- **[採用]** トークン＝CSPRNG 32バイトを base64url（≒256bit・A.0「意味を埋め込まない」）。Redis キー＝`sess:{token}`。値＝`{account_id, company_id, system_role, locale, user_id, created_at, last_seen_at, last_login_bonus_date}`（A.6／A.1 のログインボーナス最適化フィールドを含む）。
- **[採用]（2026-08-08 ユーザー確認・運用で調整可）** 非信頼端末セッションの寿命＝**アイドル 30分（スライディング延長）／絶対上限 12時間**。理由＝短命でセッション奪取の窓を絞りつつ、勤務中の連続操作は延長で維持。信頼端末の長期ローリングは MFA/信頼端末スライスで別途決定。
- **[採用]** 認証成功時は**必ず新トークンを発行**（固定化対策・A.0）。ログアウトは Redis から即削除＋Cookie 失効。

### 2.3 Cookie（属性は A.0 が正・ここは運用値）
- **[採用]** `iq_session`＝httpOnly / Secure / SameSite=Lax / Path=/ / Domain 未指定（ホスト限定）。`iq_csrf`＝**非httpOnly** / Secure / SameSite=Lax（ダブルサブミット）。
- **[採用]** ローカル開発（HTTP）では `Secure` を**設定で無効化可**にする（`COOKIE_SECURE` env）。本番は常に `true`。localhost の別ポート間は same-site のため SameSite=Lax で成立（CORS は別途許可）。

### 2.4 CSRF / Origin
- **[採用]** 状態変更系は `X-CSRF-Token` ヘッダ＝`iq_csrf` 値一致を必須＋Origin/Sec-Fetch 検証（A.0）。`POST /auth/login` は CSRF 免除・**Origin/Sec-Fetch のみ**（A.1）。`GET /auth/session` は検証不要。

### 2.5 パスワードハッシュ
- **[採用]（2026-08-08 ユーザー確認・運用で調整可）** **Argon2id**、パラメータ＝`m=19456 KiB (19 MiB), t=2, p=1`（OWASP 推奨の下限ベースライン）。理由＝広く推奨される安全側の既定。本番のマシン性能に応じて後で引き上げ可（ハッシュに埋め込まれるので段階移行可能）。
- **[採用]** 照合失敗・アカウント不在・`password_set=false` は**一律 401 `unauthenticated`**（列挙耐性・A.1）。存在しないアカウントでも**ダミーハッシュで照合を実行**しタイミング差を作らない。

### 2.6 レート制限（ログイン）
- **[採用]（2026-08-08 ユーザー確認・運用で調整可）** `POST /auth/login` を **(IP＋login_id) 単位で 10回/5分**を超えたら `429 rate_limited`＋`Retry-After`（総当りの一次抑止＝ベースライン防御）。
- **[委譲・決定先=A 設計]** **アカウント一時ロック方針**（連続失敗での N 回→T 分ロック・解除経路等）は本スライスでは実装せず、**MFA/セキュリティ・ハードニングのスライスで確定**する（2026-08-08 ユーザー決定）。理由＝ロックは**列挙耐性との衝突**（実在アカウントのみロック=存在漏洩）・**DoS 悪用**（他人IDの故意ロック）・**解除経路**（自動T分/管理者/PW再設定）・**OTP 連続失敗→pre-auth 失効**（A.0/§9 で既に連動）と絡み、MFA と同じ「アカウントのセキュリティ状態」を触るため一緒に設計するのが手戻りが少ない。最終 SoT＝`A_認証・セッション.md`（レート制限/総当り対策の節）、具体値は後続 ADR。本スライスの基本レート制限（上記）で無防備にはならない。

### 2.7 MFA / パスワードポリシー（範囲外の明示）
- **[採用・範囲外]** 本スライスはシード会社を `mfa_required=false` とし、login は `authenticated` 分岐のみを対象にする（`mfa_required` 分岐は MFA スライスで）。
- **[採用・範囲外]** パスワードポリシー（最小長・文字種＝SC-00 §6・A.9-④）は**PW設定/再設定スライス**で確定。login はポリシー検証をせず既存ハッシュの照合のみ。

### 2.8 リクエスト ID / エラー形式
- **[採用]** すべての応答に `request_id` を付与し、エラーは `application/problem+json`＋`code`（README §1.7）。**エラーcode の網羅は OpenAPI が SoT**（別レジストリは作らない＝§1.7）。

## 3. 検討した代替案（不採用）

- **JWT ステートレスセッション**＝不採用。失効（logout-all・強制ログアウト・ロール変更＝A.9-③）を即時に効かせにくく、A の「Redis 不透明セッション」方針に反する。
- **CSRF を SameSite=Strict のみで担保**＝不採用。外部リンク流入で毎回ログアウト相当になり UX を損なう。A.0 の Lax＋トークン＋Origin の多層防御を維持。
- **エラーコード一覧の独立 md**＝不採用。§1.7 が OpenAPI を SoT と規定済みで二重管理になる。

- テスト＝`doc/テスト/A_認証.md` の期待値（Cookie 属性・401 一律・Set-Cookie）に反映。
