# 情報インプット 動的タブ機能 — 設計ドラフト（会社が束ねる情報の器）

> 状態: **ドラフト第一版（2026-10-08）**。方向と主要3論点のうち本機能に関わる2点を確定（§11）＝(1) **1情報＝1タブ（単一所属）**・(2) 既定タブ「**全般**」はシステム予約で削除不可・(3) タブ管理は **会社アカウント管理者＋情報判定権限者（`info_curator`）**。実装未着手。参照表記は [ドキュメント作成規約](../規約/ドキュメント作成規約.md) 準拠（文書間参照は文書名接頭辞）。
> 関連正本＝[コーディング規約](../規約/コーディング規約.md)（§2 セキュリティ・§2.3 DRY・§3.4 バックエンド4層）・[データモデル](../データモデル.md)・[API設計 README](../API設計/README.md)・[情報インプット機能 設計](情報インプット機能_設計.md)（本機能はその拡張）。
> 姉妹ドラフト＝[カメリオAPI連携 設計](カメリオAPI連携_設計.md)（本機能で定義する **connector タブ** へ外部記事を投入する）。

## 0. 位置づけ・狙い（なぜ「タブ」か）

- 現状の情報インプット（[情報インプット機能 設計](情報インプット機能_設計.md)）は、**「データのまとまり」を表現できていない**。分類(#3 単一)・カテゴリ(#8 複数)・大分類(#6) 等は「その情報が**何か**」を表す**属性軸**で、「どの束（棚）に置くか」という**器**が無い。
- そこで **会社が動的に「タブ」を追加**し、情報をそのタブ配下に束ねられるようにする。例＝「**情報共有**」タブ（社内で共有したい情報）、「**カメリオAPI**」タブ（外部連携で自動取得した記事）。
- **タブ＝情報の第一級コンテナ**（1情報＝1タブ）。既存の属性軸とは**直交する新軸＝「束ね／一覧の第一次ナビ」の軸**。属性は「何か」、タブは「どの棚か」。
- **なぜ属性拡張でなくタブか（設計判断）**＝SC-50 一覧の**第一次ナビ（タブ）**として会社が自由に棚を作れる＝情報共有・用途別の運用を**会社裁量**に委ねられる。既存 enum の「会社ごと拡張は Phase2」（＝属性のテナント拡張はマスタ管理UIが要るため見送り・[情報インプット機能 設計](情報インプット機能_設計.md) §11-②）の懸念を、**「属性の会社拡張」ではなく「器（タブ）の会社拡張」**として一点だけ開ける。属性体系は固定のまま触らない＝後方互換・分量最小。
- ISO56001 上は **§7.1.6 知識/インテリジェンスのマネジメント**の運用補助（情報プールを会社の運用単位で棚卸しできる）。

## 1. タブの性質（確定・§11）

- **1情報＝1タブ（単一所属）**＝`info_items.tab_id`（会社DB・FK→`info_tabs`・NOT NULL・default＝「全般」）。
  - **なぜ単一**＝UIの「**タブ配下に登録する**」比喩に素直で最小。属性軸（#3 単一／#8 複数）と役割が被らず、一覧の第一次ナビとして一意に決まる。横断の集計・類似リンクは会社横断プール（タブ非依存・§5）で担保済みなので、器は単一で十分。
- **既定タブ「全般」＝システム予約**（会社ごと seed で 1 行・`kind='system'`）。**アーカイブ不可・名称変更不可**（予約語）。未指定登録・**既存情報の移行先**（後方互換＝現存 `info_items` は全般へ）。
- **予約語（確定）**＝**「全般」「カメリオ連携」はシステム予約語**＝ユーザーはタブ名に**指定不可**（作成/改名時に検証で弾く）。同名作成も**エラー**（active 一意）。**表示はユーザーが入力したタブ名をそのまま表示**（固定ラベル化・ローカライズはしない）。
- **タブ種別 `kind`**：
  - `system`＝予約（全般）。アーカイブ/改名不可。
  - `user`＝会社が作る通常タブ（情報共有 等）。
  - `connector`＝外部連携（カメリオ連携）が**API で記事を投入する受け口タブ**。**制約は「名前が予約語」である点のみ**＝**ユーザーも手動で情報/続報を登録してよい**（ただの受け口・§3）。連携 ON で自動生成／**OFF 後も配下に情報が残る限り表示を維持**（姉妹ドラフト §4.3）。
- タブは **会社（テナント）単位のマスタ**＝会社 DB `info_tabs`。会社横断の知識プールという情報インプットの原則（[情報インプット機能 設計](情報インプット機能_設計.md) §0）はタブ導入後も不変＝タブは**プール内の棚**であって、別プールを作るわけではない。

## 2. データモデル（新規・次段で正式反映）

### 2.1 `info_tabs`（情報タブ・会社DB）

| 物理名 | 論理名 | 型 | 制約 / 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `id` | ID | uuid | PK | |
| `name` | タブ名 | text | NOT NULL | 会社内で一意（active 範囲・**同名はエラー**）。**ユーザー入力値をそのまま表示**。予約語「全般」「カメリオ連携」は指定不可 |
| `kind` | 種別 | text | NOT NULL, default `user` | `system`（全般・予約）／`user`／`connector`（§1） |
| `sort_order` | 並び順 | integer | NOT NULL | 一覧の第一次ナビの左右順（ドラッグ並べ替え） |
| `status` | 状態 | text | NOT NULL, default `active` | `active`／`archived`（論理削除・物理削除なし＝既存方針） |
| `icon_image_path` | アイコン | text | NULL可 | 任意（QuestIcon 方式＝画像 or 頭文字＋色・[[strategy-picker-show-icons]] と同系） |
| `color` | 色 | text | NULL可 | 任意（プリセットパレット） |
| `description` | 説明 | text | NULL可 | タブの用途メモ（管理者向け） |
| `connector_ref` | 連携種別 | text | NULL可 | `kind='connector'` のときのみ＝`kamelio` 等（ホワイトリスト） |
| `created_by_id` | 作成者 | uuid | FK→users | |
| `created_at`/`updated_at` | 監査 | timestamptz | NOT NULL | 共通監査列 |

- インデックス: `UNIQUE(name) WHERE status='active'`（active タブ名の会社内一意＝**同名エラー**）、`(status, sort_order)`。**予約語「全般」「カメリオ連携」はアプリ検証で作成/改名を拒否**。
- seed＝会社作成時に「全般」1 行（`kind='system'`・`sort_order=0`）。既存会社は backfill migration で付与（§10）。

### 2.2 `info_items.tab_id`（既存表に列追加）

- `tab_id` uuid NOT NULL default（全般タブ）・FK→`info_tabs`。index `(tab_id, status, created_at)`（タブ別一覧＝新着順）。
- **後方互換**＝既存行は migration で全般タブへ割当。属性体系（#1〜#14）は**一切不変**。

## 3. 運用・権限（確定・§11）

- **タブの作成/名称変更/並べ替え/アーカイブ**＝**`company_account_admin` ＋ `info_curator`**。
  - **なぜこの2者**＝会社の統制点（管理者）と、情報プールの運用担当（curator・既存のキュレーション/アーカイブ権と同軸）に揃える＝既存権限体系に整合（[情報インプット機能 設計](情報インプット機能_設計.md) §11-①）。一般ユーザーは**登録時に「登録先タブ」を選ぶのみ**。
- **アーカイブ＝論理削除**（確定）＝`status=archived`・**物理削除なし**。**`info_items.tab_id` を NULL に更新しない**（NOT NULL 維持）。**配下に情報が 1 件でもあればアーカイブ不可＝削除エラー**（先に各情報を別タブへ付け替えて空にしてから）。**自動の一括付け替えはしない**（意図しない移動を防ぐ）。
- **`connector` タブ（カメリオ連携）**＝連携 ON で自動生成される**受け口タブ**。**ユーザーも手動で情報/続報を登録できる**（受け口の制約は無し＝名前が予約語である点のみ）。**連携 OFF 後も配下に情報が残ればアーカイブされず表示を維持**（空なら任意でアーカイブ可）。再 ON は同一タブを再利用（`connector_ref` 一致）。
- **タブは「分類」であり「閲覧制限」ではない（#4 確定）**＝MVP のタブに可視範囲は無く**会社内 active 全員が全タブ閲覧可**。「情報共有」「○○限定」等の名前で**機密の仕切りと誤解させない**UI 文言を添える（タブ別可視範囲は §8 Phase2）。
- **タブ付け替え**＝`info_curator` のキュレーション操作の一部として可（属性付与と同じ編集権）。

## 4. 画面（SC-50 拡張・2026-10-08 UI 確定）

> 検討モック＝[`mocks/_サブタブ_検討.html`](../画面設計/mocks/_サブタブ_検討.html)（サブメニュー型サブタブ・確定形）／[`mocks/_サブタブ溢れ_検討.html`](../画面設計/mocks/_サブタブ溢れ_検討.html)（溢れ時＝案C）。比較の経緯は `_タブUI比較_検討.html`/`_タブUI比較2_検討.html`（残置）。いずれも Playwright でレンダリング目視済み（[[verify-ui-visually-before-done]]）。

- **2階層ナビ（確定）**＝**トップタブ「🧭 情報インプット／🔍 全文検索」は維持**（既存 SC-50 の下線型タブ体裁）。グループ（全般／カメリオ連携／情報共有…）は**「情報インプット」タブの“中”のサブタブ**として置く（＝トップタブを置き換えない）。
- **サブタブ＝サブメニュー型（確定）**＝アクティブなトップタブの**直下に地続きのサブメニュー帯**（薄い下地＝primary-soft・**トップタブ行に全幅下線を引かずスキマ/境界線を作らない**）を出し、その中にグループを**タブ（下線アクティブ）**として並べる。**バッジ/ピルにしない**・トップタブとはスタイルで段を分ける（上＝下線タブ／帯＝アクティブタブと同下地で連結）。各サブタブ＝`tab_id` で絞った DataTable（§1.8.1 契約は不変）。**「全般」が既定選択**。「🔍 全文検索」選択時は**サブメニュー帯を出さない**（全文検索は全グループ横断・結果にグループ名を添える）。
- **溢れ時＝案C ハイブリッド（確定）**＝サブタブが帯の幅に収まらない時は、**よく使う分だけ帯に出し、入りきらない分は「⋯ すべて (N)」ボタン→検索付き一覧ダイアログ**から選ぶ。タブが少ない会社は自然に全部が帯へ並び、増えたら自動で「⋯ すべて」が出る（少数時の見た目は折り返し/スクロールと変わらない）。2行折り返し（案A）／左右スクロール（案B）は不採用（縦圧迫・隠れタブの気づきにくさ）。
- **タブ管理**＝サブメニュー帯の「＋ タブ」または一覧ヘッダから、**管理者/curator のみ**「タブ管理」＝**URL付きモーダル**（[[url-modal-standard-for-dialogs]]）で追加／名称編集（予約語・同名は検証エラー §2.1）／ドラッグ並べ替え（`sort_order`）／アーカイブ（配下が空のときのみ・§3）。検証は §4.7 標準（[[form-validation-47-standard]]）。「＋ タブ」は権限者のみ表示。
- **SC-51 登録モーダル**＝「**登録先タブ**」セレクタを追加（既定＝現在開いているサブタブ）。**「カメリオ連携」も手動の登録先に選べる**（受け口＝§1/§3）。「全般」「カメリオ連携」は既存の予約タブとして候補に出る（新規作成名としては不可）。続報は親のタブを既定継承（§5）。
- **info_curator** の詳細（SC-52）でタブ付け替え可。

## 5. 既存機構との整合（タブは「導線／器」）

- タブは**一覧ナビの絞り**であって、`info_items` の**属性構造は不変**（#1〜#14・分類/カテゴリ/影響評価はそのまま）。
- **ワードクラウド／類似リンク（`info_links`・`entity_tokens`）はタブ非依存**＝会社横断プールのまま（§1）。ただしワードクラウドの**絞り込みに `tab` を1つ足す**のは自然（既存 `GET /info-items/word-cloud` のフィルタに tab 追加）。
- **自動類似リンクの情報別 ON/OFF（#6 確定・新設）**＝`info_items.auto_link_enabled`（boolean）を追加し、**情報ごとに自動類似リンク（auto `info_links`）の対象可否を切替**。**外部連携（カメリオ連携）で取り込む情報は既定 OFF**＝大量ニュースが知識プールの自動関連付けを汚染しないため（手動貼付は既定 ON）。OFF でも手動リンクは可。curator が価値ある記事を ON（or curated 昇格）して初めて燃料化。正式反映は FR-41（情報インプット正本）＋姉妹 [カメリオAPI連携 設計](カメリオAPI連携_設計.md) §5/§8。
- **続報（`parent_info_id`）**＝続報は親と**同じタブを既定継承**（プリフィル・編集可）＝スレッドが同じ棚に並ぶ。**カメリオ連携タブの記事への手動続報も可**（§1・受け口の制約なし）。スレッド（`parent_info_id`）と `tab_id` は独立＝必要ならタブをまたいでよい。
- **テンプレート機能**（[情報インプットテンプレート機能 設計](情報インプットテンプレート機能_設計.md)）との合流は Phase2（タブ既定テンプレ・§9）。

## 6. API（ドメイン N 拡張・次段で実体化）

| メソッド/パス | 概要 | 権限 |
| --- | --- | --- |
| `GET /info-tabs` | タブ一覧（`sort_order` 順・各タブ件数付き） | 会社内 active 全員（読取） |
| `POST /info-tabs` | タブ作成 | admin / curator |
| `PATCH /info-tabs/{id}` | 名称/色/アイコン/並べ替え/アーカイブ | admin / curator |
| `GET /info-items?tab_id=...` | 一覧フィルタに `tab_id` 追加（既存 N.1 拡張） | 会社内 active 全員 |
| `POST /info-items`（既存 N.2） | ボディに `tab_id`（省略時＝全般） | 会社内 active 全員 |

- `kind='connector'` タブは **API で作成不可**（連携設定側が生成・姉妹ドラフト §4）＝`POST /info-tabs` は `user` のみ許可。
- 既存同様 `can`（`manage_tabs`＝admin/curator）をサーバー算出で返し、フロントは表示出し分け・EP で必ず再検証。

## 7. セキュリティ・テナント

- **タブ名 XSS**＝text・表示時エスケープ（リッチ不可）。
- **テナント分離**＝会社 DB（§1）。`connector_ref` はコード側**ホワイトリスト**（`kamelio` 等・任意文字列を受けない）。
- 権限越権＝403／他テナント＝404（既存 N.0 準拠）。

## 8. MVP 境界・Phase2

- **MVP**＝単一所属タブ（`tab_id`）／全般予約（削除不可）／admin・curator 管理／一覧第一次ナビ／登録先選択／`connector` タブ（カメリオ用）。
- **Phase2**＝タブ別の**既定属性/既定テンプレ**プリフィル（テンプレ機能と合流）／タブ単位の**可視範囲**（特定部署のみ等）／**M:N 化**（1情報を複数タブに）＝必要が出たら。

## 9. 代替案と不採用理由（なぜこの形か）

- **(A) 属性 enum の会社拡張で表現**（#7/#8 をテナント master 化）＝不採用。器と属性は役割が別で、マスタ管理UI＋会社別 master テーブルが要り重い（[情報インプット機能 設計](情報インプット機能_設計.md) §11-②で Phase2 送り済）。タブは**独立した軽い新軸**として開ける方が安い・衝突しない。
- **(B) タブ＝保存ビュー（属性条件の保存フィルタ）**＝不採用。ユーザー像は「タブ**配下に登録**する」＝**所属（コンテナ）**であって検索条件ではない。連携記事の投入先としても所属の方が素直（姉妹ドラフト §5）。
- **(C) M:N（複数所属）を最初から**＝MVP 不採用（§11）。器は単一で足り、既存の #3 単一/#8 複数と役割が被らない方が運用が明快。拡張余地は §8 Phase2。

## 10. 残論点

1. **タブ別ワードクラウド絞り**を MVP に含めるか（推奨＝含める・既存フィルタに tab 追加のみ）。
2. **`sort_order` の並べ替え同時編集**の採番戦略（軽微）。
3. **既存会社への backfill**（全般 seed＋既存 `info_items` の割当 migration）。
4. **「⋯ すべて」の出し分け閾値**（帯に何件まで出すか＝幅依存の自動計算 or 固定N・軽微）。

## 11. 確定事項（2026-10-08・ユーザー合意）

1. **1情報＝1タブ（単一所属）**＝`info_items.tab_id`（§1/§2.2）。
2. **既定タブ「全般」＝システム予約・アーカイブ/改名不可**（`kind='system'`・§1）。未指定/移行の受け皿。
3. **タブ管理＝会社アカウント管理者＋`info_curator`**（§3）。一般ユーザーは登録先選択のみ。
4. **タブ名＝同名エラー＋予約語「全般」「カメリオ連携」は指定不可**。表示はユーザー入力値そのまま（§1/§2.1）。
5. **アーカイブ＝論理削除・`tab_id` を NULL にしない・配下に情報があればアーカイブ不可（エラー）**（§3）。
6. **`connector` タブ（カメリオ連携）は受け口**＝ユーザーの手動登録/続報も可（制約は予約語名のみ）・連携 OFF 後も情報が残れば表示維持（§1/§3）。
7. **タブは分類であり閲覧制限ではない**（会社内全員閲覧可・可視範囲は Phase2・§3）。
8. **自動類似リンクは情報別 ON/OFF（`auto_link_enabled`）・外部連携取り込みは既定 OFF**（§5・#6）。
9. **SC-50 UI＝トップタブ（情報インプット／全文検索）維持＋"情報インプット"内にサブメニュー型サブタブ**（下線アクティブ・帯でアクティブタブと地続き・ピル/バッジ不可）／**溢れ時＝案C「⋯ すべて (N)」＋検索ダイアログのハイブリッド**（§4・検討モック `_サブタブ_検討.html`／`_サブタブ溢れ_検討.html`・目視済み）。
