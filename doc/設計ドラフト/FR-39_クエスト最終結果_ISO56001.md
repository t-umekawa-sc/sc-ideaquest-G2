## 1. 位置づけ（合意済みの考え方）

**クエスト＝1つのイノベーション・イニシアチブ**。ISO 56001 のイノベーション・プロセス「①機会の特定 → ②コンセプトの創造 → ③コンセプトの検証 → ④ソリューションの開発 → ⑤導入（価値の実現）」に対し、ideaquest は **①〜③を担うツール**である。

| ISO 56001 の工程 | ideaquest の活動・成果物 |
|---|---|
| ① 機会の特定 | クエスト作成（テーマ・目的） |
| ② コンセプトの創造 | **アイデア**投稿（＝「意図」の創出・提案価値＋本文） |
| ②' コンセプトの精緻化 | **チャット議論**（意図の具体化・課題/利害関係者/前提の洗い出し） |
| ③ コンセプトの検証 | **評価**（5観点採点＋総評）＋**選定** |
| ④ ソリューションの開発 | **本アプリの対象外（将来拡張）** |
| ⑤ 導入・価値の実現 | 同上（将来拡張） |

→ **「最終結果」＝③の締めくくりであり、④へ渡す“橋”＝「検証済みコンセプト票（development brief）」**。既存3成果物（アイデア＋チャット＋評価）を1枚に凝縮・翻訳した実務成果物とする。**新情報を増やすのではなく、既存を集約・意思決定・学びの記録で締める**のが本質。

> **スコープ（2026-09-13 合意）**：④ソリューション開発のアプリ内実装は**今回のスコープ外＝将来拡張**。今回は「検証済みコンセプト票を出力し、次アクション（＝後続クエストの起票）へ橋渡しする」ところまでで完成とする。

## 2. 「検証済みコンセプト票」の構成と、どの成果物から作るか

SC-12 に **「🏁 結果」タブ**を追加（**常時表示＝途中経過も見られる。完了前は「暫定」を明示**〔タブに「暫定」チップ＋進行中バナー〕・2026-09-13 変更。理由・整合は [ISO56001 との関係と設計意図 §2.6](FR-39_ISO56001との関係と設計意図.md)）。上から：

| # | セクション | 内容 | データ源 | 自動/人手 | ISO56001 |
|---|---|---|---|---|---|
| 1 | 検証済みコンセプト | 選定アイデア（複数可）＝title/価値/本文抜粋/投稿者/評価平均 | 選定（`ideas.is_selected`）＋評価 | 自動 | §8.3 |
| 2 | 検証サマリ | 観点別平均（新規性/影響度/実現度/適合性/コスト）・スコア分布＋参加指標（アイデア数/投票総数/評価実施数/パーティー人数） | 評価(F)・投票(D)・パーティー(C) | 自動 | §9 |
| 3 | 意思決定の記録 | 採用/不採用と理由（評価総評抜粋＋一言） | 選定＋評価総評 | 自動＋一言人手 | §8.3 |
| 4 | 議論の要点 | 各採用アイデアの**(a) チャットへのリンク**＋**(b) ピン留めした重要メッセージの集約**＋**(c) AI要約（要点候補）** | チャット(E) | 半自動（下記§4） | §8.3/§9 |
| 5 | 振り返り・学び | `summary`（成果）・`learnings`（学び・課題）＋**期待価値/成果の指標（自由記述の指標行）** | 新規記入（owner/管理） | 人手 | §10 |
| 6 | 次アクション | `next_actions`＋**「このクエストを複製して次（開発フェーズ）を起票」導線** | 新規記入＋既存複製 | 人手 | §8.3/§10 |

## 3. 権限・可視性・出現タイミング

- **閲覧**：`completed` クエストのパーティー員（門番＝C.0・範囲外 404）。評価の観点別スコア/総評は `evaluation_visibility`（party/limited）を尊重（limited は範囲外に非表示）。
- **編集（5・6 と 3 の一言）**：`owner` / `quest_admin` のみ（サーバー再検証）。
- **出現**：`completed` 遷移（C.5）で「結果」タブ出現。総括は完了後いつでも追記・修正可。

## 4. チャット要点の3方式（a/b/c すべて対応）

- **(a) リンク**：各採用アイデアの `4` 欄からチャット（SC-24）へ遷移。実装極小。
- **(b) ピン留め**：チャットで重要メッセージを **★ピン**でき、結果票 `4` に自動集約。検証の証跡（なぜ有望と判断したか）を確実に残す。E ドメインに `is_pinned` を追加。
- **(c) 自動要約（抽出型・オフライン・無料）**：チャットを**無料の Python ライブラリで要点抽出**（重要文を数文選ぶ extractive 要約。**外部API・課金・外部送信なし**）。owner/quest_admin が **「自動要約」**を実行→結果を `4` に保存（キャッシュ）＋**再生成**可。人手で採否・編集できる（丸呑みにしない）。生成型LLMより粗いが無料で完結（将来 LLM への差し替えは seam）。ライブラリ案＝日本語分かち書き `janome`（純Python・MIT）or `tinysegmenter` ＋ 要約 `sumy`（LexRank/TextRank）。詳細§7。

## 5. データモデル（新規最小）

- **`quest_outcomes`**（クエスト1件＝0..1・テナントDB）
  | 列 | 型 | 説明 |
  |---|---|---|
  | `quest_id` | uuid PK/FK | 対象クエスト |
  | `summary` | text | 成果（総括） |
  | `learnings` | text | 学び・課題（§10） |
  | `next_actions` | text | 次アクション |
  | `metrics` | jsonb | 期待価値/成果の指標（自由記述の `[{label, value}]`） |
  | `chat_summary` | text | (c) AI要約のキャッシュ（再生成可） |
  | `chat_summary_at` | timestamptz null | AI要約の生成時刻 |
  | `updated_by` / `updated_at` | uuid / timestamptz | 監査 |
- **`chat_messages.is_pinned`**（boolean・既定 false）＝(b) ピン留め。または `chat_pins`（message_id, pinned_by, at）小テーブル（監査重視なら後者）。
- 1・2・3 は既存（`ideas.is_selected`・`evaluations`・投票・`quest_members`）の集計で導出＝新規列不要。

## 6. API（最小）

| メソッド/パス | 用途 | 権限 |
|---|---|---|
| `GET /quests/{id}/result` | 最終結果の取得（`completed` のみ・合成：選定/評価/投票/参加/pinned/outcomes） | パーティー員（C.0・可視性尊重） |
| `PUT /quests/{id}/result` | 総括（summary/learnings/next_actions/metrics）の保存 | owner/quest_admin |
| `POST/DELETE /chat-messages/{id}/pin` | チャットのピン留め/解除（(b)・E ドメイン） | パーティー員（comment 権限） |
| `POST /quests/{id}/result/chat-summary` | (c) 自動要約（抽出型・オフライン）の生成/再生成（結果に保存） | owner/quest_admin |

- `GET result` は**読取合成の殻**（I ダッシュボード集約と同方針・新業務ロジック最小）。

## 7. 横断・非機能

- **通知/フィード（④）**：`completed`＝結果確定時にパーティーへ通知（H・`quest_result_ready` 等）＋チーム成果フィード（FR-36 成果系）に載せる。
- **XP（⑥）**：完了総括の初回記入に少額 XP（G 台帳・冪等・完了総括1回のみ）。
- **自動要約（(c)）＝無料・オフライン方針**：外部LLM・APIキー・課金・外部送信は**使わない**（会社データを外部へ出さない＝データ保護上も安全）。backend コンテナに純Python 依存（`janome`/`tinysegmenter`＋`sumy` 等）を追加するのみ。抽出型のため品質は生成型より粗い前提。失敗時は (a)(b) が独立で機能。**将来 LLM 生成要約へ差し替える seam**（要約関数を1箇所に隔離）を用意。
- 総括/要約テキストは表示時サニタイズ（§2.2・XSS）。改行保持（レビュー#5）。

## 9. 実装順（段階）

- **Phase 1（コア）**：`quest_outcomes` migration → `GET`/`PUT result` API（TC先行）→ SC-12「結果」タブ（モック先行→接続）＝セクション1/2/3/5/6 ＋ (a) チャットリンク ＋ ③複製導線 ＋ ④通知/フィード ＋ ⑥XP。
- **Phase 2（(b) ピン留め）**：E ドメインに `is_pinned`／`POST/DELETE .../pin` ＋ SC-24 チャットUIの★ピン ＋ 結果票 `4` へ集約。
- **Phase 3（(c) 自動要約・無料オフライン）**：`POST .../chat-summary`（**無料 Python ライブラリで抽出型要約**・外部API/課金なし）＋ 結果票 `4` に「自動要約/再生成」。backend に純Python 依存を追加（`janome`/`tinysegmenter`＋`sumy` 等）。要約関数は seam 化（将来 LLM 差し替え可）。

> 各 Phase は独立して価値を出す（Phase 1 だけでも「検証済みコンセプト票」は成立）。Phase 3 は**無料ライブラリのみ**で完結（外部LLM・キー・課金なし）。
