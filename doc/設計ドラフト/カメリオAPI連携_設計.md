## 0. 位置づけ・狙い

- カメリオAPI を **情報インプットの外部ソースコネクタ**として連携し、**取得した記事（見出し＋要約＋出典URL＋タグ）を `info_items`（raw）として自動投入**する。投入先＝動的タブ「**カメリオ連携**」（`connector` タブ・姉妹ドラフト）。
- **会社単位で連携 ON/OFF**。ON 時に **API 連携に必要な項目（APIキー・プラン・監視フィード/キーワード条件・取得間隔）**を入力する。
- **狙い**＝これまで**手動貼付のみ**だった知識レイヤ（[情報インプット機能 設計](情報インプット機能_設計.md) §1）に、会社が選んだ監視テーマの外部ニュースを**自動供給する蛇口**を付ける＝ISO56001 **① 機会の特定**・環境スキャンの燃料を継続供給。取り込み後は既存の**自動関連付け**（§5）でアイデア/コンセプトへ動的リンクされ、受動スクラップでなく能動的に効く。

## 1. 設計の芯＝疎結合コネクタ（port / adapter）

- 既存の**疎結合 port 思想**を踏襲する＝[帳票連携 設計](帳票連携(JasperReports)_設計.md)（Jasper＝差し替え可能な 1 レンダラ）・[ローカルLLM連携 設計](ローカルLLM連携_設計.md)（LLM ゲートウェイ＝provider 隠蔽）と同型。
- **「情報ソースコネクタ」port** を定義し、**カメリオは差し替え可能な 1 実装（adapter）に過ぎない**。
  - port IF（概念）＝`fetch(feed_config, since_cursor) -> (NormalizedArticle[], next_cursor)`。
  - `NormalizedArticle`＝`{ external_id, title, summary, url, published_at, tags[], source_name }`。**adapter がカメリオ JSON → NormalizedArticle へ写像**。
- **なぜ疎結合か**＝(a) 将来の別ニュースAPI（カメリオは "NewsAPI 代替" も標榜）も**同 IF で挿せる** (b) **カメリオ未契約/不在でもアプリは動く**（連携 OFF＝従来の手動貼付のみ） (c) 取り込み→`info_items` 正規化のロジックを**カメリオ固有仕様から切り離す**（仕様変更の波及を adapter に閉じ込める）。
- 配置＝副作用インフラ（`infra/` 配下のコネクタ・コードのみ）＋テナント側ドメイン（取り込み結果＝会社DB `info_items`）。LLM ゲートウェイと同じ「インフラ×ジョブ基盤×会社設定」の三層（§4/§5）。

## 2. 大原則＝取り込みは「要約＋出典URL＋タグ」のみ（記事全文は保持しない）

- 手動貼付（本文コピペ）と異なり、**自動取得では記事の全文を保存しない**＝カメリオが返す**見出し＋要約（スニペット）＋出典URL＋タグ**のみを `info_items` に格納する。
- **なぜ**＝**著作権**（自動で大量に全文を保持するのは権利リスクが大きい）。既存の **"要約＋出典URL" モデル**（[情報インプット機能 設計](情報インプット機能_設計.md) §12-3）にそのまま乗る＝`summary`＝カメリオ要約、`source_url`＝記事URL、`body_html`＝要約/スニペット（全文を読むユーザーは出典URLへ誘導）。
- これにより **`info_items` 構造に完全後方互換**（既存の `body_html`/`body_text`/`summary`/`source_url`/`source`/`scope` を使うだけ＝新しい本文概念を足さない）。

## 3. SSRF・サーバフェッチの扱い（方針転換の明示）

- 情報インプットの核は「**サーバは外部 URL を取りに行かない＝SSRF 対象外**」（[情報インプット機能 設計](情報インプット機能_設計.md) §1/§7）。本連携は**サーバが外部 API を fetch する**＝この前提を**一部破る**。設計上、明示して対処する。
- ただし **取得先は固定・既知・許可リストのホスト（`kamelio-api.com`＝コード側 allowlist）**であり、**ユーザー入力の任意 URL を取りに行くわけではない**（会社設定が持つのは **APIキーとフィード条件のみ**＝宛先ホストは持たせない）＝SSRF 面は限定的。
- **対処**：
  - (a) **fetch 先ホストはコード側 allowlist 固定**（会社設定に任意 URL を持たせない）。
  - (b) **timeout／指数バックオフ・リトライ／レスポンスサイズ上限／取得件数上限**。
  - (c) 取得した要約/テキストも **`nh3` サニタイズ**を通す（[情報インプット機能 設計](情報インプット機能_設計.md) §12-4）＝手動貼付と**同じ無害化パス**。`source_url` は http/https のみ。
  - (d) **画像は MVP では取り込まない**（要約テキストのみ）。将来取り込む場合も既存の **MinIO 再ホスト**（外部 img を素通ししない・§12-4）に従う。

## 4. 会社単位 ON/OFF ＋ 設定（先行パターン＝`company_ai_model_settings` §5.58 踏襲）

### 4.1 設定台帳（新規・会社DB）

- **汎用の `company_integration_settings`**（`provider` 列で種別・将来の連携も同表に）を推奨（§11-残論点で確定）。

| 物理名 | 論理名 | 型 | 制約 / 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `id` | ID | uuid | PK | |
| `provider` | 連携種別 | text | NOT NULL | `kamelio` 等（ホワイトリスト） |
| `enabled` | 有効 | boolean | NOT NULL, default false | 会社での ON/OFF |
| `credentials_encrypted` | 認証情報（暗号化） | bytea / text | NULL可 | APIキー等を**暗号化**保管（§9）。平文は返さない |
| `config` | 連携設定 | jsonb | NULL可 | プラン（search/tag-feed）・監視フィード/キーワード条件（AND/OR/NOT）・対象タグ・取得件数上限 等 |
| `poll_interval_min` | 取得間隔（分） | integer | NULL可 | 定期ポーリング間隔（最小値はカメリオ契約レートに合わせ下限ガード・§10） |
| `last_polled_at` | 最終取得時刻 | timestamptz | NULL可 | 可視化/次回判定 |
| `last_cursor` | 取得カーソル | text | NULL可 | 増分取得の位置（adapter 定義） |
| `last_error` | 直近エラー | jsonb | NULL可 | 401/429/障害の記録（画面に degraded 表示） |
| `enabled_by_id` | 変更者 | uuid | FK→users | **課金/契約合意の記録**（§5.58 と同思想＝誰が ON にしたか） |
| `enabled_at` | 変更時刻 | timestamptz | NULL可 | 同上 |
| `created_at`/`updated_at` | 監査 | timestamptz | NOT NULL | 共通監査列 |

- インデックス: `UNIQUE(provider)`（会社DB 内で 1 連携 1 行）、`(enabled)`（ポーリング対象絞り）。
- **なぜテーブルで持つ**＝会社ごとに違い・監査（誰がいつ ON＝契約に合意したか）が要る。LLM 設定（§5.58）と完全同型の判断。

### 4.2 取り込み台帳（新規・会社DB＝冪等の要）

| 物理名 | 論理名 | 型 | 制約 / 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `id` | ID | uuid | PK | |
| `provider` | 連携種別 | text | NOT NULL | `kamelio` |
| `external_id` | 外部記事ID | text | NOT NULL | カメリオの記事ID（**重複排除キー**） |
| `info_item_id` | 生成 info | uuid | FK→info_items | 取り込みで作成した情報 |
| `imported_at` | 取り込み時刻 | timestamptz | NOT NULL | |

- インデックス: **`UNIQUE(provider, external_id)`**（再取得で既存はスキップ＝冪等）。

### 4.3 ON/OFF と入力項目

- **ON にする時**＝APIキー＋**最低 1 つのフィード/キーワード条件**を必須入力（[§4.7 検証標準](../画面設計/デザイン標準.md)）。**接続テスト**（カメリオへ 1 回 test fetch で疎通確認）を推奨。
- **権限**＝`company_account_admin`（LLM 設定 SC-94 と同じ **SoD**＝「会社がお金を使う契約判断」は管理者の領分・[SC-94](../画面設計/screens/SC-94_会社のLLM設定.md) §2）。カメリオは**有料契約**（¥40k〜/月）ゆえ妥当。
- **↔ 動的タブ**＝連携 ON で `connector` タブ「**カメリオ連携**」を**自動生成**（`kind='connector'`・`connector_ref='kamelio'`・名前は予約語）。**OFF 後も配下に情報が残れば表示を維持**（空なら任意アーカイブ）。受け口なので**ユーザーの手動登録/続報も受け付ける**（姉妹ドラフト §1/§3）。

## 5. 取り込みパイプライン（定期ポーリング＋手動取得・確定 §11）

- **既存 AI ジョブ基盤のポーリングワーカを踏襲**（[ローカルLLM連携 設計](ローカルLLM連携_設計.md) の「状態管理と実行方式の分離」）＝新ワーカ `integration_worker`（or 既存 outbox/worker を流用）。**新しい非同期機構を作らない**（DRY）。
- **定期**＝会社ごと `poll_interval_min` で、`enabled` 連携に対し `fetch(config, last_cursor)` → `NormalizedArticle[]` → 正規化 → `info_items`(raw) へ upsert → `last_cursor` 更新。
- **手動**＝設定画面の「**今すぐ取得**」で即時ジョブ enqueue。
- **冪等**＝`integration_import_log.UNIQUE(provider, external_id)`（§4.2）で再取得の重複を排除。
- **投入時の `info_items` 写像**：
  - `tab_id`＝「カメリオ連携」`connector` タブ／`status`＝`raw`（＝curator が後で属性付与・判定）。
  - **`auto_link_enabled`＝`false`（既定 OFF・#6）**＝大量ニュースが知識プールの自動類似リンクを汚染しないため。curator が価値ある記事を ON（or curated 昇格）して初めて燃料化。
  - `source`＝`新聞・ネットニュース`（#2）／`scope`＝`external`（#6 大分類）／`classification`＝`information`（#3）。
  - `source_url`＝記事URL／`summary`＝カメリオ要約／`body_html`＝要約・スニペット（§2）。
  - `created_by`＝連携の起動者 or 専用連携アカウント（§10 残論点）。一覧バッジ用に `source_system='kamelio'`（便宜 denorm の小列）を推奨。
  - **カメリオ tags**（企業名/地域/イベント種別等）→ 情報カテゴリ(#8) への自動マッピングは **Phase2**（MVP は tags を保持のみ・§8）。
- **取り込み後**＝**既定は自動類似リンク OFF**（`auto_link_enabled=false`・#6）＝生ニュースで知識プールを汚さない。**curator が価値を認めた記事を ON（or curated 昇格）すると**、既存の自動関連付け（`info_links` auto・`entity_tokens`・類似度／[情報インプット機能 設計](情報インプット機能_設計.md) §4/§5）が効き、**アイデア/コンセプトへ動的リンク＝燃料化**。手動リンクは OFF でも随時可。
- **通知**＝新着まとめ通知は**既定 OFF**（ノイズ回避）／curator が任意 ON（既存 `notifications` に type 追加・§10）。

## 6. エラー・運用

- APIキー失効（401）・レート超過（429）・カメリオ障害＝**連携は自動停止せず**、`last_error` 記録＋**管理者へ通知**＋画面に **degraded 状態**表示。リトライは**指数バックオフ**。
- 取得件数/失敗の**可視化**＝設定画面に `last_polled_at`・直近取り込み件数・直近エラーを表示。
- 利用量（取得件数/契約枠）の**メータリング**は Phase2（必要なら LLM の `ai_usage_events` §5.59 と同型で追記台帳化）。

## 8. MVP 境界・Phase2

- **MVP**＝会社 ON/OFF＋APIキー/フィード設定＋**定期ポーリング＋手動取得**＋「カメリオ連携」タブ投入(raw・要約+URL+タグ・`auto_link_enabled=false`)＋**冪等取り込み**＋**curator が ON/昇格した記事のみ自動関連付け連動**＋状態表示＋接続テスト。
- **Phase2**＝tags→情報カテゴリ(#8) 自動マッピング／利用量メータリング／複数フィードの細分管理／新着通知／**他プロバイダ adapter 追加**（同 port）／画像取り込み（MinIO 再ホスト）。

## 9. セキュリティ（秘密保護を最優先）

> **秘密保護の“守り方”の機構は横断基盤に集約**＝[シークレット管理(SOPS) 設計](シークレット管理(SOPS)_設計.md)（SOPS+age／ファイルマウント／AES-GCM／守れる・守れない／将来のサーバ型）。**本連携はその消費者**であり、ここには**カメリオ固有の適用だけ**を記す（一般機構は再発明しない・DRY）。

### 9.1 カメリオ APIキーの保管（＝「実行時入力秘密(B)」パターン）

- カメリオ APIキーは **会社管理者が実行時に画面入力**するため DB 保存が必須＝[シークレット管理(SOPS) 設計](シークレット管理(SOPS)_設計.md) §2 の **(B) 実行時入力秘密**に該当。
- **`credentials_encrypted` に AES-GCM で暗号化**（同 §6・AAD に `provider='kamelio'`/`company_id` を束ねて付け替え検知）。**復号用マスター鍵は SOPS+age 経由で供給**（同 §3〜§5）＝暗号文と鍵を分離。
- **マスク表示・平文非返却**＝API 応答は末尾4桁等、変更は再入力のみ。設定変更は `company_account_admin` のみ＋監査（`enabled_by`/`enabled_at`・§4.1）。

### 9.2 カメリオ固有の補完策（runtime/ローテーション）

> runtime の平文到達は原理的に完全には防げない（横断基盤 §7/§8）。カメリオ固有の適用は以下。

- **復号後の平文はメモリ限定・ログ禁止**＝カメリオへ HTTPS 送信の瞬間だけ使い即破棄。**ログマスクに「カメリオのキー名」を登録**（横断基盤 §8・[本番デプロイ要件](../本番デプロイ要件.md) §6.6）。
- **ローテーション**＝**カメリオ側でのキー再発行可否を契約確認**（§10 残論点）→ 可能なら漏洩時に再発行→DB 再暗号化で被害 window を短縮。
- **異常検知**＝**取得件数の急増**などキー悪用の兆候をアラート。
- **最小権限**＝APIキー復号・fetch 実行ができるのは連携ワーカのプロセスのみ。

### 9.3 通信・取り込み・テナント（カメリオ固有）

- **通信（in transit）**＝カメリオへは **HTTPS/TLS 必須・証明書検証を無効化しない**。
- **fetch（SSRF 対処・§3 再掲）**＝宛先ホスト allowlist 固定／timeout・サイズ/件数上限／取得テキスト `nh3` サニタイズ／画像 MVP 非取り込み。
- **テナント分離**＝会社DB で完結。他テナントの連携は見えない（404 存在秘匿）。
- **著作権/利用規約**＝**要約＋リンクのみ保持**（§2）。カメリオ利用規約の再配布条項の確認は契約時運用。

## 10. 残論点

1. **設定台帳**＝汎用 `company_integration_settings`（推奨）vs カメリオ専用表。
2. ~~**APIキー暗号化方式**~~ **✅ 確定＝[シークレット管理(SOPS) 設計](シークレット管理(SOPS)_設計.md) に集約（2026-10-08）**＝AES-GCM＋鍵分離、鍵は compose `secrets:` ファイルマウント、at-rest 強化に SOPS+age、サーバ型は将来オプション。**本連携固有の残＝カメリオがキー再発行（ローテーション）可能かの契約確認**（§9.2）。
3. **カメリオ API の正式仕様**（エンドポイント/認証ヘッダ/ページング/レート/増分取得カーソルの実体）＝**API ドキュメント入手後に §4/§5 確定**。現状は公開サイトからの推定（`playground.kamelio-api.com` デモあり）。
4. **tags→情報カテゴリ(#8) マッピング**の有無/方式（MVP は保持のみ）。
5. **`created_by`**＝専用「連携システムアカウント」を設けるか（監査/表示の明快さ）。
6. **取得間隔の既定/最小値**（カメリオ契約レート・従量コストとの兼ね合い）。
