# シークレット管理 手順書（SOPS+age／ファイルマウント供給）

> 対象読者＝**秘密の管理者・デプロイ担当者（＝自己ホストでは運用者本人）**。
> 設計の正本＝[シークレット管理(SOPS)_設計](../設計ドラフト/シークレット管理(SOPS)_設計.md)（なぜこうするか）。本番チェックリスト＝[本番デプロイ要件](../本番デプロイ要件.md) §3.1。実装現況＝[impl/README](../../impl/README.md)（D6）。
> 本書は「**何を・どの順で叩くか**」の実務手順。コマンドは原則 `impl/` で実行する。

## 0. 前提の要点（30秒で把握）

- **暗号化は age 公開鍵でできる**（秘密鍵は不要）。**復号は age 秘密鍵が必要**。だから「秘密を暗号化する人」と「本番で復号する人」は分離でき、自己ホストなら両方あなたでよい。
- **暗号化するのは運用者（人）**。アプリ/CI が自動で暗号化はしない（平文の実値を入力する必要があるため）。
- **二層**＝(A) デプロイ秘密＝SOPS+age で暗号化（at-rest）＋`/run/secrets/<name>` ファイルマウントで供給（env 露出面の縮小）。(B) 実行時入力秘密（カメリオ等）は未実装（D3 待ち）。
- backend/jasper の秘密読取は **file > env**（`/run/secrets/<name>` があれば env より優先）。
- **本番ガード**＝`APP_ENV=prod` で dev 既定値のまま or 必須秘密が空なら**起動を拒否**（事故防止）。
- 方針＝**案1 デプロイ時復号**（イメージビルド時ではない）／**案2 age 鍵は本番非常駐**（投入のみ）／**平文は tmpfs**／**環境別鍵**／**`secrets.enc.yaml` はリポジトリに上げない**。

## 1. 前提ツールの導入（sops / age）

暗号化する端末・本番サーバ（復号する所）に `sops` と `age` が要る。**アプリイメージには同梱しない**（ビルドに秘密を焼き込まないため）。

- Ubuntu/Debian 例:
  ```bash
  sudo apt-get install -y age          # age / age-keygen
  # sops はリリースバイナリを配置（例 v3.9.4）
  curl -sSL -o /usr/local/bin/sops \
    https://github.com/getsops/sops/releases/download/v3.9.4/sops-v3.9.4.linux.amd64
  sudo chmod +x /usr/local/bin/sops
  ```
- 確認: `sops --version` / `age --version`。

## 2. 初回セットアップ（環境ごとに1回）

> **環境別鍵**＝dev と prod で別の age 鍵を使う（dev 流出で prod が死なないように）。

### 2.1 age 鍵ペアを生成
```bash
age-keygen -o prod_age.key            # 本番用（dev 用は dev_age.key など別名で）
#   出力例:  Public key: age1xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```
- `prod_age.key`（秘密鍵）は**厳重保管**（パスワードマネージャ/USB 等）。**本番サーバに常駐させない**（案2）。**バックアップ対象から外す**。
- 控えた **Public key** を次で使う。

### 2.2 公開鍵を `.sops.yaml` に設定
`impl/.sops.yaml` の `age:` を、生成した**公開鍵に置換**（初期値は EXAMPLE）。公開鍵は Git に入れてよい。
```yaml
creation_rules:
  - path_regex: secrets/secrets\.enc\.ya?ml$
    age: >-
      age1xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx   # ← あなたの公開鍵
```
> 複数環境を1ファイルで扱いたい場合は age に公開鍵を複数列挙できる（どの秘密鍵でも復号可）。ただし**環境別に別ファイルを持つ**のが基本（値も別）。

## 3. 秘密の暗号化（authoring・公開鍵のみ・初回＋値変更時）

```bash
cd impl
cp secrets/secrets.template.yaml secrets/secrets.enc.yaml   # 初回のみ（テンプレを複製）
sops secrets/secrets.enc.yaml                               # エディタが開く→実値を記入して保存＝自動で暗号化
```
- 保存すると各値が `ENC[AES256_GCM,...]` になる（キー名は平文＝差分が見える）。
- 値を変える時も `sops secrets/secrets.enc.yaml` で編集（差分だけ再暗号化）。
- **記入中の平文ファイルを別途作った場合は破棄**。`secrets.enc.yaml` と age 鍵は **Git に上げない**（`.gitignore` 済）。
- テンプレの鍵名＝backend の設定フィールド名（`app/core/config.py`）／jasper は `jasper_shared_secret`。空が正当な秘密（CAPTCHA 無効等）は空のままでよい。

## 4. 開発環境での利用（任意）

**既定の dev は env で動く（SOPS 不要）**＝`cd impl && docker compose up -d`。dev 既定値（`dev-jasper-secret` 等）で問題ない通常開発はこれでよい。

**dev でも SOPS を使ってよい**（推奨する場面＝本番フローの予行／dev で非既定の秘密を使いたい時）。その場合:
1. **dev 専用の age 鍵**を生成（`dev_age.key`・prod 鍵は使い回さない）。公開鍵を `.sops.yaml` に（prod とは別運用にするなら dev 用に別 `.sops.yaml`／別 enc ファイル）。
2. §3 で `secrets.enc.yaml` を作る（dev 値）。
3. 復号して起動（§6 と同じ・鍵は dev 鍵）:
   ```bash
   SOPS_AGE_KEY_FILE=dev_age.key impl/scripts/decrypt-secrets.sh
   docker compose -f compose.yaml -f compose.secrets.yaml up -d
   ```
> 注意＝dev で tmpfs を使わない場合、平文がディスクに残る（`decrypt-secrets.sh` が WARN を出す）。dev 検証なら許容可だが、**prod 値を dev で復号しない**（環境分離）。

## 5. 本番デプロイ（復号・案1/案2）

> 前提＝本番サーバに「秘密ゼロのイメージ」＋「暗号文 `secrets.enc.yaml`」が運ばれている。age **秘密鍵は常駐させず**、この作業の時だけ投入する。

```bash
# 1) 平文を置く tmpfs を用意（ディスクに残さない・§8）。例（deploy ディレクトリ配下）:
sudo mount -t tmpfs -o size=1m,mode=0700 tmpfs <deploy>/impl/secrets

# 2) age 秘密鍵を“投入”して復号 → 各秘密を tmpfs に materialize
cd <deploy>/impl
SOPS_AGE_KEY_FILE=/path/to/prod_age.key scripts/decrypt-secrets.sh
#   → dir 0700 / file 0444 で materialize（非 Swarm のため権限は復号側で決める・§9）
#   → より厳格にするなら root 実行＋ STRICT_CHOWN_UID=<消費uid> で 0400＋uid所有

# 3) 本番オーバーレイで起動（file マウントが有効）
docker compose -f compose.yaml -f compose.secrets.yaml up -d

# 4) 投入した age 秘密鍵を破棄（スクリプトは鍵を保存しない）
#    例: 投入元がリムーバブル/一時なら取り外し・unset 等
```

**無人再起動の注意（案2 の受容事項）**＝サーバが人手を介さず再起動すると、コンテナは上がるが tmpfs の平文が消えており復号もできない＝**人が鍵を再投入して §5 をやり直すまでサービスは復帰しない**。可用性より「鍵を常駐させない」を優先した設計。常駐自動復帰が必須なら設計 §9（TPM/KMS 封印）への昇格を検討。

## 6. ローテーション

- **秘密値のローテ（漏洩対応の本命）**＝元サービスで再発行（DB パスワード変更・API キー再発行等）→ §3 で `secrets.enc.yaml` を更新 → 再デプロイ。
- **age 鍵のローテ**＝定期 or 鍵漏洩が疑われる時。新鍵ペア生成→`.sops.yaml` の公開鍵更新→`sops updatekeys secrets/secrets.enc.yaml`（recipient 変更を反映）→再デプロイ。
- **重要**＝**age 鍵を変えるだけでは漏洩済みの秘密値は無効化できない**（Git 履歴に旧暗号文が残る・攻撃者は復号済みかも）。漏洩時は**必ず「秘密値ローテ」とセット**で行う。毎デプロイでの鍵ローテは不要（費用対効果が低い）。

## 7. やってよいこと / だめなこと

| | |
|---|---|
| ✅ `secrets.enc.yaml`（暗号文）を環境の配布経路で運ぶ | ❌ **本番 `secrets.enc.yaml` をこのリポジトリ/ホスト型 Git に push**（harvest-now-decrypt-later 回避・設計 §13） |
| ✅ 公開鍵を `.sops.yaml` に入れて Git 管理 | ❌ **age 秘密鍵を Git/イメージ/バックアップに入れる** |
| ✅ 環境別の age 鍵（dev/prod 別） | ❌ dev と prod で同じ鍵を使い回す |
| ✅ 復号先は tmpfs（平文を残さない） | ❌ 本番で平文を永続ディスクに置いたまま放置 |
| ✅ 本番は `APP_ENV=prod`（ガードを効かせる） | ❌ 本番で dev 既定値のまま起動（ガードで停止する） |

## 8. トラブルシュート

- **jasper が 401（復号値にしたのに）**＝(1) `docker compose up` では jasper が再作成されず**旧秘密を保持**していることがある → `docker compose -f compose.yaml -f compose.secrets.yaml up -d --force-recreate jasper`。(2) **権限**＝ファイルが `0400 owner=他uid` だと jasper(10001) が読めず env にフォールバック → `decrypt-secrets.sh` の既定（dir0700/file0444）を使う。**非 Swarm の docker compose は secret の `uid/gid/mode` を無視**する点に注意（compose 側で `mode:` を書いても効かない）。
- **`decrypt-secrets.sh` が ERROR で止まる**＝age 鍵未投入（`SOPS_AGE_KEY_FILE`/`SOPS_AGE_KEY` 未設定）＝**fail-closed（正常な防御）**。鍵を投入して再実行。
- **`sops` が creation rule を見つけられない**＝`.sops.yaml` の `path_regex`（`secrets/secrets.enc.yaml$`）に実行対象パスが一致しているか。`impl/` で実行する。
- **本番コンテナが起動直後に落ちる**＝本番ガードが dev 既定/空秘密を検出した可能性。ログの `RuntimeError`（フィールド名のみ・値は出さない）を確認し、該当秘密を強い値に。
- **平文がディスクに残る WARN**＝復号先が tmpfs でない。本番は tmpfs をマウントしてから `decrypt-secrets.sh`。

## 9. 動作確認（疎通）

```bash
# backend が file 値を採用しているか（env より優先されるか）
docker compose -f compose.yaml -f compose.secrets.yaml exec -T backend \
  python -c "from app.core.config import get_settings; print(get_settings().jasper_shared_secret[:4]+'...')"

# jasper S2S（復号値で 200／誤りで 401）＝backend から内部到達で確認
docker compose -f compose.yaml -f compose.secrets.yaml exec -T backend \
  python -c "import urllib.request;print(urllib.request.urlopen('http://jasper:8000/health',timeout=3).read())"

# 本番ガードの手動確認（dev 既定秘密で RuntimeError になること）
docker compose run --rm -T -e APP_ENV=prod --entrypoint python backend \
  -c "from app.main import _enforce_prod_secret_guard; _enforce_prod_secret_guard()"
```
