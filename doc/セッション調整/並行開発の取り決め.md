## 4. 実行時（docker）を分ける ★最重要

同一マシンで**2つの独立したスタック**を並立する。**互いの DB／ポートに触れないこと。**
compose の host ポート・ボリュームは env/named で分離可能（固定 `name:`/`container_name:` なし）。

### セッションB（開発）＝既定プロジェクト（そのまま）
```
cd impl && docker compose up -d --build        # 必要なら --profile workers も
# ポート: frontend 3000 / backend 8000 / db 5432 / 会社DB ideaquest_company_acme
```

### セッションA（e2e）＝隔離プロジェクト `iqe2e`
```
export COMPOSE_PROJECT_NAME=iqe2e
export FRONTEND_PORT=3100 BACKEND_PORT=8100 DB_PORT=5533 REDIS_PORT=6380 \
       MAILHOG_SMTP_PORT=1125 MAILHOG_UI_PORT=8125 MINIO_PORT=9100 MINIO_CONSOLE_PORT=9101 \
       MINIO_PUBLIC_ENDPOINT=localhost:9100 APP_BASE_URL=http://localhost:3100 \
       PLAYWRIGHT_BASE_URL=http://localhost:3100
cd impl && docker compose --profile workers up -d --build
```
→ 別コンテナ・別ボリューム（`iqe2e_db_data` 等）・別ポート。`COMPOSE_PROJECT_NAME` を立てるので
spec 内の `docker compose exec db psql …` も自動で **iqe2e 側 DB** を叩く（spec 改変不要）。
`APP_BASE_URL` は compose でハードコードのため **e2e ブランチでパラメータ化**して上書きする（メールリンクの
基点を 3100 にしないと sc-00 のメール系 e2e が開発スタック 3000 に飛ぶ）。e2e は **worker/mail-worker 起動必須**
（sc-00 OTP/再設定メール・ディレクトリミラーが依存）。

## 5. e2e 実行の注意 ★データ破壊

- `impl/frontend/e2e/db.reset.ts`（reset project）は**実行のたび**会社DB（`ideaquest_company_acme/acme2`、
  今後ワーカ別DB）を **DROP → bootstrap** する（pristine 復元・テスト規約 §4.1）。これは **main に既に入っている**。
- したがって：
  - **開発セッションは既定スタックで full e2e を走らせない**（手動投入データが毎回消える）。
  - 画面確認で targeted e2e を回す場合も「**走らせた瞬間に会社DBがリセットされる**」前提で（確認用データは消える）。
  - e2e を回すのは原則 **隔離プロジェクト `iqe2e` 側だけ**。

## 6. ビルド反映（既知の作法）

- backend/frontend はイメージにベイク。反映は各プロジェクトで `docker compose up -d --build <svc>`。
- 新 DTO は **backend 再ビルド → `cd impl/frontend && npm run codegen` → frontend ビルド** の順。
- 2スタックは独立＝片方の再ビルドは他方に影響しない。

## 7. マージ / 統合順

- 各自 green 後に main へ：開発＝対象画面の検証／e2e＝full green（隔離スタックで）。
- `bootstrap.py` を双方が変更した場合は、**先にマージした側に合わせて他方が rebase**（e2e＝seed追加／開発＝機能seedで衝突前提）。
- マージ後は相手が `git pull --rebase origin main` で追随。

## 8. 困ったら

- 触っているファイルが不明＝自分の worktree で `git status` と `git diff --stat origin/main` を突き合わせる。
- `address already in use`＝§4 の env 未設定で既定スタックとポート衝突。env を確認。
- DB が想定と違う＝`COMPOSE_PROJECT_NAME` の付け忘れ（既定スタックの DB を見ている）。
