## 調査結果（事実・コードで裏取り済み）

### フロントエンド（SC-05系・アイデア詳細）

`impl/frontend/src/features/ideas/components/IdeaDetailView.tsx`

- **行824-867**：`{evalAgg?.ai_evaluation && (…)}` で「🤖 AI評価」ブロックを条件表示。
  - 中身＝行828 バッジ＋モデル名、行834-851 5観点スコア＋観点別コメント＋総評。
- **行854-864**：「AI評価を再生成」ボタン。
  - 表示条件＝`canEvaluate`（行438＝`evalAgg?.my_permissions?.includes("evaluate")`）。
  - `questCompleted`（行422）が true のときは disabled + frozen（title「完了したクエストでは再生成できません」）。
  - 送信中は `regenerating` フラグで「再生成中…」表示（行380-400）。
- **要点**＝再評価ボタンは AI評価ブロックの内側にある。すなわち **`evalAgg?.ai_evaluation` が無い（初回AI評価未生成）とブロックごと出ず、ボタンも出ない**。

### バックエンド

- `impl/backend/app/tenant/evaluations/router.py:82-94`＝`POST /ideas/{idea_id}/ai-evaluation/regenerate`（202・評価者権限必須）。
  - 実装＝`application.py:148-156` `regenerate_ai_evaluation()`。`_require_evaluator()`（403）／`_guard_not_completed()`（409）／`ai_app.enqueue_ai_job()` で `task_type="idea_evaluate"` を投入。入力に `regenerated_by: uid`。
- 公開時の自動評価＝`impl/backend/app/tenant/ideas/application.py:363-381` `_enqueue_idea_ai_evaluation()`。`LLM_AUTO_EVALUATE_ON_PUBLISH=true` かつ会社モデル有効時のみ投入（失敗してもアイデア公開は進行＝graceful）。
- 会社でモデル無効なら 422（`ai_jobs/application.py:370-371`）。

### 有効化に必要な設定（`impl/.env.example`）

- LLM基盤起動：`docker compose --profile ai up -d ollama` → `ollama pull bge-m3`（埋め込み）／`ollama pull qwen3:4b`（生成）。
- ワーカ起動：`docker compose --profile workers up -d llm-worker`。
- 主要 env：`LLM_BASE_URL`(既定 `http://ollama:11434/v1`)／`LLM_MODEL_LIGHT`(qwen3:4b)／**`LLM_AUTO_EVALUATE_ON_PUBLISH`(既定 false)**／`EVAL_RAG_STRATEGY_TOPK/TOTAL/MIN_COSINE`。
- 管理画面 **admin/ai-settings（SC-94・`impl/frontend/src/app/(app)/admin/ai-settings/page.tsx`）** で会社のモデルを `enabled=ON`（OFFだと評価ジョブ422）。company_account_admin / system_admin 専用。

### 「AI再評価ボタンだけ表示」の逆算

現状の表示条件から、ボタンが出る状態＝次の3条件すべて：
1. `evalAgg?.ai_evaluation` が存在（＝**初回AI評価が生成済み**）。
2. `canEvaluate===true`（評価者権限）。
3. `questCompleted===false`（クエスト未完了）。

→ 専用の「ボタンだけ表示」トグルは**存在しない**（デザイン上無い）。
