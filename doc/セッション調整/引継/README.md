# 調査・設計の引き継ぎ（セッション間ハンドオフ）

> 別の Claude Code セッションで行った**調査・仕様確認・設計ドラフト**の内容を、**実装を担当しているセッション**に、毎回ブレない一定の方法で引き継ぐための運用ルール。

## 0. なぜこの仕組みか（原則）

- **共有正本（`doc/` 設計正本 + [バックログ台帳](../../バックログ/未実装・ギャップ一覧.md)）への書き込みは、実装セッションに一元化する。** 複数セッションが同じ正本ファイルを同時編集するとコンフリクトするため。
- したがって**調査/設計セッションは「引継ファイル」と「設計ドラフト（`doc/設計ドラフト/` の新規ファイル＝低競合）」だけを作る**。正本やバックログ台帳は触らない。
- 引継ファイルは**一時的な受け渡し専用の媒体**であり、正本ではない。役目を終えたら消す（§4）。

## 1. 置き場所・命名（1引継＝1ファイル）

- 置き場所＝本フォルダ `doc/セッション調整/引継/`。
- ファイル名＝**`YYYY-MM-DD_<スラッグ>.md`**（例 `2026-10-09_ai評価-有効化手順.md`）。
- **1つの引き継ぎにつき1ファイル**。1ファイルに複数テーマを詰め込まない（削除タイミングが辿れなくなる）。
- 様式は [_template.md](_template.md) に従う。

## 2. 役割分担

### 調査/設計セッション（引き渡す側）

1. 調査・仕様確認の結果を**本フォルダに引継ファイル1枚**として書く（[_template.md](_template.md) 準拠）。
2. 必要なら**設計ドラフトは `doc/設計ドラフト/` に新規ファイル**として起票し、引継ファイルからリンクする。
3. **正本・バックログ台帳は編集しない**（実装セッションに委ねる）。
4. 事実と憶測を分けて書く。裏取り状況（実コードで確認済みか）を明記する。

### 実装セッション（引き継ぐ側）

1. 着手時に本フォルダの引継ファイルを読む。
2. 残作業を[バックログ台帳](../../バックログ/未実装・ギャップ一覧.md)に**起票する（§3 の出典必須）**。
3. 確定仕様の**正本反映はこのセッションが一元管理**する。
4. 消化してバックログ行を削除する。
5. **その引継ファイルから起こした行が台帳から全て消えた時点で、引継ファイルを削除する**（§4＝A案）。

## 3. トレーサビリティ（出典は必須）

- 引継ファイルから起こしたバックログ行には、**備考に出典を必ず付ける**。
  - 形式＝`(出典: セッション調整/引継/YYYY-MM-DD_<スラッグ>.md)`
- これにより「この引継はどの行を生んだか／全部消えたか」を辿れる（§4 の削除判定に必要）。

## 4. 削除タイミング（A案＝文脈を保険に残す）

- 引継ファイルは、**それが生んだバックログ行の全てが台帳から消えた（＝対応完了した）時点**で削除する。
- 1引継が複数行を生んだ場合は、**最後の1行が完了した時**に削除する。
- 完了の記録先は commit メッセージ／[impl/README.md](../../../impl/README.md)／[handoff.md](../../../handoff.md)。**引継フォルダに「完了済み」を残さない**（本フォルダは未消化の引き継ぎのみを保持＝バックログ台帳と同じ思想）。

## 5. リポジトリ直下 `handoff.md` との違い

- 直下 [handoff.md](../../../handoff.md)＝**セッションを跨いだ経緯・次アクションの連続ログ**（1本・追記式）。
- 本フォルダ＝**特定の調査/設計を実装セッションに渡すための単発の受け渡し**（1引継1ファイル・消化したら削除）。
- 両者は別物。経緯は handoff.md、受け渡しは本フォルダ。
