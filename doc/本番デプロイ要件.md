# 本番デプロイ要件

> 本番デプロイ環境が**アプリの前提を満たすために保証すべきこと**を1箇所に集約する（アプリ側のコードだけでは強制できない、リバプロ/エッジ・実行環境・秘匿供給の保証事項）。
> ここは「決定の記録」ではなく「デプロイ時チェックリスト」。**決定の正は各 ADR**（本書は参照＝DRY・[`規約/ドキュメント作成規約.md`](規約/ドキュメント作成規約.md)）。本番イメージ/インフラ構築時に本書を上から満たすこと。

---

## 1. リバースプロキシ／クライアント IP（ADR-0006）

正＝[`ADR/ADR-0006_クライアントIPの確定.md`](ADR/ADR-0006_クライアントIPの確定.md)。ログインのレート制限（[`ADR/ADR-0001_認証・セッション基本パラメータ.md`](ADR/ADR-0001_認証・セッション基本パラメータ.md) §2.6）・アカウント一時ロック（[`ADR/ADR-0005_アカウント一時ロック.md`](ADR/ADR-0005_アカウント一時ロック.md) §2.2）が **(IP+login_id) 単位**で成り立つには、backend が**実クライアント IP**を見られる必要がある。

- [ ] **最外の信頼プロキシ（エッジ）が `X-Forwarded-For` を確定させる**＝クライアント由来の `X-Forwarded-For`/`X-Real-IP` を**破棄または上書き**し、自分が受けた実ピア IP を付与する（クライアント詐称値を通さない）。
- [ ] **backend 手前の信頼プロキシ段数と env `TRUSTED_PROXY_COUNT` を一致**させる（例＝エッジのみ経由なら 1）。ズレると実 IP を誤取得する。
- [ ] 推奨: **`/api/v1/*` はエッジから FastAPI へ直結**（Next.js を API データ経路から外す）＝ホップ数を 1 に固定でき、Next の XFF 転送挙動に依存しない。Next.js の `rewrites()` を本番の API 経路に使う場合は、**Next が XFF を正しく転送するか検証**したうえでホップ数に算入すること（ADR-0006 §5・未検証）。
- [ ] 起動ログに `TRUSTED_PROXY_COUNT=0` の警告が出ていないこと（`APP_ENV=prod` で 0 は設定漏れの疑い・ADR-0006 §2.2）。

## 2. Cookie / TLS

正＝[`API設計/A_認証・セッション.md`](API設計/A_認証・セッション.md) A.0（Cookie 表）・[`ADR/ADR-0001_認証・セッション基本パラメータ.md`](ADR/ADR-0001_認証・セッション基本パラメータ.md) §2.3。

- [ ] **`COOKIE_SECURE=true`**（本番は必ず Secure Cookie）。TLS 終端されていること（`iq_session`/`iq_csrf`/`iq_preauth`/`iq_trust` は Secure 前提）。
- [ ] 同一オリジン構成（ブラウザは 1 オリジンのみと通信・CORS 不要）を維持。別オリジンにする場合は許可オリジン（`ALLOWED_ORIGINS`）を明示。

## 3. 秘匿情報の供給（ADR-0003）

正＝[`ADR/ADR-0003_設定と秘匿情報の置き場所.md`](ADR/ADR-0003_設定と秘匿情報の置き場所.md) §2.3/§2.4。

- [ ] **秘匿（`SMTP_USER`/`SMTP_PASSWORD` 等）はシークレットマネージャ供給**（`.env` に本番実値を焼かない・`.env` は追跡外）。
- [ ] `SMTP_HOST`/`SMTP_PORT`/`SMTP_START_TLS`（本番 587 送信は `true`）/`MAIL_FROM`/`MAIL_ALERT_TO` を本番値に設定。
- [ ] コンテナへ届く env は **`compose.yaml`（本番相当の manifest）の `environment:` に列挙された変数のみ**（`env_file:` 無し）。新規しきい値は必ず `environment:` に配線（ドリフト防止）。

## 4. しきい値 env（プラットフォーム共通・ADR-0001/0002/0004/0005/0006）

いずれも env で調整可（非秘匿）。本番で意図した値になっていること。

- [ ] セッション（`SESSION_IDLE_TTL_SECONDS`/`SESSION_ABSOLUTE_TTL_SECONDS`・ADR-0001）
- [ ] ログインレート制限（`LOGIN_RATE_LIMIT_MAX`/`LOGIN_RATE_LIMIT_WINDOW_SECONDS`・ADR-0001）
- [ ] MFA/信頼端末（`OTP_*`/`OTP_LENGTH`/`PREAUTH_TTL_SECONDS`/`TRUSTED_DEVICE_TTL_SECONDS`・ADR-0004）
- [ ] アカウント一時ロック（`LOGIN_LOCK_MAX_ATTEMPTS`/`LOGIN_LOCK_TTL_SECONDS`/`LOGIN_LOCK_NOTIFY_COOLDOWN_SECONDS`・ADR-0005）
- [ ] クライアント IP（`TRUSTED_PROXY_COUNT`・ADR-0006・本書 §1）

## 5. データストア / 起動

正＝[`API設計/A_認証・セッション.md`](API設計/A_認証・セッション.md) A.10（Redis セッション）・[`データモデル.md`](データモデル.md)。

- [ ] **Redis** が可用（セッション・OTP/pre-auth・レート制限/ロックの保持先＝即時失効の確定要件）。永続/フェイルオーバ方針を決めること（消失＝全ログアウト相当）。
- [ ] **PostgreSQL**（管理DB＋会社DB N）と **MinIO** が可用。会社DB は全文検索 PGroonga。
- [ ] backend の bootstrap（DB 作成→`alembic` head→seed）が本番でどう走るか（本番は seed を流さない等）を決めること。dev の entrypoint 冪等 bootstrap をそのまま本番に使わない。

- [ ] **本番トポロジの確定**＝`Browser→エッジ→FastAPI`（/api 直結・ホップ1）か `Browser→エッジ→Next(rewrite)→FastAPI`（ホップ2）か。→ `TRUSTED_PROXY_COUNT` の値が決まる（ADR-0006 §2.3）。
- [ ] メール送信基盤（SMTP/送信サービス）の**選定**（要件定義 README「TBD」）。
- [ ] Redis 永続/HA、DB バックアップ、監査ログの保存先/期間（[`API設計/A_認証・セッション.md`](API設計/A_認証・セッション.md) §A.8）。
