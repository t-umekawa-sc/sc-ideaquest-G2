# ゲーム感 ブラウザ受入チェックリスト

> 目的＝「ゲーム感向上」フェーズの**視覚/操作感**をユーザーがブラウザで確認するための一覧。各項目に**一意ID（`GF-AC-NNN`）**を付ける。
> 使い方＝下表を上から操作して確認し、気になる点は **ID を添えて**指摘する（例：「GF-AC-002 のバー速度が速すぎる」）。自動テスト（純ロジックの vitest）は別途 `doc/テスト/I_ダッシュボード.md` の I-TC-150/151 で担保済み＝ここは**見た目の受入**に限定。
> 状態列＝`未確認`／`OK`／`要修正`（指摘は本人が記入 or 口頭）。

## 事前準備（並行ワークフロー）
- **受入/QA は compose の本番ビルドで**（2026-08-28〜）＝`docker compose -f impl/compose.yaml up -d --build frontend`。**新しいコミットを反映するには毎回 `--build` で再ビルド**（コンテナ内にソースを焼くため）。本番ビルドはハッシュ付き CSS を確定参照するので**F5 リロードでスタイルが剥がれない**（`next dev` のオンデマンド compile 起因の無スタイル現象を回避）。backend 一式も compose 稼働・`/api` は `backend:8000` へプロキシ。
- **コードを弄りながらの素早い検証はホスト**＝`cd impl/frontend && npm run dev`（HMR・`/api` は `localhost:8000` へプロキシ）。※`next dev` はごく稀にリロードで CSS グリッチが起こり得る＝その場合は dev サーバーだけ再起動（コンテナ再起動は不要）。
- ブラウザ `http://localhost:3000` → ログイン `ACME-01` / `user@acme.example` / `Passw0rd!` → **ダッシュボード**。
- OS 設定「視差効果を減らす / reduce motion」を ON/OFF で切り替えて両方確認できると尚良い。
