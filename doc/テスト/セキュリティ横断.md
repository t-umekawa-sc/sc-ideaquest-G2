## 6. 冪等キー（Idempotency-Key・§1.9・横断ミドルウェア）

> 対象＝`app/core/idempotency.py`（非冪等 POST の二重送信防御）。検体＝アイデア作成 `POST /quests/{id}/ideas`。会社×アカウント×キーで Redis スコープ・24h・確定応答（2xx/決定的4xx）のみ done 保存・5xx は解放。※`SEC-TC-` はトレーサビリティ検査の正規表現（`\b[A-Z]-TC-`）に不一致＝本 md で追跡。

| TC-ID | 階層 | 目的 | 前提 | 操作 | 期待 | 根拠 |
| --- | --- | --- | --- | --- | --- | --- |
| SEC-TC-041 | api | 同一キー再送は最初の結果を再生・副作用は1回 | ログイン | 同一 `Idempotency-Key`＋同一内容で `POST .../ideas` を2回 | 2回目＝**同じ id・同ステータス**＋`Idempotency-Replayed: true` ヘッダ／**アイデアは1件のみ作成**（二重作成なし） | §1.9 |
| SEC-TC-042 | api | 同一キー・別内容は誤用として拒否 | 同上 | 同一キーで**異なる body**を送る | `422` `code=idempotency_key_reuse`（別操作には別キー） | §1.9 |
| SEC-TC-043 | api | キー長の検証 | ログイン | `Idempotency-Key` に129文字 | `422` `validation_error`（`field=Idempotency-Key`・最大128） | §1.9 |
| SEC-TC-044 | api | 処理中（in_flight）の同時再送 | Redis に同一キーの `in_flight` マーカー（同一指紋）を設置 | 同一キー・同一内容で `POST` | `409` `code=idempotency_in_progress`＋`Retry-After` | §1.9 |
